## 1. ปรับการอ้างอิงและลิงก์ให้เหมาะสม

เรียนรู้วิธีปรับปรุงประสิทธิภาพที่เกี่ยวกับชนิดของการอ้างอิงและลิงก์

### อย่าใช้ forward referencing และ backward referencing

เพื่อความชัดเจนและหลีกเลี่ยงข้อผิดพลาด ให้ออกแบบสูตรไม่ให้อ้างอิงไปข้างหน้า (ไปทางขวาหรือด้านล่าง) ถึงสูตรหรือเซลล์อื่น การอ้างอิงไปข้างหน้ามักไม่กระทบประสิทธิภาพการคำนวณ ยกเว้นกรณีสุดโต่งตอนคำนวณเวิร์กบุ๊กครั้งแรก ซึ่งอาจใช้เวลานานขึ้นในการสร้างลำดับการคำนวณที่เหมาะสมเมื่อมีสูตรจำนวนมากที่ต้องเลื่อนการคำนวณ

### ลดการใช้ circular reference แบบ iteration

การคำนวณ circular reference ด้วย iteration ช้า เพราะต้องคำนวณหลายรอบ และเป็นแบบเธรดเดียว มักจะ "คลี่" circular reference ออกได้ด้วยพีชคณิต เพื่อไม่ต้องใช้การคำนวณแบบ iterative อีก เช่น ในการคำนวณกระแสเงินสดและดอกเบี้ย ให้ลองคำนวณกระแสเงินสดก่อนดอกเบี้ย แล้วคำนวณดอกเบี้ย แล้วจึงคำนวณกระแสเงินสดรวมดอกเบี้ย

Excel คำนวณ circular reference ทีละเวิร์กชีตโดยไม่พิจารณา dependency ดังนั้นมักช้าถ้า circular reference ข้ามมากกว่าหนึ่งเวิร์กชีต ลองย้ายการคำนวณวนไว้ในเวิร์กชีตเดียว หรือปรับลำดับการคำนวณของเวิร์กชีตเพื่อหลีกเลี่ยงการคำนวณที่ไม่จำเป็น

ก่อนที่การคำนวณ iterative เริ่ม Excel ต้องคำนวณเวิร์กบุ๊กใหม่เพื่อระบุ circular reference ทั้งหมดและ dependent ของมัน กระบวนการนี้เทียบเท่า iteration สองถึงสามรอบ

หลังจากระบุ circular reference และ dependent แล้ว แต่ละ iteration ต้องให้ Excel คำนวณไม่เพียงทุกเซลล์ใน circular reference แต่รวมถึงเซลล์ใด ๆ ที่ขึ้นกับเซลล์ในห่วงโซ่ circular reference พร้อมกับเซลล์ volatile และ dependent ของมัน ถ้ามีการคำนวณซับซ้อนที่ขึ้นกับเซลล์ใน circular reference อาจเร็วกว่าถ้าแยกไปไว้ในเวิร์กบุ๊กปิดแยกต่างหาก แล้วเปิดเพื่อคำนวณใหม่หลังจากการคำนวณวนลู่เข้าแล้ว

สิ่งสำคัญคือลดจำนวนเซลล์ในการคำนวณวนและเวลาคำนวณที่เซลล์เหล่านั้นใช้

### หลีกเลี่ยงลิงก์ระหว่างเวิร์กบุ๊ก

หลีกเลี่ยงลิงก์ระหว่างเวิร์กบุ๊กเมื่อเป็นไปได้ เพราะอาจช้า พังง่าย และไม่ใช่ว่าจะหาและแก้ได้ง่ายเสมอไป

การใช้เวิร์กบุ๊กใหญ่ไม่กี่เล่มมักดีกว่า (แต่ไม่เสมอไป) การใช้เวิร์กบุ๊กเล็กหลายเล่ม ข้อยกเว้นอาจเป็นเมื่อมีการคำนวณฝั่งหน้า (front-end) จำนวนมากที่คำนวณใหม่น้อยมากจนสมเหตุสมผลที่จะแยกไว้เวิร์กบุ๊กอื่น หรือเมื่อ RAM ไม่พอ

พยายามใช้การอ้างอิงเซลล์โดยตรงแบบง่ายที่ทำงานกับเวิร์กบุ๊กที่ปิดอยู่ได้ เพื่อหลีกเลี่ยงการคำนวณเวิร์กบุ๊กที่ลิงก์ *ทั้งหมด* ใหม่เมื่อคำนวณ *เวิร์กบุ๊กใด ๆ* ใหม่ และคุณยังเห็นค่าที่ Excel อ่านจากเวิร์กบุ๊กที่ปิดอยู่ ซึ่งมักสำคัญสำหรับการดีบักและตรวจสอบเวิร์กบุ๊ก

ถ้าหลีกเลี่ยงการใช้เวิร์กบุ๊กที่ลิงก์กันไม่ได้ ให้เปิดทั้งหมดไว้แทนที่จะปิด และเปิดเวิร์กบุ๊กที่ถูกลิงก์ **ไป** (linked to) ก่อนเวิร์กบุ๊กที่ลิงก์ **มา** (linked from)

### ลดลิงก์ระหว่างเวิร์กชีต

การใช้หลายเวิร์กชีตทำให้เวิร์กบุ๊กใช้ง่ายขึ้น แต่โดยทั่วไปการคำนวณการอ้างอิงไปยังเวิร์กชีตอื่นช้ากว่าการอ้างอิงภายในเวิร์กชีตเดียวกัน

## 2. ลด used range ให้น้อยที่สุด

เพื่อประหยัดหน่วยความจำและลดขนาดไฟล์ Excel พยายามเก็บข้อมูลเฉพาะพื้นที่บนเวิร์กชีตที่ถูกใช้ เรียกว่า *used range* บางครั้งการแก้ไขและจัดรูปแบบต่าง ๆ ขยาย used range เกินกว่าที่คุณเห็นว่าใช้อยู่ ซึ่งอาจเป็นสิ่งกีดขวางทั้งประสิทธิภาพและขนาดไฟล์

ตรวจ used range ที่มองเห็นบนเวิร์กชีตด้วย **Ctrl+End** ถ้ามากเกินไป ให้พิจารณาลบทุกแถวและคอลัมน์ใต้และขวาของเซลล์สุดท้ายที่ใช้จริง แล้วบันทึกเวิร์กบุ๊ก **สร้างสำเนาสำรองก่อน** ถ้ามีสูตรที่มีช่วงขยายเข้าไปหรืออ้างอิงถึงพื้นที่ที่ถูกลบ ช่วงเหล่านั้นจะถูกลดขนาดหรือเปลี่ยนเป็น **#N/A**

## 3. รองรับข้อมูลที่เพิ่มขึ้น

เมื่อเพิ่มแถวหรือคอลัมน์ข้อมูลลงเวิร์กชีตบ่อย ๆ ต้องหาวิธีให้สูตร Excel อ้างอิงพื้นที่ข้อมูลใหม่โดยอัตโนมัติ แทนที่จะต้องค้นหาและเปลี่ยนสูตรทุกครั้ง

ทำได้โดยใช้ช่วงใหญ่ในสูตรที่ขยายเกินขอบเขตข้อมูลปัจจุบันไปมาก แต่อาจทำให้การคำนวณไม่มีประสิทธิภาพในบางสถานการณ์ และดูแลยาก เพราะการลบแถวและคอลัมน์อาจลดช่วงลงโดยไม่รู้ตัว

### ใช้ structured table references (แนะนำ)

ตั้งแต่ Excel 2007 ใช้ structured table references ซึ่งขยายและหดตามขนาดของตารางที่อ้างอิงโดยอัตโนมัติ

ข้อดีหลายประการ:

- ข้อเสียด้านประสิทธิภาพน้อยกว่าทางเลือกอย่างการอ้างอิงทั้งคอลัมน์และ dynamic range
- สร้างหลายตารางข้อมูลบนเวิร์กชีตเดียวได้ง่าย
- สูตรที่ฝังในตารางก็ขยายและหดตามข้อมูล

### ทางเลือก: อ้างอิงทั้งคอลัมน์และทั้งแถว

ใช้การอ้างอิงทั้งคอลัมน์ เช่น **$A:$A** ซึ่งคืนทุกแถวในคอลัมน์ A เพิ่มข้อมูลเท่าไรก็ได้ การอ้างอิงจะรวมเสมอ

มีทั้งข้อดีข้อเสีย:

- ฟังก์ชันในตัวของ Excel หลายตัว (**SUM, SUMIF**) คำนวณการอ้างอิงทั้งคอลัมน์ได้มีประสิทธิภาพ เพราะรู้จักแถวสุดท้ายที่ใช้ในคอลัมน์โดยอัตโนมัติ แต่ฟังก์ชันคำนวณอาร์เรย์อย่าง **SUMPRODUCT** จัดการการอ้างอิงทั้งคอลัมน์ไม่ได้ หรือคำนวณทุกเซลล์ในคอลัมน์
- UDF ไม่รู้จักแถวสุดท้ายที่ใช้ในคอลัมน์โดยอัตโนมัติ จึงมักคำนวณการอ้างอิงทั้งคอลัมน์อย่างไม่มีประสิทธิภาพ แต่เขียนโปรแกรม UDF ให้รู้จักแถวสุดท้ายได้ง่าย
- ใช้การอ้างอิงทั้งคอลัมน์ยากเมื่อมีหลายตารางข้อมูลบนเวิร์กชีตเดียว
- ใน Excel 2007 ขึ้นไป สูตรอาร์เรย์จัดการการอ้างอิงทั้งคอลัมน์ได้ แต่บังคับให้คำนวณทุกเซลล์ในคอลัมน์ รวมเซลล์ว่าง อาจช้า โดยเฉพาะ 1 ล้านแถว

### ทางเลือก: dynamic ranges

ใช้ฟังก์ชัน **OFFSET** หรือ **INDEX** และ **COUNTA** ในนิยามของ named range ทำให้พื้นที่ที่ชื่อนั้นอ้างถึงขยายและหดแบบไดนามิก เช่น สร้าง defined name ด้วยสูตรใดสูตรหนึ่งต่อไปนี้

```vb
  =OFFSET(Sheet1!$A$1,0,0,COUNTA(Sheet1!$A:$A),1)
  =Sheet1!$A$1:INDEX(Sheet1!$A:$A,COUNTA(Sheet1!$A:$A)+ROW(Sheet1!$A$1) - 1,1)
```

เมื่อใช้ชื่อ dynamic range ในสูตร มันจะขยายรวมรายการใหม่อัตโนมัติ

การใช้สูตร **INDEX** สำหรับ dynamic range ดีกว่าสูตร **OFFSET** โดยทั่วไป เพราะ **OFFSET** เป็นฟังก์ชัน volatile ที่คำนวณทุกครั้งที่คำนวณใหม่

ประสิทธิภาพลดลงเพราะ **COUNTA** ภายในสูตร dynamic range ต้องตรวจสอบหลายแถว ลดผลนี้ได้โดยเก็บส่วน **COUNTA** ของสูตรไว้ในเซลล์หรือ defined name แยก แล้วอ้างถึงเซลล์หรือชื่อนั้นใน dynamic range:

```vb
 Counts!z1=COUNTA(Sheet1!$A:$A)
 OffsetDynamicRange=OFFSET(Sheet1!$A$1,0,0,Counts!$Z$1,1)
 IndexDynamicRange=Sheet1!$A$1:INDEX(Sheet1!$A:$A,Counts!$Z$1+ROW(Sheet1!$A$1) - 1,1)
```

ใช้ฟังก์ชันอย่าง **INDIRECT** สร้าง dynamic range ได้ด้วย แต่ **INDIRECT** เป็น volatile และคำนวณเธรดเดียวเสมอ

ข้อดีข้อเสียของ dynamic range:

- dynamic range ใช้ได้ดีเพื่อจำกัดจำนวนการคำนวณของสูตรอาร์เรย์
- การใช้ dynamic range หลายตัวในคอลัมน์เดียวต้องใช้ฟังก์ชันนับเฉพาะทาง
- การใช้ dynamic range จำนวนมากอาจลดประสิทธิภาพ

## 4. ปรับปรุงเวลาคำนวณของการค้นหา

ใน Office 365 เวอร์ชัน 1809 ขึ้นไป VLOOKUP, HLOOKUP และ MATCH แบบตรงทุกตัวบนข้อมูลที่ไม่เรียง เร็วกว่าเดิมมากเมื่อค้นหาหลายคอลัมน์ (หรือหลายแถวสำหรับ HLOOKUP) จากช่วงตารางเดียวกัน

แต่สำหรับ Excel รุ่นก่อน การค้นหายังเป็นสิ่งกีดขวางการคำนวณที่สำคัญอยู่บ่อยครั้ง โชคดีที่มีหลายวิธีปรับปรุงเวลาคำนวณ ถ้าใช้ตัวเลือก exact match เวลาคำนวณของฟังก์ชันเป็นสัดส่วนกับจำนวนเซลล์ที่สแกนก่อนเจอรายการที่ตรง สำหรับการค้นหาในช่วงใหญ่ เวลานี้อาจมาก

เวลาค้นหาด้วยตัวเลือก approximate match ของ **VLOOKUP, HLOOKUP, MATCH** บนข้อมูลที่เรียงลำดับ **เร็ว** และไม่เพิ่มขึ้นมากตามความยาวของช่วงที่ค้นหา ลักษณะเหมือนการค้นหาแบบ binary search

### เข้าใจตัวเลือกการค้นหา

ตรวจให้แน่ใจว่าเข้าใจตัวเลือก match-type และ range-lookup ใน **MATCH, VLOOKUP, HLOOKUP**

รูปแบบของ **MATCH** (ดูเพิ่มที่ method [Match](https://learn.microsoft.com/en-us/office/vba/api/excel.worksheetfunction.match) ของออบเจ็กต์ [WorksheetFunction](https://learn.microsoft.com/en-us/office/vba/api/excel.worksheetfunction)):

```vb
  MATCH(lookup value, lookup array, matchtype)
```

- **Matchtype=1** คืนค่าที่ตรงที่มากที่สุดที่น้อยกว่าหรือเท่ากับค่าที่ค้นหา เมื่อ lookup array เรียงจากน้อยไปมาก (approximate match) ถ้า lookup array ไม่ได้เรียงจากน้อยไปมาก MATCH จะคืนคำตอบผิด **ตัวเลือกเริ่มต้นคือ approximate match เรียงจากน้อยไปมาก**
- **Matchtype=0** ขอ exact match และสมมติว่าข้อมูลไม่ได้เรียงลำดับ
- **Matchtype=-1** คืนค่าที่ตรงที่น้อยที่สุดที่มากกว่าหรือเท่ากับค่าที่ค้นหา เมื่อ lookup array เรียงจากมากไปน้อย (approximate match)

รูปแบบของ **VLOOKUP** และ **HLOOKUP** (ดูเพิ่ม [VLOOKUP](https://learn.microsoft.com/en-us/office/vba/api/excel.worksheetfunction.vlookup), [HLOOKUP](https://learn.microsoft.com/en-us/office/vba/api/excel.worksheetfunction.hlookup)):

```vb
  VLOOKUP(lookup value, table array, col index num, range-lookup)
  HLOOKUP(lookup value, table array, row index num, range-lookup)
```

- **Range-lookup=TRUE** คืนค่าที่ตรงที่มากที่สุดที่น้อยกว่าหรือเท่ากับค่าที่ค้นหา (approximate match) เป็นตัวเลือกเริ่มต้น table array ต้องเรียงจากน้อยไปมาก
- **Range-lookup=FALSE** ขอ exact match และสมมติว่าข้อมูลไม่ได้เรียงลำดับ

หลีกเลี่ยงการค้นหาบนข้อมูลที่ไม่เรียงเมื่อทำได้ เพราะช้า ถ้าข้อมูลเรียงแล้วแต่ต้องการ exact match ดูหัวข้อ "ใช้สอง lookup กับข้อมูลที่เรียงลำดับและมีค่าที่หายไป" ด้านล่าง

### ใช้ INDEX และ MATCH หรือ OFFSET แทน VLOOKUP

ลองใช้ **INDEX** และ **MATCH** แทน **VLOOKUP** แม้ VLOOKUP จะเร็วกว่าเล็กน้อย (ประมาณ 5 เปอร์เซ็นต์) ง่ายกว่า และใช้หน่วยความจำน้อยกว่าการรวม MATCH และ INDEX หรือ OFFSET แต่ความยืดหยุ่นเพิ่มเติมของ MATCH และ INDEX มักช่วยประหยัดเวลาได้มาก เช่น เก็บผลของ MATCH แบบตรงทุกตัวไว้ในเซลล์และใช้ซ้ำในหลายคำสั่ง INDEX

ฟังก์ชัน **INDEX** เร็วและเป็น non-volatile ซึ่งเร่งการคำนวณใหม่ ฟังก์ชัน **OFFSET** ก็เร็ว แต่เป็น volatile และบางครั้งเพิ่มเวลาประมวลผล calculation chain อย่างมาก

แปลง **VLOOKUP** เป็น **INDEX** และ **MATCH** ได้ง่าย สองคำสั่งต่อไปนี้คืนคำตอบเดียวกัน:

```vb
 VLOOKUP(A1, Data!$A$2:$F$1000,3,False)
 INDEX(Data!$A$2:$F$1000,MATCH(A1,$A$1:$A$1000,0),3)
```

### เร่งการค้นหา

เนื่องจากการค้นหาแบบ exact match อาจช้า พิจารณาตัวเลือกต่อไปนี้:

- ใช้เวิร์กชีตเดียว การเก็บ lookup และข้อมูลไว้ในชีตเดียวกันเร็วกว่า
- เมื่อทำได้ ให้ **SORT** ข้อมูลก่อน (SORT เร็ว) แล้วใช้ approximate match
- เมื่อต้องใช้ exact match ให้จำกัดช่วงเซลล์ที่สแกนให้น้อยที่สุด ใช้ตารางและ structured reference หรือชื่อ dynamic range แทนการอ้างอิงแถวหรือคอลัมน์จำนวนมาก บางครั้งคำนวณขอบเขตล่างและบนของช่วงล่วงหน้าสำหรับ lookup ได้

### ใช้สอง lookup กับข้อมูลที่เรียงลำดับและมีค่าที่หายไป

*การทำ approximate match สองครั้งเร็วกว่า exact match หนึ่งครั้งอย่างมากสำหรับการค้นหาเกินไม่กี่แถว* (จุดคุ้มทุนประมาณ 10–20 แถว)

ถ้าเรียงข้อมูลได้ แต่ยังใช้ approximate match ตรง ๆ ไม่ได้เพราะไม่แน่ใจว่าค่าที่ค้นหามีอยู่ในช่วง ให้ใช้สูตรนี้:

```vb
  IF(VLOOKUP(lookup_val ,lookup_array,1,True)=lookup_val, _
      VLOOKUP(lookup_val, lookup_array, column, True), "notexist")
```

ส่วนแรกของสูตรทำ approximate lookup บนคอลัมน์ที่ค้นหาเอง

```vb
  VLOOKUP(lookup_val ,lookup_array,1,True)
```

ตรวจว่าคำตอบจากคอลัมน์ค้นหาเหมือนค่าที่ค้นหาหรือไม่ (ถ้าเหมือนแปลว่า exact match) ด้วย

```vb
  IF(VLOOKUP(lookup_val ,lookup_array,1,True)=lookup_val,
```

ถ้าสูตรคืน True แปลว่าเจอ exact match จึงทำ approximate lookup อีกครั้ง แต่คราวนี้คืนคำตอบจากคอลัมน์ที่ต้องการ

```vb
  VLOOKUP(lookup_val, lookup_array, column, True)
```

ถ้าคำตอบจากคอลัมน์ค้นหาไม่ตรงกับค่าที่ค้นหา แปลว่าค่านั้นหายไป และสูตรคืน "notexist"

ระวัง: ถ้าค้นหาค่าที่เล็กกว่าค่าที่น้อยที่สุดในรายการ จะได้ error จัดการ error นี้ด้วย **IFERROR** หรือเพิ่มค่าทดสอบขนาดเล็กลงในรายการ

### ใช้ IFERROR กับข้อมูลที่ไม่เรียงและมีค่าที่หายไป

ถ้าต้องใช้ exact match lookup บนข้อมูลที่ไม่เรียง และไม่แน่ใจว่าค่าที่ค้นหามีอยู่หรือไม่ มักต้องจัดการ #N/A ที่คืนมาเมื่อไม่พบ ตั้งแต่ Excel 2007 ใช้ **IFERROR** ซึ่งทั้งง่ายและเร็ว

```vb
  IF IFERROR(VLOOKUP(lookupval, table, 2 FALSE),0)
```

(หมายเหตุผู้แปล: รูปแบบในต้นฉบับเขียนตามนี้ รูปแบบที่ใช้ได้จริงคือ `=IFERROR(VLOOKUP(lookupval, table, 2, FALSE), 0)`)

ในรุ่นก่อนหน้า วิธีที่ง่ายแต่ช้าคือใช้ **IF** ที่มีสอง lookup

```vb
  IF(ISNA(VLOOKUP(lookupval,table,2,FALSE)),0,_
      VLOOKUP(lookupval,table,2,FALSE))
```

หลีกเลี่ยง exact lookup สองครั้งได้ โดยใช้ exact **MATCH** ครั้งเดียว เก็บผลในเซลล์ แล้วทดสอบผลก่อนทำ **INDEX**

```vb
  In A1 =MATCH(lookupvalue,lookuparray,0)
  In B1 =IF(ISNA(A1),0,INDEX(tablearray,A1,column))
```

ถ้าใช้สองเซลล์ไม่ได้ ใช้ **COUNTIF** ซึ่งโดยทั่วไปเร็วกว่า exact match lookup

```vb
  IF (COUNTIF(lookuparray,lookupvalue)=0, 0, _
      VLOOKUP(lookupval, table, 2 FALSE))
```

### ใช้ MATCH และ INDEX สำหรับ exact match lookup หลายคอลัมน์

มักใช้ exact **MATCH** ที่เก็บไว้ซ้ำได้หลายครั้ง เช่น ถ้าทำ exact lookup ที่หลายคอลัมน์ผลลัพธ์ ประหยัดเวลาได้โดยใช้ MATCH หนึ่งตัวและ INDEX หลายตัว แทนที่จะใช้ VLOOKUP หลายตัว

เพิ่มคอลัมน์พิเศษให้ MATCH เก็บผล (`stored_row`) และสำหรับแต่ละคอลัมน์ผลลัพธ์ใช้:

```vb
  INDEX(Lookup_Range,stored_row,column_number)
```

หรือจะใช้ **VLOOKUP** ในสูตรอาร์เรย์ก็ได้ (ต้องป้อนสูตรอาร์เรย์ด้วย Ctrl+Shift+Enter Excel จะเติม { และ } ให้เพื่อแสดงว่าเป็นสูตรอาร์เรย์)

```vb
  {VLOOKUP(lookupvalue,{4,2},FALSE)}
```

### ใช้ INDEX สำหรับชุดแถวหรือคอลัมน์ที่ต่อเนื่อง

คืนหลายเซลล์จากการค้นหาครั้งเดียวได้ เพื่อค้นหาหลายคอลัมน์ติดกัน ใช้ **INDEX** ในสูตรอาร์เรย์เพื่อคืนหลายคอลัมน์พร้อมกัน (ใช้ 0 เป็นหมายเลขคอลัมน์) และใช้ INDEX คืนหลายแถวพร้อมกันได้

```vb
  {INDEX($A$1:$J$1000,stored_row,0)}
```

คืนคอลัมน์ A ถึง J จากแถวที่เก็บไว้ซึ่งสร้างโดยคำสั่ง **MATCH** ก่อนหน้า

### ใช้ MATCH คืนบล็อกเซลล์สี่เหลี่ยม

ใช้ฟังก์ชัน **MATCH** และ **OFFSET** คืนบล็อกเซลล์สี่เหลี่ยม

### ใช้ MATCH และ INDEX สำหรับการค้นหาสองมิติ

ค้นหาตารางสองมิติอย่างมีประสิทธิภาพได้โดยแยก lookup ตามแถวและคอลัมน์ ใช้ **INDEX** ที่มี **MATCH** ซ้อนสองตัว ตัวหนึ่งสำหรับแถว อีกตัวสำหรับคอลัมน์

### ใช้ subset range สำหรับการค้นหาหลายดัชนี

ในเวิร์กชีตใหญ่ อาจต้องค้นหาด้วยหลายดัชนีบ่อย ๆ เช่น ค้นหาปริมาณสินค้าในแต่ละประเทศ/ภูมิภาค ทำได้โดยต่อดัชนีเป็นสตริงเดียวแล้วค้นหาด้วยค่าที่ต่อกัน แต่ไม่มีประสิทธิภาพด้วยสองเหตุผล:

- การต่อสตริงเป็นการดำเนินการที่ใช้การคำนวณหนัก
- การค้นหาจะครอบคลุมช่วงใหญ่

มักมีประสิทธิภาพกว่าถ้าคำนวณ subset range สำหรับการค้นหา (เช่น หาแถวแรกและแถวสุดท้ายของประเทศ/ภูมิภาค แล้วค้นหาสินค้าภายใน subset range นั้น)

### พิจารณาตัวเลือกสำหรับการค้นหาสามมิติ

ถ้าต้องค้นหาตารางที่จะใช้ นอกเหนือจากแถวและคอลัมน์ ใช้เทคนิคต่อไปนี้ โดยเน้นว่าจะทำให้ Excel ค้นหาหรือเลือกตารางอย่างไร

ถ้าแต่ละตารางที่ต้องการค้นหา (มิติที่สาม) เก็บเป็นชุดของ structured table ที่มีชื่อ ชื่อช่วง หรือตารางของสตริงข้อความที่แทนช่วง อาจใช้ฟังก์ชัน **CHOOSE** หรือ **INDIRECT** ได้

- การใช้ **CHOOSE** กับชื่อช่วงอาจเป็นวิธีที่มีประสิทธิภาพ **CHOOSE** ไม่ volatile แต่เหมาะที่สุดกับตารางจำนวนค่อนข้างน้อย ตัวอย่างนี้ใช้ `TableLookup_Value` เลือกแบบไดนามิกว่าจะใช้ชื่อช่วงใด (`TableName1, TableName2, ...`) เป็นตารางค้นหา

  ```vb
    INDEX(CHOOSE(TableLookup_Value,TableName1,TableName2,TableName3), _
    MATCH(RowLookup_Value,$A$2:$A$1000),MATCH(colLookup_value,$B$1:$Z$1))
  ```

- ตัวอย่างต่อไปใช้ **INDIRECT** กับ `TableLookup_Value` สร้างชื่อชีตแบบไดนามิกสำหรับตารางค้นหา วิธีนี้ง่ายและรองรับตารางจำนวนมาก แต่เพราะ **INDIRECT** เป็นฟังก์ชัน volatile แบบเธรดเดียว การค้นหาจึงคำนวณแบบเธรดเดียวทุกครั้งที่คำนวณ แม้ไม่มีข้อมูลเปลี่ยน วิธีนี้ **ช้า**

  ```vb
    INDEX(INDIRECT("Sheet" & TableLookup_Value & "!$B$2:$Z$1000"), _
    MATCH(RowLookup_Value,$A$2:$A$1000),MATCH(colLookup_value,$B$1:$Z$1))
  ```

- ใช้ **VLOOKUP** หาชื่อชีตหรือสตริงข้อความสำหรับตาราง แล้วใช้ **INDIRECT** แปลงข้อความที่ได้เป็นช่วง

  ```vb
    INDEX(INDIRECT(VLOOKUP(TableLookup_Value,TableOfTAbles,1)),MATCH(RowLookup_Value,$A$2:$A$1000),MATCH(colLookup_value,$B$1:$Z$1))
  ```

อีกเทคนิคคือรวมทุกตารางเป็นตารางยักษ์เดียวที่มีคอลัมน์เพิ่มเติมระบุตารางแต่ละตาราง แล้วใช้เทคนิค multiple-index lookup ที่แสดงในตัวอย่างก่อนหน้า

### ใช้ wildcard lookup

ฟังก์ชัน **MATCH, VLOOKUP, HLOOKUP** ให้ใช้ตัวอักษร wildcard **?** (อักขระใดก็ได้หนึ่งตัว) และ **\*** (ไม่มีอักขระหรืออักขระกี่ตัวก็ได้) กับ exact match ที่เป็นตัวอักษรได้ บางครั้งใช้วิธีนี้เพื่อเลี่ยงการจับคู่หลายครั้ง

## 5. ปรับสูตรอาร์เรย์และ SUMPRODUCT

สูตรอาร์เรย์และฟังก์ชัน **SUMPRODUCT** ทรงพลังแต่ต้องใช้ด้วยความระมัดระวัง สูตรอาร์เรย์หนึ่งสูตรอาจต้องคำนวณหลายครั้ง

กุญแจสู่การเพิ่มความเร็วของสูตรอาร์เรย์คือทำให้จำนวนเซลล์และนิพจน์ที่ถูกประเมินในสูตรอาร์เรย์ **น้อยที่สุดเท่าที่ทำได้** จำไว้ว่าสูตรอาร์เรย์ค่อนข้างคล้ายสูตร volatile: ถ้าเซลล์ใดเซลล์หนึ่งที่มันอ้างอิงเปลี่ยน เป็น volatile หรือถูกคำนวณใหม่ สูตรอาร์เรย์จะคำนวณทุกเซลล์ในสูตรและประเมิน "เซลล์เสมือน" ทั้งหมดที่ต้องใช้

เพื่อเพิ่มความเร็วของสูตรอาร์เรย์:

- นำนิพจน์และการอ้างอิงช่วงออกจากสูตรอาร์เรย์ไปไว้ในคอลัมน์และแถวช่วยแยกกัน ซึ่งใช้กระบวนการ smart recalculation ของ Excel ได้ดีกว่ามาก
- อย่าอ้างอิงทั้งแถว หรืออ้างอิงแถวและคอลัมน์มากกว่าที่ต้องการ สูตรอาร์เรย์ถูกบังคับให้คำนวณทุกการอ้างอิงเซลล์ในสูตร แม้เซลล์ว่างหรือไม่ได้ใช้ เมื่อมี 1 ล้านแถวตั้งแต่ Excel 2007 สูตรอาร์เรย์ที่อ้างอิงทั้งคอลัมน์จึงคำนวณช้ามาก
- ตั้งแต่ Excel 2007 ใช้ structured reference ที่ทำได้ เพื่อรักษาจำนวนเซลล์ที่สูตรอาร์เรย์ประเมินให้น้อยที่สุด
- ในรุ่นก่อน Excel 2007 ใช้ชื่อ dynamic range ที่เป็นไปได้ แม้จะ volatile ก็คุ้ม เพราะลดขนาดของช่วงได้
- ระวังสูตรอาร์เรย์ที่อ้างอิงทั้งแถวและคอลัมน์: บังคับให้คำนวณช่วงสี่เหลี่ยม
- ใช้ **SUMPRODUCT** ถ้าเป็นไปได้ เร็วกว่าสูตรอาร์เรย์ที่เทียบเท่าเล็กน้อย

### พิจารณาตัวเลือกการใช้ SUM กับสูตรอาร์เรย์หลายเงื่อนไข

ควรใช้ **SUMIFS, COUNTIFS, AVERAGEIFS** แทนสูตรอาร์เรย์เสมอเมื่อทำได้ เพราะคำนวณเร็วกว่ามาก Excel 2016 เพิ่มฟังก์ชัน **MAXIFS** และ **MINIFS** ที่เร็ว

ในรุ่นก่อน Excel 2007 มักใช้สูตรอาร์เรย์คำนวณผลรวมหลายเงื่อนไข ทำได้ค่อนข้างง่าย โดยเฉพาะถ้าใช้ **Conditional Sum Wizard** ของ Excel แต่มักช้า โดยปกติมีวิธีที่เร็วกว่ามากในการได้ผลเดียวกัน ถ้ามี SUM หลายเงื่อนไขเพียงไม่กี่ตัว อาจใช้ฟังก์ชัน **DSUM** ซึ่งเร็วกว่าสูตรอาร์เรย์ที่เทียบเท่ามาก

ถ้าต้องใช้สูตรอาร์เรย์ วิธีเร่งความเร็วที่ดี:

- ใช้ชื่อ dynamic range หรือ structured table reference เพื่อลดจำนวนเซลล์
- แยกหลายเงื่อนไขออกเป็นคอลัมน์สูตรช่วยที่คืน **True** หรือ **False** ในแต่ละแถว แล้วอ้างอิงคอลัมน์ช่วยใน **SUMIF** หรือสูตรอาร์เรย์ อาจดูเหมือนไม่ลดจำนวนการคำนวณของสูตรอาร์เรย์เดี่ยว แต่ส่วนใหญ่ทำให้ smart recalculation คำนวณใหม่เฉพาะสูตรในคอลัมน์ช่วยที่ต้องคำนวณใหม่
- พิจารณาต่อทุกเงื่อนไขเข้าเป็นเงื่อนไขเดียว แล้วใช้ **SUMIF**
- ถ้าเรียงข้อมูลได้ ให้นับกลุ่มของแถว และจำกัดสูตรอาร์เรย์ให้ดูเฉพาะกลุ่มย่อย

### จัดลำดับเงื่อนไขใน SUMIFS, COUNTIFS และตระกูล IFS อื่น

ฟังก์ชันเหล่านี้ประเมินแต่ละเงื่อนไขจากซ้ายไปขวาตามลำดับ ดังนั้นมีประสิทธิภาพกว่าถ้าวางเงื่อนไขที่เข้มงวดที่สุดก่อน เพื่อให้เงื่อนไขถัดไปต้องดูจำนวนแถวน้อยที่สุด

### พิจารณาตัวเลือกการใช้ SUMPRODUCT กับสูตรอาร์เรย์หลายเงื่อนไข

ตั้งแต่ Excel 2007 ควรใช้ **SUMIFS, COUNTIFS, AVERAGEIFS** และใน Excel 2016 ใช้ **MAXIFS, MINIFS** แทนสูตร **SUMPRODUCT** เมื่อเป็นไปได้

ในรุ่นก่อนหน้า มีข้อดีบางอย่างของ **SUMPRODUCT** เหนือสูตรอาร์เรย์ **SUM**:

- **SUMPRODUCT** ไม่ต้องป้อนแบบอาร์เรย์ด้วย Ctrl+Shift+Enter
- **SUMPRODUCT** มักเร็วกว่าเล็กน้อย (5 ถึง 10 เปอร์เซ็นต์)

ใช้ **SUMPRODUCT** กับสูตรอาร์เรย์หลายเงื่อนไขดังนี้:

```vb
  SUMPRODUCT(--(Condition1),--(Condition2),RangetoSum)
```

ในตัวอย่างนี้ `Condition1` และ `Condition2` เป็นนิพจน์เงื่อนไข เช่น `$A$1:$A$10000<=$Z4` เพราะนิพจน์เงื่อนไขคืน **True** หรือ **False** ไม่ใช่ตัวเลข จึงต้องบังคับ (coerce) เป็นตัวเลขภายใน SUMPRODUCT ทำได้ด้วยเครื่องหมายลบสองตัว (**--**) หรือบวก 0 (**+0**) หรือคูณ 1 (**x1**) การใช้ **--** เร็วกว่า **+0** หรือ **x1** เล็กน้อย

โปรดทราบว่า ขนาดและรูปร่างของช่วงหรืออาร์เรย์ที่ใช้ในนิพจน์เงื่อนไขและช่วงที่จะรวมต้องเท่ากัน และต้องไม่มีทั้งคอลัมน์

คูณเทอมภายใน **SUMPRODUCT** โดยตรงแทนการคั่นด้วยจุลภาคก็ได้:

```vb
  SUMPRODUCT((Condition1)*(Condition2)*RangetoSum)
```

โดยทั่วไปช้ากว่าการใช้ไวยากรณ์ที่คั่นด้วยจุลภาคเล็กน้อย และเกิด error ถ้าช่วงที่จะรวมมีค่าข้อความ แต่ยืดหยุ่นกว่าเล็กน้อย เช่น ช่วงที่จะรวมมีหลายคอลัมน์ได้ เมื่อเงื่อนไขมีคอลัมน์เดียว

### ใช้ SUMPRODUCT คูณและบวกช่วงและอาร์เรย์

ในกรณีอย่างการคำนวณค่าเฉลี่ยถ่วงน้ำหนัก ที่ต้องคูณช่วงตัวเลขกับอีกช่วงแล้วรวมผล การใช้ไวยากรณ์แบบจุลภาคของ **SUMPRODUCT** เร็วกว่า **SUM** ที่ป้อนแบบอาร์เรย์ 20 ถึง 25 เปอร์เซ็นต์

```vb
  {=SUM($D$2:$D$10301*$E$2:$E$10301)}
  =SUMPRODUCT($D$2:$D$10301*$E$2:$E$10301)
  =SUMPRODUCT($D$2:$D$10301,$E$2:$E$10301)
```

สามสูตรนี้ให้ผลเหมือนกัน แต่สูตรที่สามซึ่งใช้ไวยากรณ์แบบจุลภาคของ **SUMPRODUCT** ใช้เวลาคำนวณเพียงประมาณ 77 เปอร์เซ็นต์ของสองสูตรแรก

### ระวังสิ่งกีดขวางที่อาจเกิดจากอาร์เรย์และฟังก์ชัน

เอนจินคำนวณของ Excel ถูกปรับให้ใช้ประโยชน์จากสูตรอาร์เรย์และฟังก์ชันที่อ้างอิงช่วง แต่การจัดวางสูตรและฟังก์ชันเหล่านี้ที่ผิดปกติบางแบบอาจ (แต่ไม่เสมอไป) ทำให้เวลาคำนวณเพิ่มขึ้นมาก

ถ้าพบสิ่งกีดขวางการคำนวณที่เกี่ยวกับสูตรอาร์เรย์และฟังก์ชันช่วง ให้มองหา:

- การอ้างอิงที่ทับซ้อนกันบางส่วน
- สูตรอาร์เรย์และฟังก์ชันช่วงที่อ้างอิงส่วนหนึ่งของบล็อกเซลล์ที่ถูกคำนวณในสูตรอาร์เรย์หรือฟังก์ชันช่วงอื่น มักเกิดในการวิเคราะห์อนุกรมเวลา
- สูตรชุดหนึ่งอ้างอิงตามแถว และชุดที่สองอ้างอิงชุดแรกตามคอลัมน์
- สูตรอาร์เรย์แถวเดียวจำนวนมากที่ครอบคลุมบล็อกคอลัมน์ โดยมีฟังก์ชัน **SUM** ที่ท้ายแต่ละคอลัมน์

## 6. ใช้ฟังก์ชันอย่างมีประสิทธิภาพ

ฟังก์ชันขยายความสามารถของ Excel อย่างมาก แต่วิธีที่ใช้อาจส่งผลต่อเวลาคำนวณบ่อยครั้ง

### หลีกเลี่ยงฟังก์ชันแบบเธรดเดียว

ฟังก์ชันเนทีฟของ Excel ส่วนใหญ่ทำงานดีกับการคำนวณหลายเธรด แต่ถ้าเป็นไปได้ หลีกเลี่ยงฟังก์ชันเธรดเดียวต่อไปนี้:

- UDF แบบ VBA และ Automation (แต่ UDF ที่ใช้ XLL เป็นหลายเธรดได้)
- PHONETIC
- CELL เมื่อใช้อาร์กิวเมนต์ "format" หรือ "address"
- INDIRECT
- GETPIVOTDATA
- CUBEMEMBER, CUBEVALUE, CUBEMEMBERPROPERTY, CUBESET, CUBERANKEDMEMBER, CUBEKPIMEMBER, CUBESETCOUNT
- ADDRESS เมื่อระบุพารามิเตอร์ที่ห้า (`sheet_name`)
- ฟังก์ชันฐานข้อมูลใด ๆ (DSUM, DAVERAGE ฯลฯ) ที่อ้างถึง PivotTable
- ERROR.TYPE
- HYPERLINK

### ใช้ตารางกับฟังก์ชันที่จัดการช่วง

สำหรับฟังก์ชันอย่าง **SUM, SUMIF, SUMIFS** ที่จัดการช่วง เวลาคำนวณเป็นสัดส่วนกับจำนวนเซลล์ที่ใช้ซึ่งคุณรวมหรือนับ เซลล์ที่ไม่ได้ใช้ไม่ถูกตรวจ ดังนั้นการอ้างอิงทั้งคอลัมน์ค่อนข้างมีประสิทธิภาพ แต่ดีกว่าถ้าไม่รวมเซลล์ที่ใช้เกินกว่าที่ต้องการ ใช้ตาราง หรือคำนวณ subset range หรือ dynamic range

### ลดฟังก์ชัน volatile

ฟังก์ชัน volatile ทำให้การคำนวณใหม่ช้าลง เพราะเพิ่มจำนวนสูตรที่ต้องคำนวณใหม่ในทุกการคำนวณ

มักลดฟังก์ชัน volatile ได้โดยใช้ **INDEX** แทน **OFFSET** และ **CHOOSE** แทน **INDIRECT** แต่ **OFFSET** เป็นฟังก์ชันที่เร็ว และมักใช้ในรูปแบบสร้างสรรค์ที่ให้การคำนวณเร็วได้

### ใช้ UDF ที่เขียนด้วย C หรือ C++

UDF ที่เขียนด้วย C หรือ C++ และใช้ C API (ฟังก์ชัน XLL add-in) โดยทั่วไปทำงานเร็วกว่า UDF ที่พัฒนาด้วย VBA หรือ Automation (XLA หรือ Automation add-in) ข้อมูลเพิ่มเติม: Developing Excel 2010 XLLs (<https://learn.microsoft.com/en-us/office/vba/api/overview/excel>)

ประสิทธิภาพของ UDF แบบ VBA ไวต่อวิธีที่เขียนและวิธีที่เรียกใช้

### ใช้ UDF ของ VBA ที่เร็วกว่า

โดยปกติใช้การคำนวณสูตรของ Excel และฟังก์ชันเวิร์กชีตเร็วกว่า UDF ของ VBA เพราะมีโอเวอร์เฮดเล็กน้อยในการเรียก UDF แต่ละครั้ง และโอเวอร์เฮดมากในการส่งข้อมูลจาก Excel ไปยัง UDF แต่ UDF ที่ออกแบบและเรียกใช้ดีอาจเร็วกว่าสูตรอาร์เรย์ซับซ้อนได้มาก

ตรวจให้แน่ใจว่าใส่การอ้างอิงเซลล์เวิร์กชีตทั้งหมดไว้ในพารามิเตอร์นำเข้าของ UDF แทนที่จะอยู่ในตัวฟังก์ชัน เพื่อหลีกเลี่ยงการเพิ่ม **Application.Volatile** โดยไม่จำเป็น

ถ้าต้องมีสูตรจำนวนมากที่ใช้ UDF ให้ตรวจว่าอยู่ในโหมดคำนวณ **manual** และสั่งการคำนวณจาก VBA UDF ของ VBA คำนวณช้ากว่ามากถ้าการคำนวณ *ไม่ได้* ถูกเรียกจาก VBA (เช่น ในโหมด automatic หรือเมื่อกด F9 ในโหมด manual) โดยเฉพาะเมื่อ Visual Basic Editor (Alt+F11) เปิดอยู่หรือเคยถูกเปิดในเซสชัน Excel ปัจจุบัน

ดักปุ่ม F9 แล้วเปลี่ยนเส้นทางไปยังโพรซีเดอร์คำนวณของ VBA ได้ดังนี้ เพิ่มโพรซีเดอร์นี้ในโมดูล *ThisWorkbook*

```vb
  Private Sub Workbook_Open()
      Application.OnKey "{F9}", "Recalc"
  End Sub
```

เพิ่มโพรซีเดอร์นี้ในโมดูลมาตรฐาน

```vb
  Sub Recalc()
      Application.Calculate
      MsgBox "hello"
  End Sub
```

UDF ใน Automation add-in (Excel 2002 ขึ้นไป) ไม่มีโอเวอร์เฮดของ Visual Basic Editor เพราะไม่ได้ใช้ตัวแก้ไขแบบผสานในตัว ลักษณะประสิทธิภาพอื่นของ UDF แบบ Visual Basic 6 ใน Automation add-in คล้ายฟังก์ชัน VBA

ถ้า UDF ประมวลผลทุกเซลล์ในช่วง ให้ประกาศอินพุตเป็นช่วง กำหนดให้ตัวแปร variant ที่เก็บอาร์เรย์ แล้ววนลูปบนอาร์เรย์นั้น ถ้าต้องการจัดการการอ้างอิงทั้งคอลัมน์อย่างมีประสิทธิภาพ ต้องสร้าง subset ของช่วงอินพุต โดยแบ่งที่จุดตัดกับ used range ดังตัวอย่าง

```vb
  Public Function DemoUDF(theInputRange as Range)
      Dim vArr as Variant
      Dim vCell as Variant
      Dim oRange as Range
      Set oRange=Union(theInputRange, theRange.Parent.UsedRange)
      vArr=oRange
      For Each vCell in vArr
          If IsNumeric(vCell) then DemoUDF=DemoUDF+vCell
      Next vCell
  End Function
```

> **หมายเหตุผู้แปล:** โค้ดต้นฉบับมีความไม่สอดคล้อง: ใช้ `theRange` ที่ไม่ได้ประกาศ (พารามิเตอร์ชื่อ `theInputRange`) และใช้ `Union` ทั้งที่ข้อความอธิบายว่าให้ "แบ่งที่จุดตัดกับ used range" ซึ่งหมายถึง `Intersect` (เทียบกับตัวอย่าง `COUNTU` ในบทความที่ 2 ซึ่งใช้ `Intersect(theRange, theRange.Parent.UsedRange)`) ข้างต้นเป็นไปตามต้นฉบับ แต่ผู้อ่านควรใช้ `Intersect(theInputRange, theInputRange.Parent.UsedRange)` เมื่อนำไปใช้จริง

ถ้า UDF ใช้ฟังก์ชันเวิร์กชีตหรือ method ของออบเจ็กต์โมเดล Excel ประมวลผลช่วง โดยทั่วไปมีประสิทธิภาพกว่าถ้าเก็บช่วงไว้เป็นตัวแปรออบเจ็กต์ แทนการถ่ายโอนข้อมูลทั้งหมดจาก Excel ไปยัง UDF

```vb
  Function uLOOKUP(lookup_value As Variant, lookup_array As Range, _
                   col_num As Variant, sorted As Variant, _
                   NotFound As Variant)
      Dim vAnsa As Variant
      vAnsa = Application.VLookup(lookup_value, lookup_array, _
                                  col_num, sorted)
      If Not IsError(vAnsa) Then
          uLOOKUP = vAnsa
      Else
          uLOOKUP = NotFound
      End If
  End Function
```

ถ้า UDF ถูกเรียกในช่วงต้นของ calculation chain อาจได้รับอาร์กิวเมนต์ที่ยังไม่ได้คำนวณ ภายใน UDF ตรวจเซลล์ที่ยังไม่ได้คำนวณได้ด้วยการทดสอบเซลล์ว่างที่มีสูตรดังนี้:

```vb
  If ISEMPTY(Cell.Value) AND Len(Cell.formula)>0 then
```

มีโอเวอร์เฮดด้านเวลาในการเรียก UDF แต่ละครั้งและการถ่ายโอนข้อมูลแต่ละครั้งจาก Excel ไปยัง VBA บางครั้ง UDF แบบสูตรอาร์เรย์หลายเซลล์ตัวเดียวช่วยลดโอเวอร์เฮดเหล่านี้ได้ โดยรวมการเรียกฟังก์ชันหลายครั้งเป็นฟังก์ชันเดียวที่มีช่วงอินพุตหลายเซลล์และคืนช่วงของคำตอบ

### ลดช่วงเซลล์ที่ SUM และ SUMIF อ้างอิง

ฟังก์ชัน **SUM** และ **SUMIF** ของ Excel มักใช้กับเซลล์จำนวนมาก เวลาคำนวณของฟังก์ชันเหล่านี้เป็นสัดส่วนกับจำนวนเซลล์ที่ครอบคลุม ดังนั้นพยายามลดช่วงเซลล์ที่ฟังก์ชันอ้างอิงให้น้อยที่สุด

### ใช้ wildcard ใน SUMIF, COUNTIF, SUMIFS, COUNTIFS และฟังก์ชัน IFS อื่น

ใช้ตัวอักษร wildcard **?** (อักขระใดก็ได้หนึ่งตัว) และ **\*** (ไม่มีอักขระหรือกี่ตัวก็ได้) ในเงื่อนไขสำหรับช่วงที่เป็นตัวอักษร เป็นส่วนหนึ่งของ **SUMIF, COUNTIF, SUMIFS, COUNTIFS** และฟังก์ชัน **IFS** อื่น

### เลือกวิธีสำหรับ SUM ผลรวมสะสม (period-to-date และ cumulative)

มีสองวิธีทำ SUM แบบสะสม สมมติตัวเลขที่ต้องการรวมสะสมอยู่ในคอลัมน์ A และต้องการให้คอลัมน์ B มีผลรวมสะสม ทำได้ทั้งสองแบบ:

- สร้างสูตรในคอลัมน์ B เช่น `=SUM($A$1:$A2)` แล้วลากลง เซลล์เริ่มต้นของ SUM ถูกยึดที่ A1 แต่เซลล์สิ้นสุดมีการอ้างอิงแถวแบบสัมพัทธ์ จึงเพิ่มขึ้นเองในแต่ละแถว
- สร้างสูตร `=$A1` ในเซลล์ B1 และ `=$B1+$A2` ในเซลล์ B2 แล้วลากลง วิธีนี้คำนวณเซลล์สะสมโดยบวกตัวเลขของแถวนี้เข้ากับผลรวมสะสมก่อนหน้า

สำหรับ 1,000 แถว วิธีแรกทำให้ Excel คำนวณประมาณ **500,000** ครั้ง แต่วิธีที่สองเพียงประมาณ **2,000** ครั้ง

### คำนวณผลรวมของ subset

เมื่อมีดัชนีที่เรียงหลายตัวของตาราง (เช่น Site ภายใน Area) มักประหยัดเวลาคำนวณได้มาก โดยคำนวณแอดเดรสของช่วงย่อยของแถว (หรือคอลัมน์) แบบไดนามิกเพื่อใช้ในฟังก์ชัน **SUM** หรือ **SUMIF**

**วิธีคำนวณแอดเดรสของช่วงย่อยของแถวหรือคอลัมน์:**

1. นับจำนวนแถวของแต่ละบล็อกย่อย
2. บวกจำนวนสะสมของแต่ละบล็อกเพื่อหาแถวเริ่มต้น
3. ใช้ **OFFSET** กับแถวเริ่มต้นและจำนวน เพื่อคืนช่วงย่อยให้ **SUM** หรือ **SUMIF** ที่ครอบคลุมเฉพาะบล็อกย่อยของแถว

### ใช้ SUBTOTAL กับรายการที่กรอง

ใช้ฟังก์ชัน **SUBTOTAL** รวมรายการที่กรอง **SUBTOTAL** มีประโยชน์เพราะต่างจาก **SUM** ตรงที่มันข้าม:

- แถวที่ซ่อนจากการกรองรายการ ตั้งแต่ Excel 2003 ทำให้ **SUBTOTAL** ข้ามแถวที่ซ่อนทั้งหมดได้ ไม่ใช่เฉพาะแถวที่กรอง
- ฟังก์ชัน **SUBTOTAL** อื่น

### ใช้ฟังก์ชัน AGGREGATE

**AGGREGATE** เป็นวิธีที่ทรงพลังและมีประสิทธิภาพในการคำนวณการรวมข้อมูล 19 วิธี (เช่น **SUM, MEDIAN, PERCENTILE, LARGE**) **AGGREGATE** มีตัวเลือกให้ข้ามแถวที่ซ่อนหรือกรอง ค่า error และฟังก์ชัน **SUBTOTAL** และ **AGGREGATE** ที่ซ้อนกัน

### หลีกเลี่ยง DFunctions

DFunctions เช่น **DSUM, DCOUNT, DAVERAGE** เร็วกว่าสูตรอาร์เรย์ที่เทียบเท่ามาก ข้อเสียคือเงื่อนไขต้องอยู่ในช่วงแยกต่างหาก ทำให้ใช้และดูแลยากในหลายสถานการณ์ ตั้งแต่ Excel 2007 ควรใช้ **SUMIFS, COUNTIFS, AVERAGEIFS** แทน DFunctions

## 7. สร้างมาโคร VBA ที่เร็วขึ้น

ใช้เคล็ดลับต่อไปนี้เพื่อสร้างมาโคร VBA ที่เร็วขึ้น

### ใช้ `DoEvents` ป้องกัน Excel ไม่ตอบสนอง

มาโคร VBA ทำงานบนเธรดหลักของ Excel ซึ่งรับผิดชอบการอัปเดต UI และงานสำคัญอื่น มาโครที่ทำงานนานโดยไม่คืนการควบคุมอาจทำให้ Excel ไม่ตอบสนอง และอาจกระทบกระบวนการอื่นที่ขึ้นกับ message loop ของ Excel

เพื่อป้องกัน Excel ค้างระหว่างงานยาว ให้เรียกฟังก์ชัน `DoEvents` เป็นระยะในโค้ด VBA `DoEvents` คืนการควบคุมให้ระบบปฏิบัติการชั่วคราว ให้ Excel ประมวลผลเหตุการณ์ที่รออยู่และตอบสนองได้ สำคัญเป็นพิเศษกับมาโครที่วนลูป ประมวลผลข้อมูล หรือคำนวณมาก

ตัวอย่างการใส่ `DoEvents` ในลูป:

```vb
  Dim i As Long
  Dim counter As Long
  counter = 0
  For i = 1 To 100000
      ' โค้ดประมวลผลของคุณ
      Range("A" & i).Value = i * 2
      ' เรียก DoEvents เป็นระยะ (เช่น ทุก 100 รอบ)
      counter = counter + 1
      If counter Mod 100 = 0 Then
          DoEvents
      End If
  Next i
```

> **หมายเหตุ:** แม้ `DoEvents` ช่วยให้ตอบสนองดีขึ้น แต่เรียกบ่อยเกินไปจะทำให้มาโครทำงานช้าลง หาจุดสมดุลโดยเรียก `DoEvents` ในช่วงเวลาที่เหมาะสมตามการทำงานของมาโคร

### ปิดทุกอย่างยกเว้นสิ่งจำเป็นขณะโค้ดทำงาน

เพื่อปรับปรุงประสิทธิภาพของมาโคร VBA ให้ปิดฟังก์ชันที่ไม่จำเป็นอย่างชัดเจนขณะโค้ดทำงาน บ่อยครั้งการคำนวณใหม่หรือวาดหน้าจอใหม่เพียงครั้งเดียวหลังโค้ดทำงานก็เพียงพอ และช่วยปรับปรุงประสิทธิภาพ หลังโค้ดทำงานเสร็จ ให้คืนฟังก์ชันกลับสถานะเดิม

โดยปกติปิดฟังก์ชันต่อไปนี้ได้ขณะมาโคร VBA ทำงาน:

- **Application.ScreenUpdating** ปิดการอัปเดตหน้าจอ ถ้าตั้งเป็น **False** Excel จะไม่วาดหน้าจอใหม่ ขณะโค้ดทำงานหน้าจออัปเดตเร็ว และปกติผู้ใช้ไม่จำเป็นต้องเห็นทุกการอัปเดต อัปเดตหน้าจอครั้งเดียวหลังโค้ดทำงานช่วยเพิ่มประสิทธิภาพ
- **Application.DisplayStatusBar** ปิดแถบสถานะ ถ้าตั้งเป็น **False** Excel ไม่แสดงแถบสถานะ การตั้งค่านี้แยกจากการอัปเดตหน้าจอ เพื่อให้ยังแสดงสถานะของการทำงานปัจจุบันได้แม้หน้าจอไม่อัปเดต แต่ถ้าไม่ต้องแสดงสถานะทุกการทำงาน การปิดแถบสถานะขณะโค้ดทำงานก็ช่วยประสิทธิภาพ
- **Application.Calculation** สลับเป็นการคำนวณแบบ manual ถ้าตั้งเป็น **xlCalculationManual** Excel จะคำนวณเวิร์กบุ๊กเมื่อผู้ใช้สั่งชัดเจนเท่านั้น ในโหมด automatic Excel เป็นผู้ตัดสินใจว่าจะคำนวณเมื่อไร เช่น ทุกครั้งที่ค่าเซลล์ที่เกี่ยวกับสูตรเปลี่ยน Excel คำนวณสูตรใหม่ ถ้าสลับเป็น manual รอได้จนกว่าเซลล์ที่เกี่ยวข้องกับสูตรทั้งหมดอัปเดตแล้วจึงคำนวณเวิร์กบุ๊กใหม่ การคำนวณใหม่เฉพาะเมื่อจำเป็นขณะโค้ดทำงานช่วยเพิ่มประสิทธิภาพ
- **Application.EnableEvents** ปิด event ถ้าตั้งเป็น **False** Excel จะไม่ยก event ถ้ามี add-in ที่ฟัง event ของ Excel อยู่ add-in เหล่านั้นใช้ทรัพยากรของเครื่องขณะบันทึก event ถ้า add-in ไม่จำเป็นต้องบันทึก event ที่เกิดขณะโค้ดทำงาน การปิด event ช่วยเพิ่มประสิทธิภาพ
- **ActiveSheet.DisplayPageBreaks** ปิดตัวแบ่งหน้า ถ้าตั้งเป็น **False** Excel จะไม่แสดงตัวแบ่งหน้า ไม่จำเป็นต้องคำนวณตัวแบ่งหน้าใหม่ขณะโค้ดทำงาน และคำนวณหลังโค้ดทำงานเสร็จช่วยเพิ่มประสิทธิภาพ

> **สำคัญ:** อย่าลืมคืนฟังก์ชันเหล่านี้กลับสถานะเดิมหลังโค้ดทำงานเสร็จ

ตัวอย่างต่อไปแสดงฟังก์ชันที่ปิดได้ขณะมาโคร VBA ทำงาน

```vb
  ' บันทึกสถานะปัจจุบันของการตั้งค่า Excel
  screenUpdateState = Application.ScreenUpdating
  statusBarState = Application.DisplayStatusBar
  calcState = Application.Calculation
  eventsState = Application.EnableEvents
  ' หมายเหตุ: นี่เป็นการตั้งค่าระดับเวิร์กชีต
  displayPageBreakState = ActiveSheet.DisplayPageBreaks
  ' ปิดฟังก์ชันของ Excel เพื่อเพิ่มประสิทธิภาพ
  Application.ScreenUpdating = False
  Application.DisplayStatusBar = False
  Application.Calculation = xlCalculationManual
  Application.EnableEvents = False
  ' หมายเหตุ: นี่เป็นการตั้งค่าระดับเวิร์กชีต
  ActiveSheet.DisplayPageBreaks = False
  ' ใส่โค้ดของคุณที่นี่
  ' คืนการตั้งค่า Excel กลับสถานะเดิม
  Application.ScreenUpdating = screenUpdateState
  Application.DisplayStatusBar = statusBarState
  Application.Calculation = calcState
  Application.EnableEvents = eventsState
  ' หมายเหตุ: นี่เป็นการตั้งค่าระดับเวิร์กชีต
  ActiveSheet.DisplayPageBreaks = displayPageBreaksState
```

> **หมายเหตุผู้แปล:** ในต้นฉบับ ตัวแปรที่บันทึกคือ `displayPageBreakState` แต่ตอนคืนค่าใช้ `displayPageBreaksState` (มี s) ต่างกัน ถ้านำไปใช้จริงควรใช้ชื่อเดียวกัน (และใส่ `Option Explicit` เพื่อให้คอมไพเลอร์จับความผิดพลาดแบบนี้)

### อ่านและเขียนข้อมูลก้อนใหญ่ในการดำเนินการเดียว

ปรับโค้ดให้เหมาะสมโดยลดจำนวนครั้งที่ข้อมูลถูกถ่ายโอนระหว่าง Excel กับโค้ดอย่างชัดเจน แทนที่จะวนทีละเซลล์เพื่ออ่านหรือเขียนค่า ให้อ่านหรือเขียนค่าของช่วงเซลล์ทั้งหมดในบรรทัดเดียว โดยใช้ variant ที่เก็บอาร์เรย์สองมิติเพื่อเก็บค่าตามต้องการ ตัวอย่างโค้ดต่อไปเปรียบเทียบสองวิธี

**โค้ดที่ไม่ได้ปรับ** วนทีละเซลล์เพื่ออ่านและเขียนค่าของ A1:C10000 (เซลล์เหล่านี้ไม่มีสูตร):

```vb
  Dim DataRange as Range
  Dim Irow as Long
  Dim Icol as Integer
  Dim MyVar as Double
  Set DataRange=Range("A1:C10000")
  For Irow=1 to 10000
      For icol=1 to 3
          ' อ่านค่าจากตาราง Excel 30,000 ครั้ง
          MyVar=DataRange(Irow,Icol)
          If MyVar > 0 then
              ' เปลี่ยนค่า
              MyVar=MyVar*Myvar
              ' เขียนค่ากลับเข้าตาราง Excel 30,000 ครั้ง
              DataRange(Irow,Icol)=MyVar
          End If
      Next Icol
  Next Irow
```

**โค้ดที่ปรับแล้ว** ใช้อาร์เรย์อ่านและเขียนค่าของ A1:C10000 พร้อมกันทั้งหมด (เซลล์เหล่านี้ไม่มีสูตร):

```vb
  Dim DataRange As Variant
  Dim Irow As Long
  Dim Icol As Integer
  Dim MyVar As Double
  ' อ่านค่าทั้งหมดพร้อมกันจากตาราง Excel แล้วใส่ในอาร์เรย์
  DataRange = Range("A1:C10000").Value2
  For Irow = 1 To 10000
      For Icol = 1 To 3
          MyVar = DataRange(Irow, Icol)
          If MyVar > 0 Then
              ' เปลี่ยนค่าในอาร์เรย์
              MyVar=MyVar*Myvar
              DataRange(Irow, Icol) = MyVar
          End If
      Next Icol
  Next Irow
  ' เขียนค่าทั้งหมดกลับเข้าช่วงพร้อมกัน
  Range("A1:C10000").Value2 = DataRange
```

### ใช้ .Value2 แทน .Value หรือ .Text เมื่ออ่านข้อมูลจากช่วงใน Excel

- **.Text** คืนค่าที่จัดรูปแบบแล้วของเซลล์ ช้า อาจคืน ### ถ้าผู้ใช้ซูม และอาจสูญเสียความแม่นยำ
- **.Value** คืนตัวแปร currency หรือ date ของ VBA ถ้าช่วงถูกจัดรูปแบบเป็น Date หรือ Currency ช้า อาจสูญเสียความแม่นยำ และอาจเกิดข้อผิดพลาดเมื่อเรียกฟังก์ชันเวิร์กชีต
- **.Value2** เร็วและไม่เปลี่ยนแปลงข้อมูลที่ดึงจาก Excel

### หลีกเลี่ยงการ select และ activate ออบเจ็กต์

การเลือก (select) และทำให้ active ออบเจ็กต์ใช้การประมวลผลมากกว่าการอ้างอิงออบเจ็กต์โดยตรง การอ้างอิงออบเจ็กต์เช่น **Range** หรือ **Shape** โดยตรงช่วยเพิ่มประสิทธิภาพ ตัวอย่างต่อไปเปรียบเทียบสองวิธี

**โค้ดที่ไม่ได้ปรับ** เลือกทุก Shape บนชีตที่ active แล้วเปลี่ยนข้อความเป็น "Hello":

```vb
  For i = 0 To ActiveSheet.Shapes.Count
      ActiveSheet.Shapes(i).Select
      Selection.Text = "Hello"
  Next i
```

**โค้ดที่ปรับแล้ว** อ้างอิงแต่ละ Shape โดยตรงและเปลี่ยนข้อความเป็น "Hello":

```vb
  For i = 0 To ActiveSheet.Shapes.Count
      ActiveSheet.Shapes(i).TextEffect.Text = "Hello"
  Next i
```

### การปรับประสิทธิภาพ VBA เพิ่มเติม

รายการการปรับปรุงประสิทธิภาพเพิ่มเติมที่ใช้ในโค้ด VBA ได้:

- คืนผลลัพธ์โดยกำหนดอาร์เรย์ให้ **Range** โดยตรง
- ประกาศตัวแปรพร้อมชนิดข้อมูลอย่างชัดเจน เพื่อหลีกเลี่ยงโอเวอร์เฮดของการกำหนดชนิดข้อมูล ซึ่งอาจเกิดหลายครั้งในลูประหว่างโค้ดทำงาน
- สำหรับฟังก์ชันง่าย ๆ ที่ใช้บ่อยในโค้ด ให้เขียนฟังก์ชันนั้นเองใน VBA แทนการใช้ออบเจ็กต์ **WorksheetFunction** ดูหัวข้อ "ใช้ UDF ของ VBA ที่เร็วกว่า" ด้านบน
- ใช้ method **Range.SpecialCells** จำกัดจำนวนเซลล์ที่โค้ดโต้ตอบด้วย
- พิจารณาประสิทธิภาพที่เพิ่มขึ้นถ้าเขียนฟังก์ชันด้วย C API ใน XLL SDK ข้อมูลเพิ่มเติม: Excel 2010 XLL SDK Documentation (<https://learn.microsoft.com/en-us/office/vba/api/overview/excel>)

## 8. พิจารณาประสิทธิภาพและขนาดของรูปแบบไฟล์ Excel

ตั้งแต่ Excel 2007 Excel มีรูปแบบไฟล์หลากหลายกว่ารุ่นก่อน ไม่นับรูปแบบมาโคร เทมเพลต add-in PDF และ XPS รูปแบบหลักมีสามแบบ คือ XLS, XLSB และ XLSX

- **รูปแบบ XLS** เป็นรูปแบบเดียวกับรุ่นก่อน เมื่อใช้รูปแบบนี้ถูกจำกัดที่ 256 คอลัมน์และ 65,536 แถว เมื่อบันทึกเวิร์กบุ๊ก Excel 2007 หรือ 2010 เป็น XLS Excel จะรันการตรวจความเข้ากันได้ ขนาดไฟล์เกือบเท่ารุ่นก่อน (อาจเก็บข้อมูลเพิ่มเล็กน้อย) และประสิทธิภาพช้ากว่ารุ่นก่อนเล็กน้อย การปรับให้เหมาะสมแบบหลายเธรดที่ Excel ทำเกี่ยวกับลำดับการคำนวณเซลล์ **ไม่ถูกบันทึก** ในรูปแบบ XLS ดังนั้นการคำนวณเวิร์กบุ๊กอาจช้าลงหลังบันทึกเป็น XLS ปิด แล้วเปิดใหม่
- **รูปแบบ XLSB** เป็นรูปแบบไบนารีตั้งแต่ Excel 2007 โครงสร้างเป็นโฟลเดอร์บีบอัดที่มีไฟล์ไบนารีหลายไฟล์ กะทัดรัดกว่า XLS มาก แต่ปริมาณการบีบอัดขึ้นกับเนื้อหาของเวิร์กบุ๊ก เช่น เวิร์กบุ๊ก 10 เล่มลดขนาดได้ 2 ถึง 8 เท่า เฉลี่ย 4 เท่า ตั้งแต่ Excel 2007 ประสิทธิภาพการเปิดและบันทึกช้ากว่า XLS เพียงเล็กน้อย
- **รูปแบบ XLSX** เป็นรูปแบบ XML ตั้งแต่ Excel 2007 และเป็นรูปแบบเริ่มต้นตั้งแต่ Excel 2007 XLSX เป็นโฟลเดอร์บีบอัดที่มีไฟล์ XML หลายไฟล์ (ถ้าเปลี่ยนนามสกุลไฟล์เป็น .zip จะเปิดโฟลเดอร์บีบอัดและตรวจดูเนื้อหาได้) โดยทั่วไป XLSX สร้างไฟล์ใหญ่กว่า XLSB (ใหญ่กว่าเฉลี่ย 1.5 เท่า) แต่ยังเล็กกว่าไฟล์ XLS มาก คาดว่าเวลาเปิดและบันทึกนานกว่า XLSB เล็กน้อย

| รูปแบบ | ขนาด | ความเร็วเปิด/บันทึก | ข้อควรระวัง |
| :-- | :-- | :-- | :-- |
| XLS | ใหญ่ที่สุด | ช้ากว่ารุ่นก่อนเล็กน้อย | จำกัด 256 คอลัมน์ × 65,536 แถว; ไม่เก็บการปรับหลายเธรด |
| XLSB | เล็กที่สุด (เล็กลง 2–8 เท่า เฉลี่ย 4 เท่าเทียบกับ XLS) | ช้ากว่า XLS เล็กน้อย | ไบนารี |
| XLSX | ใหญ่กว่า XLSB เฉลี่ย 1.5 เท่า | ช้ากว่า XLSB เล็กน้อย | เป็นรูปแบบเริ่มต้น |

## 9. เปิด ปิด และบันทึกเวิร์กบุ๊ก

บางครั้งการเปิด ปิด และบันทึกเวิร์กบุ๊กช้ากว่าการคำนวณมาก บางครั้งเป็นเพราะเวิร์กบุ๊กใหญ่ แต่อาจมีเหตุผลอื่นด้วย

ถ้าเวิร์กบุ๊กหนึ่งเล่มขึ้นไปเปิดและปิดช้ากว่าที่สมเหตุสมผล อาจเกิดจากปัญหาข้อใดข้อหนึ่งต่อไปนี้

- **ไฟล์ชั่วคราว (Temporary files)** ไฟล์ชั่วคราวอาจสะสมในไดเรกทอรี \Windows\Temp (Windows 95/98/ME) หรือ \Documents and Settings\User Name\Local Settings\Temp (Windows 2000 และ XP) Excel สร้างไฟล์เหล่านี้สำหรับเวิร์กบุ๊กและตัวควบคุมที่ใช้ในเวิร์กบุ๊กที่เปิดอยู่ โปรแกรมติดตั้งซอฟต์แวร์ก็สร้างไฟล์ชั่วคราวเช่นกัน ถ้า Excel หยุดตอบสนองด้วยเหตุใดก็ตาม อาจต้องลบไฟล์เหล่านี้
  ไฟล์ชั่วคราวมากเกินไปก่อปัญหาได้ จึงควรล้างเป็นครั้งคราว แต่ถ้าติดตั้งซอฟต์แวร์ที่ต้องรีสตาร์ตคอมพิวเตอร์และยังไม่รีสตาร์ต ควรรีสตาร์ตก่อนลบไฟล์ชั่วคราว
  เปิดไดเรกทอรี temp ได้ง่าย ๆ จากเมนู **Start** ของ Windows: คลิก **Start** แล้วคลิก **Run** พิมพ์ **%temp%** ในกล่องข้อความ แล้วคลิก **OK**
- **การติดตามการเปลี่ยนแปลงในเวิร์กบุ๊กที่แชร์** การติดตามการเปลี่ยนแปลงในเวิร์กบุ๊กที่แชร์ทำให้ขนาดไฟล์เวิร์กบุ๊กเพิ่มอย่างรวดเร็ว
- **Swap file ที่กระจัดกระจาย** ตรวจว่า swap file ของ Windows อยู่บนดิสก์ที่มีพื้นที่มาก และจัดเรียงดิสก์ (defragment) เป็นระยะ
- **เวิร์กบุ๊กที่ป้องกันโครงสร้างด้วยรหัสผ่าน** เวิร์กบุ๊กที่ป้องกันโครงสร้างด้วยรหัสผ่าน (เมนู **Tools** > **Protection** > **Protect Workbook** > ใส่รหัสผ่านที่เป็นทางเลือก) เปิดและปิดช้ากว่าเวิร์กบุ๊กที่ป้องกันโดยไม่มีรหัสผ่านมาก
- **ปัญหา used range** used range ที่ใหญ่เกินไปทำให้เปิดช้าและไฟล์ใหญ่ขึ้น โดยเฉพาะถ้าเกิดจากแถวหรือคอลัมน์ที่ซ่อนซึ่งมีความสูงหรือกว้างไม่เป็นมาตรฐาน ดูหัวข้อ "ลด used range ให้น้อยที่สุด" ข้างต้น
- **ตัวควบคุมจำนวนมากบนเวิร์กชีต** ตัวควบคุมจำนวนมาก (check box, ไฮเปอร์ลิงก์ ฯลฯ) บนเวิร์กชีตทำให้เปิดเวิร์กบุ๊กช้า เพราะจำนวนไฟล์ชั่วคราวที่ใช้ และอาจก่อปัญหาในการเปิดหรือบันทึกเวิร์กบุ๊กบน WAN (หรือแม้แต่ LAN) ถ้ามีปัญหานี้ ควรพิจารณาออกแบบเวิร์กบุ๊กใหม่
- **ลิงก์ไปยังเวิร์กบุ๊กอื่นจำนวนมาก** ถ้าเป็นไปได้ ให้เปิดเวิร์กบุ๊กที่ลิงก์ไปถึงก่อนเปิดเวิร์กบุ๊กที่มีลิงก์ มักเปิดเวิร์กบุ๊กได้เร็วกว่าอ่านลิงก์จากเวิร์กบุ๊กที่ปิดอยู่
- **การตั้งค่าโปรแกรมสแกนไวรัส** การตั้งค่าโปรแกรมสแกนไวรัสบางอย่างก่อปัญหาหรือความช้าในการเปิด ปิด หรือบันทึก โดยเฉพาะบนเซิร์ฟเวอร์ ถ้าสงสัยว่าเป็นสาเหตุ ลองปิดโปรแกรมสแกนไวรัสชั่วคราว
- **การคำนวณช้าทำให้เปิดและบันทึกช้า** ในบางสถานการณ์ Excel คำนวณเวิร์กบุ๊กใหม่เมื่อเปิดหรือบันทึก ถ้าเวลาคำนวณของเวิร์กบุ๊กนานจนเป็นปัญหา ให้ตรวจว่าตั้งการคำนวณเป็น **manual** และพิจารณาปิดตัวเลือก **calculate before save** (**Tools** > **Options** > **Calculation**)
- **ไฟล์ Toolbar (.xlb)** ตรวจขนาดไฟล์ toolbar ปกติอยู่ที่ 10–20 KB ค้นหาไฟล์ XLB ได้โดยค้น `*.xlb` ด้วยการค้นหาของ Windows ผู้ใช้แต่ละคนมีไฟล์ XLB เฉพาะตัว การเพิ่ม เปลี่ยน หรือปรับแต่ง toolbar ทำให้ไฟล์ toolbar.xlb ใหญ่ขึ้น การลบไฟล์จะลบการปรับแต่ง toolbar ทั้งหมด (ปลอดภัยกว่าถ้าเปลี่ยนชื่อเป็น "toolbar.OLD") ไฟล์ XLB ใหม่จะถูกสร้างเมื่อเปิด Excel ครั้งถัดไป

## 10. การปรับประสิทธิภาพเพิ่มเติม

ปรับปรุงประสิทธิภาพได้ในด้านต่อไปนี้

- **PivotTables** เป็นวิธีที่มีประสิทธิภาพในการสรุปข้อมูลปริมาณมาก
  - **ผลรวมเป็นผลลัพธ์สุดท้าย:** ถ้าต้องสร้างผลรวมและผลรวมย่อยเป็นส่วนหนึ่งของผลลัพธ์สุดท้ายของเวิร์กบุ๊ก ลองใช้ PivotTable
  - **ผลรวมเป็นผลลัพธ์ระหว่างทาง:** PivotTable เหมาะสร้างรายงานสรุป แต่พยายามหลีกเลี่ยงการสร้างสูตรที่ใช้ผลของ PivotTable เป็นผลรวมระหว่างทางใน calculation chain เว้นแต่รับรองได้ว่า (1) PivotTable ถูกรีเฟรชถูกต้องระหว่างการคำนวณ และ (2) PivotTable ไม่ถูกเปลี่ยนจนข้อมูลยังมองเห็นอยู่
  - ถ้ายังต้องการใช้ PivotTable เป็นผลลัพธ์ระหว่างทาง ให้ใช้ฟังก์ชัน **GETPIVOTDATA**
- **Conditional formats และ data validation** ดีมาก แต่การใช้จำนวนมากทำให้การคำนวณช้าลงอย่างมาก ถ้าเซลล์ถูกแสดงอยู่ ทุกสูตร conditional format จะถูกประเมินในทุกการคำนวณ และเมื่อการแสดงผลของเซลล์ที่มี conditional format ถูกรีเฟรช ออบเจ็กต์โมเดลของ Excel มี property **Worksheet.EnableFormatConditionsCalculation** เพื่อเปิด/ปิดการคำนวณ conditional format
- **Defined names** เป็นหนึ่งในฟีเจอร์ที่ทรงพลังที่สุดของ Excel แต่ใช้เวลาคำนวณเพิ่ม การใช้ชื่อที่อ้างถึงเวิร์กชีตอื่นเพิ่มความซับซ้อนอีกระดับในกระบวนการคำนวณ และควรหลีกเลี่ยง **nested names** (ชื่อที่อ้างถึงชื่ออื่น)
  เพราะชื่อถูกคำนวณทุกครั้งที่สูตรที่อ้างถึงมันถูกคำนวณ ควรหลีกเลี่ยงการใส่สูตรหรือฟังก์ชันที่ใช้การคำนวณหนักใน defined name ในกรณีเหล่านี้ อาจเร็วกว่ามากถ้าใส่สูตรหรือฟังก์ชันที่คำนวณหนักไว้ในเซลล์ว่างที่ใดที่หนึ่ง แล้วอ้างถึงเซลล์นั้นโดยตรงหรือผ่านชื่อ
- **สูตรที่ใช้เป็นครั้งคราว** เวิร์กบุ๊กจำนวนมากมีสูตรและ lookup จำนวนมากที่เกี่ยวกับการจัดข้อมูลนำเข้าให้อยู่ในรูปที่เหมาะกับการคำนวณ หรือใช้เป็นมาตรการป้องกันการเปลี่ยนขนาดหรือรูปร่างของข้อมูล เมื่อมีบล็อกสูตรที่ใช้เป็นครั้งคราว คัดลอกแล้ววาง special values เพื่อกำจัดสูตรชั่วคราวได้ หรือใส่ไว้ในเวิร์กบุ๊กแยกที่ไม่ค่อยเปิด เพราะข้อผิดพลาดของเวิร์กชีตมักเกิดจากการไม่สังเกตว่าสูตรถูกแปลงเป็นค่า วิธีเวิร์กบุ๊กแยกจึงอาจดีกว่า
- **ใช้หน่วยความจำให้พอ** Excel 32 บิตใช้ RAM ได้ถึง 2 GB หรือถึง 4 GB สำหรับ Excel 2013 และ 2016 รุ่น 32 บิตแบบ Large Address Aware แต่คอมพิวเตอร์ที่รัน Excel ก็ต้องใช้ทรัพยากรหน่วยความจำด้วย ดังนั้นถ้าเครื่องมี RAM เพียง 2 GB Excel จะใช้ได้ไม่เต็ม 2 GB เพราะส่วนหนึ่งถูกจัดสรรให้ระบบปฏิบัติการและโปรแกรมอื่นที่รันอยู่ เพื่อเพิ่มประสิทธิภาพ Excel บนคอมพิวเตอร์ 32 บิต แนะนำให้มี RAM อย่างน้อย **3 GB**
  Excel 64 บิตไม่มีขีดจำกัด 2 GB หรือ 4 GB ข้อมูลเพิ่มเติม: หัวข้อ "Large data sets and the 64-bit version of Excel" ใน [Performance and limit improvements](05a-performance-and-limit-improvements.md)

## 12. สรุปเทคนิคสำหรับโปรเจกต์ที่ต้องอ่านและเขียน Excel ด้วย VBA

(ผู้แปลสรุปจากเนื้อหาของบทความ)

**เช็กลิสต์มาโคร VBA ที่เร็ว:**

1. สำรองสถานะ → ปิด `ScreenUpdating`, `DisplayStatusBar`, `EnableEvents`, `DisplayPageBreaks`, ตั้ง `Calculation = xlCalculationManual` → ทำงาน → **คืนสถานะ** (ใช้ error handler เพื่อให้คืนค่าแม้เกิดข้อผิดพลาด)
2. อ่าน/เขียนเป็น **บล็อก**: `arr = Range(...).Value2` → วนบนอาร์เรย์ → `Range(...).Value2 = arr`
3. ใช้ `.Value2` ไม่ใช่ `.Value`/`.Text`
4. อย่า `Select`/`Activate` อ้างอิงออบเจ็กต์ตรง ๆ
5. ประกาศชนิดตัวแปรชัดเจน; ใช้ `SpecialCells` จำกัดขอบเขต
6. งานยาว: เรียก `DoEvents` เป็นระยะ (เช่นทุก 100 รอบ)

**เช็กลิสต์สูตรและเวิร์กบุ๊ก:**

1. เลี่ยง volatile (`OFFSET`, `INDIRECT`), เลี่ยง circular reference, เลี่ยงลิงก์ข้ามเวิร์กบุ๊ก
2. ใช้ Table + structured reference แทนช่วงใหญ่/ทั้งคอลัมน์ในสูตรอาร์เรย์
3. ค้นหา: เรียงข้อมูลแล้ว approximate match, หรือ `MATCH` ครั้งเดียว + `INDEX` หลายคอลัมน์, `IFERROR`
4. รวมเงื่อนไข: `SUMIFS`/`COUNTIFS`/`AVERAGEIFS`/`MAXIFS`/`MINIFS` ก่อนสูตรอาร์เรย์ และวางเงื่อนไขที่เข้มที่สุดก่อน
5. รวมสะสมด้วยการบวกต่อเนื่อง (`=B1+A2`) แทนการรวมช่วงที่ขยายตัว
6. เลือกรูปแบบไฟล์: XLSB เล็กสุด, XLSX เป็นค่าเริ่มต้น, หลีกเลี่ยง XLS ถ้าไม่จำเป็น
