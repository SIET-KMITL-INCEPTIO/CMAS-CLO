## 1. ปรับปรุง SUMIFS และตระกูล

ใน Office 365 เวอร์ชัน 2005 monthly channel ขึ้นไป ฟังก์ชัน SUMIFS, AVERAGEIFS, COUNTIFS, MAXIFS, MINIFS รวมถึง SUMIF, AVERAGEIF, COUNTIF เร็วกว่า Excel 2010 มากเมื่อรวมข้อมูลสตริงในสเปรดชีต ฟังก์ชันเหล่านี้สร้าง **ดัชนีแคชภายใน** สำหรับช่วงที่ค้นหาในแต่ละเงื่อนไข และใช้ดัชนีนั้นซ้ำในการรวมข้อมูลครั้งถัด ๆ ไปที่ดึงจากช่วงเดียวกัน

ผลที่ได้ชัดเจน ตัวอย่าง: คำนวณสูตร SUMIFS, AVERAGEIFS และ COUNTIFS จำนวน 1,200 สูตร ที่รวมข้อมูลจาก 1 ล้านเซลล์ บน CPU 4 คอร์ 2 GHz ใช้ 20 วินาทีใน Excel 2010 แต่ใช้เพียง 8 วินาทีใน Excel M365 เวอร์ชัน 2006

## 2. ฟังก์ชัน RealTimeData (RTD)

ใน Excel M365 เวอร์ชัน 2002 monthly channel ขึ้นไป ฟังก์ชัน [RealTimeData (RTD)](https://learn.microsoft.com/en-us/office/troubleshoot/excel/set-up-realtimedata-function) เร็วกว่า Excel 2010 มาก มีการกำจัดคอขวดในหน่วยความจำและโครงสร้างข้อมูลพื้นฐาน และทำให้เป็น thread-safe เพื่อให้คำนวณบนทุกเธรดที่มีของ [Multithreaded recalculation (MTR)](https://learn.microsoft.com/en-us/office/client-developer/excel/multithreaded-recalculation-in-excel) ได้

ตัวอย่าง: จำลองการอัปเดต RTD 125,000 ครั้งสำหรับหัวข้อหุ้นอย่าง "Last Price", "Ask", "Bid" เพื่อคำนวณค่าอย่าง "Trade Volume", "Market Value", "Trade Gain/Loss" ในเซลล์รวม 500,000 เซลล์ ใช้ 47 วินาทีใน Excel 2010 และเพียง 7 วินาทีใน Excel M365 เวอร์ชัน 2002 บนฮาร์ดแวร์เดียวกัน

ผลดีอีกอย่างของการทำให้ RTD เป็น thread-safe คือ MTR ไม่ต้องหยุดชั่วคราวเพื่อรัน RTD อีกต่อไป ช่วยเพิ่มประสิทธิภาพชัดเจนเมื่อรัน RTD ร่วมกับการคำนวณอื่นจำนวนมาก

ตัวอย่าง: เวิร์กบุ๊กที่มี RTD 10,000 ตัวและ VLOOKUP 10,000 ตัว โดย VLOOKUP แต่ละตัวขึ้นกับผลของ RTD ถ้า RTD ไม่ thread-safe การคำนวณใหม่ทั้งหมดใช้ 10.20 วินาที แต่เมื่อ thread-safe ใช้ 5.84 วินาที

## 3. ปรับปรุง VLOOKUP, HLOOKUP, MATCH

ใน Office 365 เวอร์ชัน 1809 ขึ้นไป VLOOKUP, HLOOKUP และ MATCH แบบตรงทุกตัว (exact match) บนข้อมูลที่ไม่เรียง เร็วกว่าเดิมมากเมื่อค้นหาหลายคอลัมน์ (หรือหลายแถวสำหรับ HLOOKUP) จากช่วงตารางเดียวกัน

ฟังก์ชันค้นหาเหล่านี้สร้าง **ดัชนีแคชภายใน** สำหรับช่วงคอลัมน์ที่ค้นหา และใช้ดัชนีซ้ำในการค้นหาครั้งถัดไปที่ดึงจากแถวเดียวกัน (VLOOKUP และ MATCH) หรือคอลัมน์เดียวกัน (HLOOKUP) ผลชัดเจน: การค้นหา 5 คอลัมน์ต่างกันในช่วงตารางเดียวกันเร็วกว่า Excel 2010 หรือ Excel 2016 ได้ถึง 4 เท่า และยิ่งค้นหาหลายคอลัมน์ ยิ่งดีขึ้น

*ตัวอย่าง: คำนวณ 100 แถวของสูตร VLOOKUP 5 ตัวด้านล่าง ใช้ 37 วินาทีใน Excel 2010 และเพียง 12 วินาทีใน Excel 2016*

```excel
    =VLOOKUP($A900000,$A$2:$E$1000000,1,FALSE)
    =VLOOKUP($A900000,$A$2:$E$1000000,2,FALSE)
    =VLOOKUP($A900000,$A$2:$E$1000000,3,FALSE)
    =VLOOKUP($A900000,$A$2:$E$1000000,4,FALSE)
    =VLOOKUP($A900000,$A$2:$E$1000000,5,FALSE)
```

**เทคนิค:** ให้ทุกสูตรค้นหาจาก **ช่วงตารางเดียวกันและคอลัมน์ค้นหาเดียวกัน** เพื่อใช้ดัชนีแคชร่วมกัน

## 4. หน่วยความจำ LAA สำหรับ Excel 32 บิต

แม้ Excel 64 บิตมีขีดจำกัดหน่วยความจำเสมือนสูงมาก แต่ Excel 32 บิตมีเพียง 2 GB บางลูกค้าใช้ 32 บิตเพราะส่วนเสริมและตัวควบคุมจากบริษัทอื่นบางตัวไม่มีรุ่น 64 บิต

Excel 2013 และ 2016 รุ่น 32 บิตเปิดใช้ **Large Address Aware (LAA)** แล้ว ซึ่งช่วยลดข้อความ out-of-memory

LAA เพิ่มหน่วยความจำเสมือนที่ใช้ได้จาก 2 GB เป็น 4 GB บน Windows 64 บิต และจาก 2 GB เป็น 3 GB บน Windows 32 บิต

ข้อมูลเพิ่มเติม: [Large Address Aware Capability Change for Excel](https://support.microsoft.com/help/3160741/large-address-aware-capability-change-for-excel)
เครื่องมือแสดงหน่วยความจำเสมือนที่เหลือและที่ใช้อยู่: [Excel Memory Checking Tool](https://fastexcel.wordpress.com/2016/11/27/excel-memory-checking-tool-using-laa-to-increase-useable-excel-memory/)

## 5. การอ้างอิงทั้งคอลัมน์

ใน Excel รุ่นก่อน เวิร์กบุ๊กที่ใช้การอ้างอิงทั้งคอลัมน์จำนวนมากและหลายเวิร์กชีต (เช่น `=COUNTIF(Sheet2!A:A,Sheet3!A1)`) อาจใช้หน่วยความจำและ CPU มากเมื่อเปิดไฟล์หรือเมื่อลบแถว

Excel 2016 บิลด์ 16.0.8212.1000 ลดการใช้หน่วยความจำและ CPU ในกรณีเหล่านี้

*ในการทดสอบตัวอย่างกับเวิร์กบุ๊กที่มี 6 ล้านสูตร การใช้การอ้างอิงทั้งคอลัมน์ล้มเหลวด้วยข้อความ out-of-memory ที่หน่วยความจำเสมือน 4 GB ใน Excel 2013 LAA และ Excel 2010 แต่ใช้เพียง 2 GB ใน Excel 2016*

## 6. Structured References

ใน Excel 2013 และรุ่นก่อน การแก้ไขตารางที่สูตรในเวิร์กบุ๊กใช้ structured reference อ้างถึงตารางนั้นช้า ทำให้เกิดความเข้าใจว่าไม่ควรใช้ตารางกับจำนวนแถวมาก ปัญหานี้ไม่เกิดใน Excel 2016 แล้ว

*ตัวอย่าง: การแก้ไขที่ใช้ 1.9 วินาทีใน Excel 2013 และ 2010 ใช้ประมาณ 2 มิลลิวินาทีใน Excel 2016*

## 7. Filter, Sort และ Copy/Paste

ปรับปรุงเวลาตอบสนองเมื่อกรอง เรียง และคัดลอก/วางในเวิร์กบุ๊กขนาดใหญ่หลายอย่าง

ใน Excel 2013 หลังกรอง เรียง หรือคัดลอก/วางหลายแถว Excel อาจตอบสนองช้าหรือค้าง ประสิทธิภาพขึ้นกับจำนวนแถวทั้งหมดระหว่างแถวบนสุดและล่างสุดที่มองเห็น การทำงานเหล่านี้เร็วขึ้นมากหลังปรับปรุงการคำนวณตำแหน่งแนวตั้งของ UI ภายในในบิลด์ 16.0.8431.2058

การเปิดเวิร์กบุ๊กที่มีแถวที่กรองหรือซ่อนจำนวนมาก เซลล์ที่ merge หรือ outline อาจทำให้ CPU สูง แก้ไขในบิลด์ 16.0.8229.1000

หลังวางคอลัมน์ที่คัดลอกจากตารางที่กรองแล้วเหลือแถวเป็นกลุ่มแยกกันจำนวนมาก เวลาตอบสนองช้ามาก ปรับปรุงในบิลด์ 16.0.8327.1000

*ทดสอบตัวอย่างคัดลอก/วาง 22,000 แถวที่กรองจาก 44,000 แถว*

- *ตาราง (table): 39 วินาทีใน Excel 2013 และ 18 วินาทีใน Excel 2010 เหลือ 2 วินาทีใน Excel 2016*
- *ช่วงข้อมูล (range): 30 วินาทีใน Excel 2013 และ 13 วินาทีใน Excel 2010 เหลือแทบทันทีใน Excel 2016*

## 10. ฟังก์ชันใหม่

Excel 2016 บิลด์ 16.0.7920.1000 เพิ่มฟังก์ชันเวิร์กชีตที่มีประโยชน์:

- **MAXIFS** และ **MINIFS** ขยายตระกูล **COUNTIFS/SUMIFS** มีประสิทธิภาพดี ใช้แทนสูตรอาร์เรย์ที่เทียบเท่าได้

## 11. การปรับปรุงใน Excel 2010

จากข้อเสนอแนะของผู้ใช้ Excel 2007 ทำให้ Excel 2010 ปรับปรุงหลายฟีเจอร์

| ฟีเจอร์ | การปรับปรุง |
| :-- | :-- |
| **เครื่องพิมพ์และมุมมอง Page Layout** | เพื่อเพิ่มประสิทธิภาพการโต้ตอบพื้นฐานในมุมมอง page layout เช่น กรอกข้อมูล ทำงานกับสูตร หรือตั้งค่าขอบกระดาษ Excel 2010 แคชการตั้งค่าเครื่องพิมพ์ และเพิ่มการคำนวณการเรนเดอร์ที่ปรับให้เหมาะสม การแคชลดจำนวนการเรียกเครือข่ายและลดการพึ่งพาเครื่องพิมพ์ที่ช้าหรือไม่ตอบสนอง การเชื่อมต่อเครื่องพิมพ์ยกเลิกได้ ผู้ใช้จึงไม่ต้องรอ |
| **แผนภูมิ (Charts)** | ตั้งแต่ Excel 2010 ความเร็วเรนเดอร์แผนภูมิเพิ่มขึ้น โดยเฉพาะข้อมูลขนาดใหญ่ และการเรนเดอร์ข้อความดีขึ้น Excel 2010 แคชภาพของแผนภูมิและใช้ฉบับแคชเมื่อทำได้ เพื่อหลีกเลี่ยงการคำนวณและเรนเดอร์ที่ไม่จำเป็น |
| **โซลูชัน VBA** | การปรับปรุงออบเจ็กต์โมเดลและวิธีที่โต้ตอบกับ Excel ทำให้โซลูชัน VBA หลายตัวเร็วขึ้นใน Excel 2010 เมื่อเทียบกับ Excel 2007 |

### ชุดข้อมูลขนาดใหญ่และ Excel 64 บิต

Excel 2010 รุ่น 64 บิตไม่ถูกจำกัดที่ RAM 2 GB แบบแอป 32 บิต หรือ 4 GB แบบ 32 บิต LAA จึงสร้างเวิร์กบุ๊กที่ใหญ่กว่ามากได้ Windows 64 บิตรองรับหน่วยความจำที่อ้างอิงได้มากกว่า และ Excel ออกแบบมาใช้ประโยชน์จากสิ่งนี้ เช่น กรอกข้อมูลลงตารางได้มากกว่ารุ่นก่อน เมื่อเพิ่ม RAM Excel ใช้หน่วยความจำส่วนเพิ่มนั้น เวิร์กบุ๊กใหญ่ขึ้นได้เรื่อย ๆ ตามขนาด RAM

เนื่องจากรุ่น 64 บิตรองรับชุดข้อมูลใหญ่ ทั้ง 32 และ 64 บิตของ Excel 2010 จึงปรับปรุงงานที่พบบ่อยกับข้อมูลใหญ่ เช่น การกรอกและเติมข้อมูลลง การเรียง การกรอง การคัดลอกและวาง และปรับการใช้หน่วยความจำให้มีประสิทธิภาพขึ้นในทั้งสองรุ่น

ข้อมูลเพิ่มเติม: [Choose between the 64-bit or 32-bit version of Office](https://support.office.com/article/Choose-between-the-64-bit-or-32-bit-version-of-Office-2dee7807-8f95-4d0c-b5fe-6c6f49b8d261) และ [Compatibility Between the 32-bit and 64-bit Versions of Office 2010](https://learn.microsoft.com/en-us/office/vba/api/overview/excel)

### รูปร่าง (Shapes)

Excel 2010 ปรับปรุงประสิทธิภาพกราฟิกอย่างมาก ในภาพรวมอยู่ใน 2 ด้าน: scalability (การรองรับขนาด) และ rendering (การเรนเดอร์)

การปรับปรุง scalability มีผลมากเพราะเวิร์กชีตมีกราฟิกจำนวนมาก ซึ่งมักเกิดโดยไม่ตั้งใจจากการคัดลอกและวางข้อมูลจากเว็บไซต์ หรือระบบอัตโนมัติที่สร้างรูปร่างแล้วไม่เคยลบ การมีกราฟิกจำนวนมากร่วมกับวิธีที่กราฟิกสัมพันธ์กับตารางข้อมูลใน Excel ก่อปัญหาประสิทธิภาพเฉพาะตัวหลายอย่าง Excel 2010 ปรับปรุงความเร็วของเวิร์กชีตที่มีรูปร่างมาก

ตั้งแต่ Excel 2010 รองรับ hardware acceleration ช่วยการเรนเดอร์ และปรับปรุงประสิทธิภาพ method **Select** ของออบเจ็กต์ **Shape** ในออบเจ็กต์โมเดล VBA

| ฟีเจอร์ | การปรับปรุง |
| :-- | :-- |
| **การใช้งานพื้นฐาน** | ชุดแรกเกี่ยวกับสถานการณ์พื้นฐาน ได้แก่ การเรียง กรอง แทรกหรือปรับขนาดแถว/คอลัมน์ หรือ merge เซลล์ ซึ่งอาจต้องอัปเดตตำแหน่งของกราฟิกบนตาราง กรณีเลวร้ายที่สุดต้องอัปเดตทุกออบเจ็กต์บนชีต ใน Excel 2010 สถานการณ์เหล่านี้เร็วขึ้นแม้มีออบเจ็กต์นับพัน ความสำเร็จมาจากการมุ่งเน้นประสิทธิภาพ ทั้งปรับปรุงกลไกค้นหารูปร่าง ทดสอบไฟล์ความเครียด และตรวจสอบสิ่งกีดขวาง |
| **Text links** | text link บนรูปร่างเกิดเมื่อผู้ใช้ระบุสูตร เช่น "=A1" กำหนดข้อความของรูปร่าง รูปร่างเหล่านี้มักก่อปัญหาประสิทธิภาพเมื่อมีออบเจ็กต์มากและ/หรือเมื่อเนื้อหาเซลล์เปลี่ยน ตั้งแต่ Excel 2010 วิธีติดตามและอัปเดตรูปร่างเหล่านี้ปรับให้เหมาะกับการเปลี่ยนเนื้อหาเซลล์ ช่วยกรณีเช่นพิมพ์ค่าใหม่ในเซลล์ หรือทำงานออบเจ็กต์โมเดลที่ซับซ้อน |
| **Big Grid** | ตั้งแต่ Excel 2007 ตารางขยายจาก 65,000 แถวเป็นกว่าหนึ่งล้านแถว ทำให้เกิดปัญหาประสิทธิภาพและการเรนเดอร์เมื่อทำงานกับกราฟิกในพื้นที่ใหม่ของตาราง ตั้งแต่ Excel 2010 ปรับฟังก์ชันที่ใช้มุมซ้ายบนของตารางเป็นจุดกำเนิดให้ดีขึ้น ความถูกต้องของการเรนเดอร์และประสิทธิภาพดีกว่า Excel 2007 |
| **Rendering: Hardware acceleration** | ตั้งแต่ Excel 2010 ปรับปรุงแพลตฟอร์มกราฟิกด้วยการรองรับ hardware acceleration ตอนเรนเดอร์วัตถุ 3 มิติ แม้ GPU เรนเดอร์ได้เร็วกว่า CPU แต่ประสบการณ์ขึ้นกับเนื้อหาในเวิร์กชีต ชีตที่เต็มไปด้วยรูปร่าง 3 มิติได้ประโยชน์มากกว่าชีตที่มีรูปร่าง 2 มิติ (ซึ่งไม่ใช้ GPU) |

### การปรับปรุงการคำนวณ

ตั้งแต่ Excel 2007 การคำนวณแบบหลายเธรด (multithreaded) ช่วยเพิ่มประสิทธิภาพการคำนวณ

ตั้งแต่ Excel 2010 เพิ่มการปรับปรุงเพื่อเร่งการคำนวณอีก Excel 2010 เรียก **UDF แบบอะซิงโครนัส** ได้ ซึ่งช่วยให้หลายการคำนวณทำงานพร้อมกัน เมื่อรัน UDF บน compute cluster การเรียกแบบอะซิงโครนัสทำให้ใช้หลายเครื่องคำนวณร่วมกันได้ ข้อมูลเพิ่มเติม: Asynchronous User-Defined Functions (<https://learn.microsoft.com/en-us/office/vba/api/overview/excel>)

### การประมวลผลหลายคอร์ (Multi-core processing)

Excel 2010 ลงทุนเพิ่มเพื่อใช้ประโยชน์จากโปรเซสเซอร์หลายคอร์สำหรับงานประจำ ตั้งแต่ Excel 2010 ฟีเจอร์เหล่านี้ใช้หลายคอร์: บันทึกไฟล์ เปิดไฟล์ รีเฟรช PivotTable (สำหรับแหล่งข้อมูลภายนอก ยกเว้น OLAP และ SharePoint) เรียงตารางเซลล์ เรียง PivotTable และปรับความกว้างคอลัมน์อัตโนมัติ

สำหรับงานที่เกี่ยวกับการอ่านและโหลด หรือเขียนข้อมูล เช่น เปิดไฟล์ บันทึกไฟล์ หรือรีเฟรชข้อมูล การแบ่งงานเป็นสองโปรเซสช่วยให้เร็วขึ้น โปรเซสแรกดึงข้อมูล โปรเซสที่สองโหลดข้อมูลเข้าโครงสร้างในหน่วยความจำหรือเขียนลงไฟล์ ทันทีที่โปรเซสแรกเริ่มอ่านข้อมูลส่วนหนึ่ง โปรเซสที่สองก็เริ่มโหลดหรือเขียนส่วนนั้นได้ทันที ขณะที่โปรเซสแรกอ่านส่วนถัดไป เดิมโปรเซสแรกต้องอ่านข้อมูลส่วนหนึ่งให้เสร็จก่อน โปรเซสที่สองจึงโหลดหรือเขียนส่วนนั้นได้

### PowerPivot

PowerPivot คือกลุ่มของแอปพลิเคชันและบริการที่ให้แนวทางแบบครบวงจรในการสร้างโซลูชัน business intelligence ที่ขับเคลื่อนด้วยข้อมูลและจัดการโดยผู้ใช้ในเวิร์กบุ๊ก Excel PowerPivot for Excel เป็นเครื่องมือวิเคราะห์ข้อมูลที่ให้พลังการคำนวณสูงภายใน Excel ใช้ฟีเจอร์ Excel ที่คุ้นเคย ผู้ใช้แปลงข้อมูลปริมาณมากจากแหล่งใดก็ได้เป็นข้อมูลที่มีความหมายได้อย่างรวดเร็ว เพื่อหาคำตอบภายในไม่กี่วินาที

PowerPivot ยังผสานกับ SharePoint ใน SharePoint farm, PowerPivot for SharePoint คือชุดแอปพลิเคชันฝั่งเซิร์ฟเวอร์ บริการ และฟีเจอร์ที่สนับสนุนการทำงานร่วมกันของทีมกับข้อมูล BI ผู้เขียนและเจ้าของเวิร์กบุ๊กเผยแพร่และจัดการ BI ที่พัฒนาไปยังไซต์ SharePoint ของตน

ข้อมูลเพิ่มเติม: PowerPivot Overview (<https://learn.microsoft.com/en-us/office/vba/api/overview/excel>)

### HPC Services for Excel 2010

Excel 2010 มีฟังก์ชันวิเคราะห์เชิงสถิติมากมาย รองรับการสร้างการวิเคราะห์ที่ซับซ้อน และขยายได้กว้างขวาง จึงเป็นเครื่องมือยอดนิยมสำหรับวิเคราะห์ข้อมูลธุรกิจ เมื่อโมเดลใหญ่ขึ้นและเวิร์กบุ๊กซับซ้อนขึ้น คุณค่าของข้อมูลที่ได้ก็สูงขึ้น แต่เวิร์กบุ๊กที่ซับซ้อนต้องใช้เวลาคำนวณมากขึ้น ผู้ใช้มักใช้เวลาหลายชั่วโมง หลายวัน หรือหลายสัปดาห์เพื่อให้เวิร์กบุ๊กเช่นนั้นเสร็จ

ทางออกหนึ่งคือใช้ Windows HPC Server 2008 ขยายการคำนวณ Excel ออกไปยังหลายโหนดใน cluster คอมพิวเตอร์ประสิทธิภาพสูง (HPC) ของ Windows แบบขนาน มีสามวิธีรันการคำนวณ Excel 2010 บน cluster ที่ใช้ Windows HPC Server 2008: รันเวิร์กบุ๊ก Excel ใน cluster, รัน UDF ของ Excel ใน cluster และใช้ Excel เป็น client ของ cluster แบบ service-oriented architecture (SOA)

ข้อมูลเพิ่มเติม: [Accelerating Excel 2010 with Windows HPC Server 2008 R2](https://www.microsoft.com/en-us/download/details.aspx?id=21238)

## 13. สรุปแนวปฏิบัติ

ข้อต่อไปนี้ถอดจากเนื้อหาของบทความ (ผู้แปลสรุป)

1. ใช้ **MAXIFS/MINIFS** แทนสูตรอาร์เรย์ และ **TEXTJOIN/CONCAT** แทน UDF ที่ต่อข้อความ
2. ให้สูตรค้นหา/รวมข้อมูลหลายตัวอ้างช่วงเดียวกัน เพื่อใช้ดัชนีแคชร่วมกัน (SUMIFS ตระกูล, VLOOKUP/HLOOKUP/MATCH แบบตรงทุกตัว)
3. ถ้าต้องใช้ Excel 32 บิต ตรวจว่าเป็นรุ่นที่เปิด LAA ถ้าข้อมูลใหญ่มาก ใช้ 64 บิต
4. ระวังรูปร่าง (shapes) ที่สะสมโดยไม่ตั้งใจ จากการวางข้อมูลจากเว็บหรือมาโครที่สร้างรูปร่างแต่ไม่ลบ
5. UDF แบบอะซิงโครนัสและหลายคอร์ช่วยเร่งการคำนวณและงานอ่าน/เขียนไฟล์
