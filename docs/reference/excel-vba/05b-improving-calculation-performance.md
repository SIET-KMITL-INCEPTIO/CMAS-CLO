"Big Grid" ที่มี 1 ล้านแถวและ 16,000 คอลัมน์ใน Office Excel 2016 พร้อมกับการเพิ่มขีดจำกัดอื่นอีกมาก ทำให้สร้างเวิร์กชีตขนาดใหญ่กว่า Excel รุ่นก่อนได้มาก เวิร์กชีตเดียวใน Excel ปัจจุบันมีเซลล์ได้มากกว่ารุ่นก่อนกว่า 1,000 เท่า

ใน Excel รุ่นก่อน หลายคนสร้างเวิร์กชีตที่คำนวณช้า และเวิร์กชีตใหญ่มักคำนวณช้ากว่าเวิร์กชีตเล็ก เมื่อมี "Big Grid" ใน Excel 2007 ประสิทธิภาพจึงสำคัญจริง ๆ การคำนวณและการจัดการข้อมูลที่ช้า เช่น การเรียงและกรอง ทำให้ผู้ใช้จดจ่อกับงานที่ทำได้ยากขึ้น และการขาดสมาธิเพิ่มข้อผิดพลาด

Excel รุ่นล่าสุดมีฟีเจอร์ช่วยรับมือกับความจุที่เพิ่มขึ้น เช่น ใช้โปรเซสเซอร์มากกว่าหนึ่งตัวพร้อมกันในการคำนวณ และงานกับชุดข้อมูลทั่วไปอย่างรีเฟรช เรียง และเปิดเวิร์กบุ๊ก การคำนวณหลายเธรดช่วยลดเวลาคำนวณได้มาก แต่ปัจจัยสำคัญที่สุดที่กำหนดความเร็วการคำนวณของ Excel ยังคงเป็น **วิธีออกแบบและสร้างเวิร์กชีต**

เวิร์กชีตที่คำนวณช้าส่วนใหญ่ปรับให้คำนวณเร็วขึ้นได้หลายสิบ หลายร้อย หรือหลายพันเท่า ด้วยการระบุ วัดผล แล้วปรับปรุง **สิ่งกีดขวางการคำนวณ (calculation obstructions)** ในเวิร์กชีต

## 1. ความสำคัญของความเร็วการคำนวณ

ความเร็วการคำนวณที่แย่กระทบผลิตภาพและเพิ่มข้อผิดพลาดของผู้ใช้ ผลิตภาพและความสามารถในการจดจ่อกับงานลดลงเมื่อเวลาตอบสนองนานขึ้น

Excel มีโหมดการคำนวณหลักสองโหมดที่ให้ควบคุมว่าเมื่อไรจะคำนวณ:

- **Automatic calculation** — สูตรถูกคำนวณใหม่อัตโนมัติเมื่อมีการเปลี่ยนแปลง
- **Manual calculation** — สูตรถูกคำนวณใหม่เฉพาะเมื่อสั่ง (เช่น กด F9)

| เวลาคำนวณ | ผลต่อผู้ใช้ |
| :-- | :-- |
| น้อยกว่าประมาณ 0.1 วินาที | รู้สึกว่าระบบตอบสนองทันที ใช้ automatic ได้แม้ตอนกรอกข้อมูล |
| 0.1 – 1 วินาที | รักษาแนวคิดต่อเนื่องได้ แม้จะสังเกตเห็นความหน่วง |
| 1 – 10 วินาที (โดยทั่วไป) | ต้องสลับเป็น manual ตอนกรอกข้อมูล ข้อผิดพลาดและความรำคาญเริ่มเพิ่ม โดยเฉพาะงานซ้ำ ๆ และรักษาแนวคิดได้ยาก |
| มากกว่า 10 วินาที | ผู้ใช้หมดความอดทน มักสลับไปทำงานอื่นระหว่างรอ ซึ่งทำให้เกิดปัญหาเมื่อการคำนวณเป็นส่วนหนึ่งของลำดับงานแล้วผู้ใช้ตามไม่ทัน |

## 2. เข้าใจวิธีการคำนวณของ Excel

เพื่อปรับปรุงประสิทธิภาพการคำนวณ ต้องเข้าใจทั้งวิธีการคำนวณที่มีและวิธีควบคุม

### การคำนวณเต็มรูปแบบและ dependency ของการคำนวณใหม่

เอนจิน **smart recalculation** ของ Excel พยายามลดเวลาคำนวณโดยติดตาม **precedents และ dependencies** ของแต่ละสูตร (เซลล์ที่สูตรอ้างอิง) อย่างต่อเนื่อง รวมทั้งการเปลี่ยนแปลงตั้งแต่การคำนวณครั้งล่าสุด เมื่อคำนวณใหม่ครั้งถัดไป Excel คำนวณเฉพาะ:

- เซลล์ สูตร ค่า หรือชื่อที่เปลี่ยนไป หรือถูกตั้งธงว่าต้องคำนวณใหม่
- เซลล์ที่ขึ้นกับเซลล์ สูตร ชื่อ หรือค่าอื่นที่ต้องคำนวณใหม่
- ฟังก์ชัน volatile และ conditional format ที่มองเห็นอยู่

Excel คำนวณเซลล์ที่ขึ้นกับเซลล์ที่คำนวณก่อนหน้าต่อไป แม้ค่าของเซลล์ที่คำนวณก่อนหน้าจะไม่เปลี่ยนเมื่อคำนวณ

เพราะส่วนใหญ่ระหว่างการคำนวณแต่ละครั้งเปลี่ยนเพียงบางส่วนของข้อมูลนำเข้าหรือไม่กี่สูตร smart recalculation จึงมักใช้เวลาเพียงเศษเสี้ยวของการคำนวณทุกสูตรเต็มรูปแบบ

ในโหมด manual สั่ง smart recalculation ได้ด้วย **F9** บังคับคำนวณทุกสูตรเต็มรูปแบบด้วย **Ctrl+Alt+F9** หรือบังคับสร้าง dependency ใหม่ทั้งหมดและคำนวณเต็มรูปแบบด้วย **Shift+Ctrl+Alt+F9**

### กระบวนการคำนวณ

สูตร Excel ที่อ้างอิงเซลล์อื่นวางก่อนหรือหลังเซลล์ที่อ้างอิงก็ได้ (forward / backward referencing) เพราะ Excel ไม่คำนวณตามลำดับตายตัว หรือทีละแถว/คอลัมน์ แต่กำหนดลำดับการคำนวณแบบไดนามิก จากรายการของสูตรทั้งหมดที่ต้องคำนวณ (**calculation chain**) และข้อมูล dependency ของแต่ละสูตร

Excel มีช่วงการคำนวณที่แยกกัน:

1. สร้าง calculation chain เริ่มต้นและกำหนดจุดเริ่มคำนวณ ช่วงนี้เกิดเมื่อโหลดเวิร์กบุ๊กเข้าหน่วยความจำ
2. ติดตาม dependency ตั้งธงเซลล์ว่ายังไม่คำนวณ และอัปเดต calculation chain ช่วงนี้ทำงานทุกครั้งที่กรอกหรือเปลี่ยนเซลล์ แม้ในโหมด manual ปกติเร็วจนไม่รู้สึก แต่ในกรณีซับซ้อนอาจตอบสนองช้า
3. คำนวณทุกสูตร ระหว่างนี้ Excel จัดลำดับและโครงสร้าง calculation chain ใหม่เพื่อเพิ่มประสิทธิภาพการคำนวณครั้งถัดไป
4. อัปเดตส่วนที่มองเห็นของหน้าต่าง Excel

ช่วงที่สามทำงานทุกครั้งที่คำนวณหรือคำนวณใหม่ Excel พยายามคำนวณแต่ละสูตรใน chain ตามลำดับ แต่ถ้าสูตรขึ้นกับสูตรอื่นที่ยังไม่ได้คำนวณ สูตรนั้นจะถูกส่งไปท้าย chain เพื่อคำนวณใหม่ภายหลัง ซึ่งแปลว่าสูตรหนึ่งอาจถูกคำนวณหลายครั้งต่อการคำนวณใหม่หนึ่งรอบ

การคำนวณเวิร์กบุ๊กครั้งที่สองมักเร็วกว่าครั้งแรกมาก ด้วยหลายสาเหตุ:

- Excel มักคำนวณใหม่เฉพาะเซลล์ที่เปลี่ยนและเซลล์ที่ขึ้นกับมัน
- Excel เก็บและใช้ซ้ำลำดับการคำนวณล่าสุด จึงประหยัดเวลาส่วนใหญ่ที่ใช้กำหนดลำดับ
- บนคอมพิวเตอร์หลายคอร์ Excel พยายามปรับวิธีกระจายการคำนวณไปยังคอร์ตามผลของการคำนวณก่อนหน้า
- ในเซสชัน Excel ทั้ง Windows และ Excel แคชข้อมูลและโปรแกรมที่ใช้ล่าสุดไว้เข้าถึงเร็วขึ้น

## 3. คำนวณเวิร์กบุ๊ก เวิร์กชีต และช่วงข้อมูล

ควบคุมสิ่งที่ถูกคำนวณได้ด้วยวิธีคำนวณต่าง ๆ ของ Excel

### คำนวณเวิร์กบุ๊กที่เปิดอยู่ทั้งหมด

การคำนวณใหม่และการคำนวณเต็มรูปแบบทุกครั้งคำนวณเวิร์กบุ๊กทั้งหมดที่เปิดอยู่ แก้ dependency ภายในและระหว่างเวิร์กบุ๊กและเวิร์กชีต และรีเซ็ตเซลล์ที่ยังไม่ได้คำนวณ (dirty) ทั้งหมดเป็นคำนวณแล้ว

### คำนวณเวิร์กชีตที่เลือก

คำนวณใหม่เฉพาะเวิร์กชีตที่เลือกด้วย **Shift+F9** ซึ่งแก้ dependency ของเวิร์กชีตและรีเซ็ตเซลล์ dirty ทั้งหมดเป็นคำนวณแล้ว

ใน Excel รุ่นก่อน พฤติกรรมต่างออกไป เซลล์ dirty ไม่ถูกตั้งเป็นคำนวณแล้วหลังการคำนวณเสร็จ ถ้า UDF พึ่งพฤติกรรมนี้ ควรทำให้ฟังก์ชันเหล่านั้นเป็น volatile แทน ตามหัวข้อ "ฟังก์ชัน volatile" ด้านล่าง

### คำนวณช่วงของเซลล์

Excel คำนวณช่วงของเซลล์ได้ด้วย method VBA **Range.CalculateRowMajorOrder** และ **Range.Calculate**:

- **Range.CalculateRowMajorOrder** คำนวณช่วงจากซ้ายไปขวา บนลงล่าง โดย **ไม่สนใจ dependency ทั้งหมด**
- **Range.Calculate** คำนวณช่วงโดย **แก้ dependency ทั้งหมดภายในช่วง**

เนื่องจาก `CalculateRowMajorOrder` ไม่แก้ dependency ภายในช่วงที่คำนวณ จึงมักเร็วกว่า `Range.Calculate` มาก แต่ใช้ด้วยความระวัง เพราะอาจให้ผลไม่เหมือน `Range.Calculate`

`Range.Calculate` เป็นเครื่องมือที่มีประโยชน์ที่สุดอย่างหนึ่งของ Excel สำหรับการเพิ่มประสิทธิภาพ เพราะใช้จับเวลาและเปรียบเทียบความเร็วการคำนวณของสูตรต่าง ๆ ได้

ดูเพิ่มเติม: [Excel performance: Performance and limit improvements](05a-performance-and-limit-improvements.md)

### ฟังก์ชัน Volatile

ฟังก์ชัน volatile ถูกคำนวณใหม่ทุกครั้งที่คำนวณใหม่ แม้จะดูเหมือนไม่มี precedent ที่เปลี่ยน การใช้ฟังก์ชัน volatile จำนวนมากทำให้การคำนวณใหม่แต่ละรอบช้าลง แต่ไม่มีผลต่อการคำนวณเต็มรูปแบบ ทำให้ UDF เป็น volatile ได้ด้วยการใส่ **Application.Volatile** ในโค้ดของฟังก์ชัน

- ฟังก์ชันในตัวที่ volatile ชัดเจน: **RAND(), NOW(), TODAY()**
- ที่ volatile ไม่ชัดเจนนัก: **OFFSET(), CELL(), INDIRECT(), INFO()**
- ฟังก์ชันที่เคยมีเอกสารว่า volatile แต่ **ไม่ใช่**: **INDEX(), ROWS(), COLUMNS(), AREAS()**

### การกระทำที่ทำให้เกิด volatile (Volatile actions)

การกระทำที่กระตุ้นการคำนวณใหม่ ได้แก่:

- คลิกตัวแบ่งแถวหรือคอลัมน์ในโหมด automatic
- แทรกหรือลบแถว คอลัมน์ หรือเซลล์บนชีต
- เพิ่ม เปลี่ยน หรือลบ defined name
- เปลี่ยนชื่อเวิร์กชีตหรือย้ายตำแหน่งเวิร์กชีตในโหมด automatic
- กรอง ซ่อน หรือแสดงแถว
- เปิดเวิร์กบุ๊กในโหมด automatic ถ้าเวิร์กบุ๊กถูกคำนวณครั้งล่าสุดโดย Excel คนละเวอร์ชัน การเปิดมักทำให้เกิดการคำนวณเต็มรูปแบบ
- บันทึกเวิร์กบุ๊กในโหมด manual ถ้าเลือกตัวเลือก **Calculate before Save**

### สถานการณ์ที่สูตรและชื่อถูกประเมินค่า

สูตรหรือส่วนของสูตรถูกประเมิน (คำนวณ) ทันที แม้ในโหมด manual เมื่อ:

- กรอกหรือแก้ไขสูตร
- กรอกหรือแก้ไขสูตรด้วย Function Wizard
- กรอกสูตรเป็นอาร์กิวเมนต์ใน Function Wizard
- เลือกสูตรใน formula bar แล้วกด F9 (กด Esc เพื่อเลิกทำและกลับเป็นสูตร) หรือคลิก **Evaluate Formula**

สูตรถูกตั้งธงว่ายังไม่คำนวณ เมื่ออ้างอิงถึง (ขึ้นกับ) เซลล์หรือสูตรที่มีเงื่อนไขอย่างใดอย่างหนึ่งต่อไปนี้:

- ถูกกรอก
- ถูกเปลี่ยน
- อยู่ในรายการ AutoFilter และเปิดรายการเงื่อนไขแบบดรอปดาวน์
- ถูกตั้งธงว่ายังไม่คำนวณ

สูตรที่ถูกตั้งธงว่ายังไม่คำนวณ จะถูกประเมินเมื่อเวิร์กชีต เวิร์กบุ๊ก หรืออินสแตนซ์ Excel ที่มีมันถูกคำนวณหรือคำนวณใหม่

สถานการณ์ที่ทำให้ **defined name** ถูกประเมินต่างจากสูตรในเซลล์:

- defined name ถูกประเมินทุกครั้งที่สูตรที่อ้างถึงมันถูกประเมิน ดังนั้นการใช้ชื่อเดียวในหลายสูตรอาจทำให้ชื่อถูกประเมินหลายครั้ง
- ชื่อที่ไม่มีสูตรใดอ้างถึง จะไม่ถูกคำนวณแม้ในการคำนวณเต็มรูปแบบ

### Data Tables

Excel data tables (แท็บ **Data** > กลุ่ม **Data Tools** > **What-If Analysis** > **Data Table**) ต้องไม่สับสนกับฟีเจอร์ table (แท็บ **Home** > กลุ่ม **Styles** > **Format as Table** หรือแท็บ **Insert** > กลุ่ม **Tables** > **Table**) data table ของ Excel คำนวณเวิร์กบุ๊กใหม่หลายครั้ง แต่ละครั้งขับเคลื่อนด้วยค่าต่างกันในตาราง Excel คำนวณเวิร์กบุ๊กตามปกติก่อน จากนั้นสำหรับแต่ละคู่ค่าแถวและคอลัมน์ จะแทนค่า คำนวณใหม่แบบเธรดเดียว และเก็บผลลงใน data table

*การคำนวณใหม่ของ data table ใช้โปรเซสเซอร์เพียงตัวเดียวเสมอ*

data table เป็นวิธีสะดวกในการคำนวณหลายรูปแบบและดูเปรียบเทียบผลลัพธ์ ใช้ตัวเลือก **Automatic except Tables** เพื่อไม่ให้ Excel กระตุ้นการคำนวณหลายครั้งโดยอัตโนมัติทุกครั้ง แต่ยังคำนวณสูตรที่ขึ้นกับทั้งหมดยกเว้นตาราง

## 4. ควบคุมตัวเลือกการคำนวณ

Excel มีตัวเลือกมากมายให้ควบคุมวิธีคำนวณ เปลี่ยนตัวเลือกที่ใช้บ่อยได้ที่กลุ่ม **Calculation** บนแท็บ **Formulas** ของ Ribbon (*รูปที่ 1 ดูที่หน้าต้นฉบับ*)

ดูตัวเลือกเพิ่ม: แท็บ **File** > **Options** > กล่องโต้ตอบ **Excel Options** > แท็บ **Formulas** (*รูปที่ 2*)

ตัวเลือกการคำนวณหลายตัว (**Automatic, Automatic except for data tables, Manual, Recalculate workbook before saving**) และการตั้งค่า iteration (**Enable iterative calculation, Maximum Iterations, Maximum Change**) ทำงานที่ **ระดับแอปพลิเคชัน** ไม่ใช่ระดับเวิร์กบุ๊ก (เหมือนกันสำหรับทุกเวิร์กบุ๊กที่เปิดอยู่)

ตัวเลือกขั้นสูง: **File** > **Options** > **Advanced** ใต้ส่วน **Formulas** (*รูปที่ 3*)

เมื่อเริ่ม Excel หรือเมื่อ Excel ทำงานโดยไม่มีเวิร์กบุ๊กเปิดอยู่ โหมดการคำนวณเริ่มต้นและการตั้งค่า iteration ถูกกำหนดจาก **เวิร์กบุ๊กแรกที่เปิดซึ่งไม่ใช่เทมเพลตและไม่ใช่ add-in** แปลว่าการตั้งค่าการคำนวณในเวิร์กบุ๊กที่เปิดทีหลังจะถูกเพิกเฉย แต่แน่นอนว่าเปลี่ยนการตั้งค่าใน Excel เองได้ทุกเมื่อ เมื่อบันทึกเวิร์กบุ๊ก การตั้งค่าการคำนวณปัจจุบันจะถูกเก็บในเวิร์กบุ๊ก

### Automatic calculation

โหมด automatic หมายถึง Excel คำนวณเวิร์กบุ๊กที่เปิดอยู่ทั้งหมดใหม่โดยอัตโนมัติทุกครั้งที่มีการเปลี่ยนแปลงและเมื่อเปิดเวิร์กบุ๊ก ปกติเมื่อเปิดเวิร์กบุ๊กในโหมด automatic แล้ว Excel คำนวณใหม่ คุณไม่เห็นการคำนวณ เพราะไม่มีอะไรเปลี่ยนตั้งแต่บันทึกเวิร์กบุ๊ก

คุณอาจสังเกตเห็นการคำนวณเมื่อเปิดเวิร์กบุ๊กใน Excel รุ่นใหม่กว่ารุ่นที่คำนวณเวิร์กบุ๊กครั้งล่าสุด (เช่น Excel 2016 เทียบกับ Excel 2013) เพราะเอนจินคำนวณต่างกัน Excel จึงคำนวณเต็มรูปแบบเมื่อเปิดเวิร์กบุ๊กที่บันทึกด้วยรุ่นก่อน

### Manual calculation

โหมด manual หมายถึง Excel คำนวณเวิร์กบุ๊กที่เปิดอยู่ทั้งหมดใหม่เฉพาะเมื่อสั่งด้วย F9 หรือ Ctrl+Alt+F9 หรือเมื่อบันทึกเวิร์กบุ๊ก สำหรับเวิร์กบุ๊กที่ใช้เวลาคำนวณใหม่นานกว่าเศษเสี้ยววินาที ต้องตั้งเป็นโหมด manual เพื่อไม่ให้หน่วงเมื่อแก้ไข

Excel แจ้งเมื่อเวิร์กบุ๊กในโหมด manual ต้องคำนวณใหม่ โดยแสดง **Calculate** ในแถบสถานะ แถบสถานะยังแสดง **Calculate** ถ้าเวิร์กบุ๊กมี circular reference และเลือกตัวเลือก iteration ไว้

### การตั้งค่า Iteration

ถ้าเวิร์กบุ๊กมี circular reference ที่ตั้งใจ การตั้งค่า iteration ให้ควบคุมจำนวนครั้งสูงสุดที่เวิร์กบุ๊กถูกคำนวณใหม่ (iterations) และเกณฑ์การลู่เข้า (maximum change: เมื่อไรหยุด) **ยกเลิกเลือกกล่อง iteration** เพื่อว่าเมื่อมี circular reference โดยไม่ตั้งใจ Excel จะเตือนและไม่พยายามแก้

### คุณสมบัติ ForceFullCalculation ของ Workbook

เมื่อตั้ง property ของเวิร์กบุ๊กนี้เป็น True Smart Recalculation ของ Excel จะถูกปิด และทุกการคำนวณใหม่จะคำนวณทุกสูตรในทุกเวิร์กบุ๊กที่เปิดอยู่ สำหรับเวิร์กบุ๊กซับซ้อนบางตัว เวลาที่ใช้สร้างและดูแล dependency tree ที่ Smart Recalculation ต้องใช้ มากกว่าเวลาที่ Smart Recalculation ประหยัดได้

ถ้าเวิร์กบุ๊กใช้เวลาเปิดนานผิดปกติ หรือการแก้ไขเล็กน้อยใช้เวลานานแม้ในโหมด manual อาจลองใช้ ForceFullCalculation

**Calculate** จะปรากฏในแถบสถานะถ้าตั้ง property **ForceFullCalculation** ของเวิร์กบุ๊กเป็น True

ควบคุมการตั้งค่านี้ผ่าน **VBE** (Alt+F11) เลือก **ThisWorkbook** ใน **Project Explorer** (Ctrl+R) และแสดง **Properties Window** (F4) (*รูปที่ 4*)

## 5. ทำให้เวิร์กบุ๊กคำนวณเร็วขึ้น

### ความเร็วโปรเซสเซอร์และหลายคอร์

สำหรับ Excel ส่วนใหญ่ โปรเซสเซอร์ที่เร็วกว่าย่อมทำให้คำนวณเร็วขึ้น เอนจินคำนวณหลายเธรดที่เริ่มใน Excel 2007 ทำให้ Excel ใช้ระบบหลายโปรเซสเซอร์ได้ดีมาก และคาดหวังประสิทธิภาพที่เพิ่มขึ้นชัดเจนกับเวิร์กบุ๊กส่วนใหญ่

สำหรับเวิร์กบุ๊กขนาดใหญ่ส่วนใหญ่ ประสิทธิภาพการคำนวณที่เพิ่มจากหลายโปรเซสเซอร์ขยายตัวเกือบเป็นเส้นตรงตามจำนวนโปรเซสเซอร์จริง (physical) แต่ hyper-threading ของโปรเซสเซอร์จริงให้ประสิทธิภาพเพิ่มเพียงเล็กน้อย

ดูเพิ่มเติม: [Performance and limit improvements](05a-performance-and-limit-improvements.md)

### RAM

การ paging ไปยังไฟล์หน่วยความจำเสมือนช้า ต้องมี RAM จริงเพียงพอสำหรับระบบปฏิบัติการ Excel และเวิร์กบุ๊ก ถ้ามีการใช้ฮาร์ดดิสก์ระหว่างคำนวณบ่อยกว่าเป็นครั้งคราว และไม่ได้รัน UDF ที่กระตุ้นการใช้ดิสก์ แปลว่าต้องการ RAM เพิ่ม

Excel รุ่นล่าสุดใช้หน่วยความจำปริมาณมากได้อย่างมีประสิทธิภาพ Excel 2007 และ 2010 รุ่น 32 บิตจัดการเวิร์กบุ๊กเดี่ยวหรือหลายเวิร์กบุ๊กรวมกันที่ใช้หน่วยความจำได้ถึง 2 GB

Excel 2013 และ 2016 รุ่น 32 บิตที่ใช้ฟีเจอร์ Large Address Aware (LAA) ใช้หน่วยความจำได้ถึง 3 หรือ 4 GB ขึ้นกับเวอร์ชัน Windows ที่ติดตั้ง Excel รุ่น 64 บิตจัดการเวิร์กบุ๊กที่ใหญ่กว่าได้ ข้อมูลเพิ่มเติม: หัวข้อ "Large data sets, LAA, and 64-bit Excel" ใน [Performance and limit improvements](05a-performance-and-limit-improvements.md)

**แนวทางคร่าว ๆ** เพื่อการคำนวณที่มีประสิทธิภาพ: มี RAM พอเก็บชุดเวิร์กบุ๊กที่ใหญ่ที่สุดที่ต้องเปิดพร้อมกัน บวก 1–2 GB สำหรับ Excel และระบบปฏิบัติการ บวก RAM เพิ่มสำหรับแอปอื่นที่รันอยู่

## 6. วัดเวลาการคำนวณ

เพื่อทำให้เวิร์กบุ๊กคำนวณเร็วขึ้น ต้องวัดเวลาคำนวณได้แม่นยำ ต้องมีตัวจับเวลาที่เร็วและแม่นยำกว่าฟังก์ชัน **Time** ของ VBA ฟังก์ชัน **MICROTIMER()** ในโค้ดด้านล่างใช้การเรียก Windows API ไปยังตัวจับเวลาความละเอียดสูงของระบบ วัดช่วงเวลาได้ละเอียดระดับไมโครวินาที

ข้อควรรู้: Windows เป็นระบบปฏิบัติการหลายงาน และการคำนวณครั้งที่สองอาจเร็วกว่าครั้งแรก เวลาที่ได้จึงมักไม่ซ้ำกันเป๊ะ เพื่อความแม่นยำสูงสุด **วัดงานคำนวณหลายครั้งแล้วเฉลี่ยผล**

ดูข้อมูลว่า Visual Basic Editor ส่งผลต่อประสิทธิภาพ UDF ของ VBA อย่างไร ที่หัวข้อ "Faster VBA user-defined functions" ใน [Tips for optimizing performance obstructions](05c-tips-for-optimizing-performance-obstructions.md)

```vb
#If VBA7 Then
    Private Declare PtrSafe Function getFrequency Lib "kernel32" Alias _
        "QueryPerformanceFrequency" (cyFrequency As Currency) As Long
    Private Declare PtrSafe Function getTickCount Lib "kernel32" Alias _
        "QueryPerformanceCounter" (cyTickCount As Currency) As Long
#Else
    Private Declare Function getFrequency Lib "kernel32" Alias _
        "QueryPerformanceFrequency" (cyFrequency As Currency) As Long
    Private Declare Function getTickCount Lib "kernel32" Alias _
        "QueryPerformanceCounter" (cyTickCount As Currency) As Long
#End If
Function MicroTimer() As Double
'
' คืนค่าเป็นวินาที
    Dim cyTicks1 As Currency
    Static cyFrequency As Currency
    '
    MicroTimer = 0
' หาความถี่
    If cyFrequency = 0 Then getFrequency cyFrequency
' หาจำนวน tick
    getTickCount cyTicks1
' เป็นวินาที
    If cyFrequency Then MicroTimer = cyTicks1 / cyFrequency
End Function
```

วัดเวลาการคำนวณโดยเรียก method การคำนวณที่เหมาะสม โพรซีเดอร์ต่อไปนี้ให้เวลาคำนวณของช่วงข้อมูล เวลาคำนวณใหม่ของชีตหรือเวิร์กบุ๊กที่เปิดอยู่ทั้งหมด หรือเวลาคำนวณเต็มรูปแบบของเวิร์กบุ๊กที่เปิดอยู่ทั้งหมด

คัดลอกโพรซีเดอร์และฟังก์ชันทั้งหมดลงในโมดูล VBA มาตรฐาน เปิดตัวแก้ไข VBA ด้วย Alt+F11 ที่เมนู **Insert** เลือก **Module** แล้ววางโค้ด

```vb
Sub RangeTimer()
    DoCalcTimer 1
End Sub
Sub SheetTimer()
    DoCalcTimer 2
End Sub
Sub RecalcTimer()
    DoCalcTimer 3
End Sub
Sub FullcalcTimer()
    DoCalcTimer 4
End Sub
Sub DoCalcTimer(jMethod As Long)
    Dim dTime As Double
    Dim dOvhd As Double
    Dim oRng As Range
    Dim oCell As Range
    Dim oArrRange As Range
    Dim sCalcType As String
    Dim lCalcSave As Long
    Dim bIterSave As Boolean
    '
    On Error GoTo Errhandl
' เริ่มต้น
    dTime = MicroTimer
    ' บันทึกการตั้งค่าการคำนวณ
    lCalcSave = Application.Calculation
    bIterSave = Application.Iteration
    If Application.Calculation <> xlCalculationManual Then
        Application.Calculation = xlCalculationManual
    End If
    Select Case jMethod
    Case 1
        ' ปิด iteration
        If Application.Iteration <> False Then
            Application.Iteration = False
        End if
        ' ขอบเขตสูงสุดคือ used range
        If Selection.Count > 1000 Then
            Set oRng = Intersect(Selection, Selection.Parent.UsedRange)
        Else
            Set oRng = Selection
        End If
        ' รวมเซลล์ array ที่อยู่นอกส่วนที่เลือก
        For Each oCell In oRng
            If oCell.HasArray Then
                If oArrRange Is Nothing Then
                    Set oArrRange = oCell.CurrentArray
                End If
                If Intersect(oCell, oArrRange) Is Nothing Then
                    Set oArrRange = oCell.CurrentArray
                    Set oRng = Union(oRng, oArrRange)
                End If
            End If
        Next oCell
        sCalcType = "Calculate " & CStr(oRng.Count) & _
            " Cell(s) in Selected Range: "
    Case 2
        sCalcType = "Recalculate Sheet " & ActiveSheet.Name & ": "
    Case 3
        sCalcType = "Recalculate open workbooks: "
    Case 4
        sCalcType = "Full Calculate open workbooks: "
    End Select
' ดึงเวลาเริ่มต้น
    dTime = MicroTimer
    Select Case jMethod
    Case 1
        If Val(Application.Version) >= 12 Then
            oRng.CalculateRowMajorOrder
        Else
            oRng.Calculate
        End If
    Case 2
        ActiveSheet.Calculate
    Case 3
        Application.Calculate
    Case 4
        Application.CalculateFull
    End Select
' คำนวณระยะเวลา
    dTime = MicroTimer - dTime
    On Error GoTo 0
    dTime = Round(dTime, 5)
    MsgBox sCalcType & " " & CStr(dTime) & " Seconds", _
        vbOKOnly + vbInformation, "CalcTimer"
Finish:
    ' คืนค่าการตั้งค่าการคำนวณ
    If Application.Calculation <> lCalcSave Then
         Application.Calculation = lCalcSave
    End If
    If Application.Iteration <> bIterSave Then
         Application.Iteration = bIterSave
    End If
    Exit Sub
Errhandl:
    On Error GoTo 0
    MsgBox "Unable to Calculate " & sCalcType, _
        vbOKOnly + vbCritical, "CalcTimer"
    GoTo Finish
End Sub
```

รันโพรซีเดอร์ใน Excel โดยกด Alt+F8 เลือกโพรซีเดอร์ที่ต้องการ แล้วคลิก **Run** (*รูปที่ 5: หน้าต่าง Macro ที่แสดงตัวจับเวลา ดูที่หน้าต้นฉบับ*)

**สรุปตัวจับเวลา 4 ตัว:**

| มาโคร | ค่า jMethod | วัดอะไร |
| :-- | :-- | :-- |
| `RangeTimer` | 1 | คำนวณช่วงที่เลือก (ใช้ `CalculateRowMajorOrder` ใน Excel 2007+) |
| `SheetTimer` | 2 | คำนวณใหม่ชีตที่ active |
| `RecalcTimer` | 3 | คำนวณใหม่เวิร์กบุ๊กที่เปิดทั้งหมด (`Application.Calculate`) |
| `FullcalcTimer` | 4 | คำนวณเต็มรูปแบบทั้งหมด (`Application.CalculateFull`) |

## 7. ค้นหาและจัดลำดับสิ่งกีดขวางการคำนวณ

เวิร์กบุ๊กที่คำนวณช้าส่วนใหญ่มีเพียงไม่กี่จุดปัญหาหรือสิ่งกีดขวางที่กินเวลาคำนวณเกือบทั้งหมด ถ้ายังไม่รู้ว่าอยู่ที่ไหน ให้ใช้วิธี drill-down ด้านล่าง ถ้ารู้แล้ว ให้วัดเวลาที่แต่ละจุดใช้เพื่อจัดลำดับความสำคัญของงานแก้ไข

### วิธี Drill-down

เริ่มจากจับเวลาการคำนวณของเวิร์กบุ๊ก ของแต่ละเวิร์กชีต และของบล็อกสูตรบนชีตที่ช้า ทำตามลำดับและจดเวลาคำนวณ

**ขั้นตอนค้นหาสิ่งกีดขวางด้วย drill-down:**

1. ตรวจว่ามีเวิร์กบุ๊กเปิดอยู่เพียงเล่มเดียว และไม่มีงานอื่นรันอยู่
2. ตั้งการคำนวณเป็น manual
3. ทำสำเนาสำรองของเวิร์กบุ๊ก
4. เปิดเวิร์กบุ๊กที่มีมาโคร Calculation Timers หรือเพิ่มมาโครเหล่านั้นลงในเวิร์กบุ๊ก
5. ตรวจ used range โดยกด Ctrl+End ในแต่ละเวิร์กชีตตามลำดับ
   ซึ่งแสดงตำแหน่งเซลล์สุดท้ายที่ใช้ ถ้าเลยจากที่คาดไว้ พิจารณาลบคอลัมน์และแถวส่วนเกินแล้วบันทึกเวิร์กบุ๊ก ดูหัวข้อ "Minimizing the used range" ใน [Tips for optimizing performance obstructions](05c-tips-for-optimizing-performance-obstructions.md)
6. รันมาโคร **FullCalcTimer**
   เวลาคำนวณสูตรทั้งหมดในเวิร์กบุ๊กมักเป็นเวลากรณีเลวร้ายที่สุด
7. รันมาโคร **RecalcTimer**
   การคำนวณใหม่ทันทีหลังคำนวณเต็มรูปแบบมักให้เวลากรณีดีที่สุด
8. คำนวณ **workbook volatility** เป็นอัตราส่วนของเวลาคำนวณใหม่ต่อเวลาคำนวณเต็มรูปแบบ
   วัดว่าสูตร volatile และการประเมิน calculation chain เป็นสิ่งกีดขวางมากน้อยเพียงใด
9. activate แต่ละชีตแล้วรันมาโคร **SheetTimer** ตามลำดับ
   เพราะเพิ่งคำนวณเวิร์กบุ๊กใหม่ จึงได้เวลาคำนวณใหม่ของแต่ละเวิร์กชีต ซึ่งช่วยระบุเวิร์กชีตที่เป็นปัญหา
10. รันมาโคร **RangeTimer** กับบล็อกสูตรที่เลือก
11. สำหรับแต่ละเวิร์กชีตที่เป็นปัญหา แบ่งคอลัมน์หรือแถวเป็นบล็อกจำนวนน้อย
12. เลือกแต่ละบล็อกตามลำดับ แล้วรัน **RangeTimer** กับบล็อกนั้น
13. ถ้าจำเป็น drill-down ต่อโดยแบ่งแต่ละบล็อกเป็นบล็อกย่อยจำนวนน้อย
14. จัดลำดับความสำคัญของสิ่งกีดขวาง

## 8. เร่งการคำนวณและลดสิ่งกีดขวาง: 4 กฎ

สิ่งที่กินเวลาคำนวณไม่ใช่จำนวนสูตรหรือขนาดเวิร์กบุ๊ก แต่คือ **จำนวนการอ้างอิงเซลล์และการดำเนินการคำนวณ** และประสิทธิภาพของฟังก์ชันที่ใช้

เพราะเวิร์กชีตส่วนใหญ่สร้างโดยคัดลอกสูตรที่ผสมการอ้างอิงแบบสัมบูรณ์และสัมพัทธ์ จึงมักมีสูตรจำนวนมากที่คำนวณและอ้างอิงซ้ำหรือซ้อนกัน

หลีกเลี่ยง **mega-formula และสูตรอาร์เรย์ที่ซับซ้อน** โดยทั่วไปดีกว่าที่จะมีแถวและคอลัมน์มากขึ้นแต่การคำนวณซับซ้อนน้อยลง ซึ่งทำให้ทั้ง smart recalculation และการคำนวณหลายเธรดของ Excel มีโอกาสปรับปรุงการคำนวณมากขึ้น และเข้าใจกับดีบักง่ายขึ้นด้วย

### กฎข้อที่ 1: กำจัดการคำนวณที่ซ้ำ ซ้ำซ้อน และไม่จำเป็น

มองหาการคำนวณที่ซ้ำ ซ้ำซ้อน และไม่จำเป็น ประมาณว่า Excel ต้องใช้การอ้างอิงเซลล์และการคำนวณกี่ครั้งเพื่อได้ผลของสิ่งกีดขวางนั้น คิดว่าจะได้ผลเดียวกันด้วยการอ้างอิงและการคำนวณน้อยลงได้อย่างไร

มักประกอบด้วยขั้นตอนหนึ่งหรือหลายข้อต่อไปนี้:

- ลดจำนวนการอ้างอิงในแต่ละสูตร
- ย้ายการคำนวณที่ซ้ำไปไว้ในเซลล์ช่วย (helper cell) หนึ่งเซลล์หรือมากกว่า แล้วให้สูตรเดิมอ้างอิงเซลล์ช่วย
- ใช้แถวและคอลัมน์เพิ่มเติมเพื่อคำนวณและเก็บผลลัพธ์ระหว่างทางครั้งเดียว แล้วใช้ซ้ำในสูตรอื่น

### กฎข้อที่ 2: ใช้ฟังก์ชันที่มีประสิทธิภาพที่สุดเท่าที่ทำได้

เมื่อพบสิ่งกีดขวางที่เกี่ยวกับฟังก์ชันหรือสูตรอาร์เรย์ ให้พิจารณาว่ามีวิธีที่มีประสิทธิภาพกว่าเพื่อให้ได้ผลเดียวกันหรือไม่ เช่น:

- การค้นหา (lookup) บนข้อมูลที่เรียงลำดับแล้ว มีประสิทธิภาพกว่าข้อมูลที่ไม่เรียงได้หลายสิบหรือหลายร้อยเท่า
- UDF ของ VBA มักช้ากว่าฟังก์ชันในตัวของ Excel (แม้ฟังก์ชัน VBA ที่เขียนอย่างระมัดระวังจะเร็วได้)
- ลดจำนวนเซลล์ที่ใช้ในฟังก์ชันเช่น **SUM** และ **SUMIF** เวลาคำนวณเป็นสัดส่วนกับจำนวนเซลล์ที่ใช้ (เซลล์ที่ไม่ได้ใช้ถูกข้าม)
- พิจารณาแทนที่สูตรอาร์เรย์ที่ช้าด้วย UDF

### กฎข้อที่ 3: ใช้ smart recalculation และการคำนวณหลายเธรดให้เกิดประโยชน์

ยิ่งใช้ smart recalculation และการคำนวณหลายเธรดได้ดี การประมวลผลที่ต้องทำทุกครั้งที่ Excel คำนวณใหม่ก็ยิ่งน้อย ดังนั้น:

- หลีกเลี่ยงฟังก์ชัน volatile เช่น **INDIRECT** และ **OFFSET** เท่าที่ทำได้ เว้นแต่จะมีประสิทธิภาพกว่าทางเลือกอื่นอย่างชัดเจน (การใช้ **OFFSET** ที่ออกแบบดีมักเร็ว)
- ลดขนาดช่วงที่ใช้ในสูตรอาร์เรย์และฟังก์ชัน
- แยกสูตรอาร์เรย์และ mega-formula ออกเป็นคอลัมน์และแถวช่วยแยกกัน
- **หลีกเลี่ยงฟังก์ชันแบบเธรดเดียว (single-threaded):**
  - PHONETIC
  - CELL เมื่อใช้อาร์กิวเมนต์ "format" หรือ "address"
  - INDIRECT
  - GETPIVOTDATA
  - CUBEMEMBER, CUBEVALUE, CUBEMEMBERPROPERTY, CUBESET, CUBERANKEDMEMBER, CUBEKPIMEMBER, CUBESETCOUNT
  - ADDRESS เมื่อระบุพารามิเตอร์ที่ห้า (sheet_name)
  - ฟังก์ชันฐานข้อมูลใด ๆ (DSUM, DAVERAGE ฯลฯ) ที่อ้างถึง PivotTable
  - ERROR.TYPE
  - HYPERLINK
  - UDF ของ VBA และ COM add-in
- หลีกเลี่ยงการใช้ data table แบบ iterative และ circular reference: ทั้งสองคำนวณเธรดเดียวเสมอ

### กฎข้อที่ 4: จับเวลาและทดสอบทุกการเปลี่ยนแปลง

การเปลี่ยนแปลงบางอย่างอาจทำให้ประหลาดใจ ทั้งไม่ให้ผลลัพธ์ตามที่คิด หรือคำนวณช้ากว่าที่คาด ดังนั้นจับเวลาและทดสอบทุกการเปลี่ยนแปลง:

1. จับเวลาสูตรที่ต้องการเปลี่ยนด้วยมาโคร **RangeTimer**
2. ทำการเปลี่ยนแปลง
3. จับเวลาสูตรที่เปลี่ยนด้วย **RangeTimer**
4. ตรวจว่าสูตรที่เปลี่ยนยังให้คำตอบที่ถูกต้อง

## 9. ตัวอย่างการใช้กฎ

### ผลรวมสะสมถึงงวด (Period-to-date sums)

ต้องการคำนวณผลรวมสะสมของคอลัมน์ที่มีตัวเลข 2,000 ตัว สมมติคอลัมน์ A มีตัวเลข และคอลัมน์ B กับ C ต้องมีผลรวมสะสม

เขียนสูตรด้วย **SUM** ซึ่งเป็นฟังก์ชันที่มีประสิทธิภาพ

```vb
  B1=SUM($A$1:$A1)
  B2=SUM($A$1:$A2)
```

*(รูปที่ 6 ตัวอย่างสูตร SUM สะสม ดูที่หน้าต้นฉบับ)*

คัดลอกสูตรลงไปถึง B2000

SUM รวมการอ้างอิงเซลล์ทั้งหมดกี่ครั้ง? B1 อ้างอิง 1 เซลล์ และ B2000 อ้างอิง 2,000 เซลล์ ค่าเฉลี่ย 1,000 การอ้างอิงต่อเซลล์ รวมเป็น 2 ล้านการอ้างอิง เลือกสูตร 2,000 ตัวแล้วใช้ **RangeTimer** พบว่าสูตร 2,000 ตัวในคอลัมน์ B คำนวณใน 80 มิลลิวินาที การคำนวณส่วนใหญ่ซ้ำกันหลายครั้ง: SUM บวก A1 กับ A2 ในทุกสูตรจาก B2:B2000

กำจัดความซ้ำซ้อนได้ถ้าเขียนสูตรดังนี้

```vb
  C1=A1
  C2=C1+A1
```

คัดลอกสูตรนี้ลงไปถึง C2000

ตอนนี้รวมการอ้างอิงเซลล์กี่ครั้ง? ทุกสูตรยกเว้นสูตรแรกใช้การอ้างอิง 2 เซลล์ รวมเป็น 1999×2+1 = 3999 ลดลง **500 เท่า**

**RangeTimer** ระบุว่าสูตร 2,000 ตัวในคอลัมน์ C คำนวณใน 3.7 มิลลิวินาที เทียบกับ 80 มิลลิวินาทีของคอลัมน์ B การเปลี่ยนนี้เร็วขึ้นเพียง 80/3.7 = 22 เท่า ไม่ใช่ 500 เท่า เพราะมีโอเวอร์เฮดเล็กน้อยต่อสูตร

### การจัดการข้อผิดพลาด (Error handling)

ถ้ามีสูตรที่ใช้การคำนวณหนักและต้องการให้แสดงผลเป็นศูนย์เมื่อเกิดข้อผิดพลาด (มักเกิดกับ lookup แบบตรงทุกตัว) เขียนได้หลายวิธี:

- เขียนเป็นสูตรเดียว **ซึ่งช้า**:
  `B1=IF(ISERROR(time expensive formula),0,time expensive formula)`
- เขียนเป็นสองสูตร **ซึ่งเร็ว**:
  `A1=time expensive formula`
  `B1=IF(ISERROR(A1),0,A1)`
- หรือใช้ฟังก์ชัน **IFERROR** ซึ่งออกแบบมาให้เร็วและง่าย เป็นสูตรเดียว:
  `B1=IFERROR(time expensive formula,0)`

### นับค่าที่ไม่ซ้ำแบบไดนามิก (Dynamic count unique)

*(รูปที่ 7 ตัวอย่างรายการข้อมูลสำหรับ count unique ดูที่หน้าต้นฉบับ)*

มีรายการข้อมูล 11,000 แถวในคอลัมน์ A ที่เปลี่ยนบ่อย และต้องการสูตรที่คำนวณจำนวนรายการที่ไม่ซ้ำแบบไดนามิก โดยไม่นับช่องว่าง มีวิธีแก้ได้หลายวิธี:

| วิธี | สูตร / โค้ด | เวลา | เร็วขึ้นเท่าไร |
| :-- | :-- | :-- | :-- |
| **สูตรอาร์เรย์** (Ctrl+Shift+Enter) | `{=SUM(IF(LEN(A2:A11000)>0,1/COUNTIF(A2:A11000,A2:A11000)))}` | 13.8 วินาที | ฐาน |
| **SUMPRODUCT** (มักเร็วกว่าสูตรอาร์เรย์ที่เทียบเท่า) | `=SUMPRODUCT((A2:A11000<>"")/COUNTIF(A2:A11000,A2:A11000&""))` | 10.0 วินาที | 1.38 เท่า (ดีขึ้นแต่ยังไม่พอ) |
| **UDF** | `=COUNTU(A2:A11000)` | 0.061 วินาที | 226 เท่า |
| **เพิ่มคอลัมน์สูตร** | ดูด้านล่าง | 0.027 วินาที | 511 เท่า |

**UDF** ด้านล่างอาศัยข้อเท็จจริงที่ว่าดัชนี (key) ของ Collection ต้องไม่ซ้ำ คำอธิบายเทคนิคบางอย่างที่ใช้ ดูหัวข้อ UDF ในส่วน "Using functions efficiently" ของ [Tips for optimizing performance obstructions](05c-tips-for-optimizing-performance-obstructions.md)

```vb
Public Function COUNTU(theRange As Range) As Variant
    Dim colUniques As New Collection
    Dim vArr As Variant
    Dim vCell As Variant
    Dim vLcell As Variant
    Dim oRng As Range
    Set oRng = Intersect(theRange, theRange.Parent.UsedRange)
    vArr = oRng
    On Error Resume Next
    For Each vCell In vArr
    If vCell <> vLcell Then
        If Len(CStr(vCell)) > 0 Then
             colUniques.Add vCell, CStr(vCell)
        End If
    End If
    vLcell = vCell
    Next vCell
    COUNTU = colUniques.Count
End Function
```

**เพิ่มคอลัมน์สูตร:** จากตัวอย่างข้อมูลก่อนหน้า จะเห็นว่าข้อมูล **เรียงลำดับอยู่แล้ว** (Excel ใช้ 0.5 วินาทีเรียง 11,000 แถว) ใช้ประโยชน์ได้โดยเพิ่มคอลัมน์สูตรที่ตรวจว่าข้อมูลในแถวนี้เหมือนแถวก่อนหน้าหรือไม่ ถ้าต่างกัน สูตรคืน 1 ไม่เช่นนั้นคืน 0

ใส่สูตรนี้ในเซลล์ B2

```vb
  =IF(AND(A2<>"",A2<>A1),1,0)
```

คัดลอกสูตร แล้วเพิ่มสูตรรวมคอลัมน์ B

```vb
  =SUM(B2:B11000)
```

การคำนวณเต็มรูปแบบของสูตรทั้งหมดนี้ใช้ 0.027 วินาที ได้ปัจจัยปรับปรุง 13.8/0.027 = **511**

## 10. บทสรุป

Excel ช่วยจัดการเวิร์กชีตที่ใหญ่กว่ามากได้อย่างมีประสิทธิภาพ และให้การปรับปรุงความเร็วการคำนวณอย่างมากเมื่อเทียบกับรุ่นแรก ๆ เมื่อสร้างเวิร์กชีตขนาดใหญ่ ทำให้คำนวณช้าได้ง่าย เวิร์กชีตที่คำนวณช้าเพิ่มข้อผิดพลาดเพราะผู้ใช้รักษาสมาธิได้ยากขณะรอการคำนวณ

ด้วยชุดเทคนิคที่ตรงไปตรงมา เร่งเวิร์กชีตที่คำนวณช้าส่วนใหญ่ได้ 10 หรือ 100 เท่า และใช้เทคนิคเหล่านี้ตอนออกแบบและสร้างเวิร์กชีตเพื่อให้คำนวณเร็วตั้งแต่แรกได้ด้วย

## 11. สรุปกระบวนการและเทคนิค

(ผู้แปลสรุปจากเนื้อหาบทความ)

**กระบวนการปรับปรุงประสิทธิภาพ (workflow):**

1. ตั้งเป็น manual, สำรองไฟล์, เปิดเวิร์กบุ๊กเดียว
2. ตรวจ used range (Ctrl+End) และลดส่วนเกิน
3. วัด `FullcalcTimer` (กรณีเลวร้ายสุด) และ `RecalcTimer` (กรณีดีสุด) → volatility = recalc ÷ full
4. วัดรายชีตด้วย `SheetTimer` → วัดรายบล็อกด้วย `RangeTimer` (drill-down)
5. จัดลำดับสิ่งกีดขวาง → แก้ตามกฎ 4 ข้อ → **จับเวลา ทดสอบความถูกต้อง ทุกครั้งที่แก้**

**เทคนิคสำคัญ:**

- ย้ายการคำนวณซ้ำไปเซลล์ช่วย; ใช้ผลสะสมแทนการรวมช่วงใหญ่ซ้ำ (เช่น `C2=C1+A1` แทน `SUM($A$1:$A2)`)
- เลือกฟังก์ชันที่ดีที่สุด: lookup บนข้อมูลเรียงลำดับ, `IFERROR`, `SUMPRODUCT` แทนสูตรอาร์เรย์, UDF ที่ใช้ Collection สำหรับ count unique
- เลี่ยงฟังก์ชัน volatile (`INDIRECT`, `OFFSET`) และฟังก์ชันเธรดเดียวเมื่อทำได้
- ตัวเลือกระดับแอปพลิเคชัน: Manual / Automatic except tables / `ForceFullCalculation` เมื่อ dependency tree แพงกว่าที่ประหยัดได้
- ปุ่มลัด: F9 (smart), Shift+F9 (ชีตที่เลือก), Ctrl+Alt+F9 (เต็มรูปแบบ), Shift+Ctrl+Alt+F9 (สร้าง dependency ใหม่ + เต็มรูปแบบ)
