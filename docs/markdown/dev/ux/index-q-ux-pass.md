## 2 · เฟส (1 เฟส = 1 กลุ่ม contract)

### A · หน้าภาพรวม: เรดาร์วิเคราะห์ CLO — contract: `d.attain[]`
`chartRadar(d)` มีอยู่แล้วแต่ถูกเรียกที่หน้าผลการประเมินที่เดียว (`:2349`) หน้าภาพรวมมีแต่ตาราง 6 คอลัมน์

- ยกบล็อก “ผลการบรรลุ CLO” ขึ้น**เหนือ**ตาราง “นักศึกษาที่ต้องติดตาม” — คำถามของหน้านี้กลายเป็นสามข้อ และข้อ CLO มาก่อน
- ภายในบล็อก แบ่งสองคอลัมน์ที่ `xl`: ซ้าย = เรดาร์ (คอลัมน์ตายตัว) ขวา = ตารางเดิม · ต่ำกว่า `xl` ซ้อนกัน เรดาร์อยู่บน
- CLO < 3 ข้อ → เรดาร์ 2 แกนไม่ใช่รูปทรง แสดงกราฟแท่ง `chartAttain` แทนในช่องเดียวกัน
- `d.locked` หรือไม่มี CLO → ไม่วาดกราฟ ใช้ข้อความล็อกเดิม (ห้ามวาดกราฟจากตัวเลขที่อธิบายไม่ได้)

**พิสูจน์:** c1 (4 CLO) เรดาร์ขึ้นคู่ตาราง ป้ายทุกอันอยู่ใน viewBox · c2 (2 CLO) ขึ้นแท่งไม่ใช่เรดาร์ · วิชาที่ล็อกไม่มีกราฟ · 1440 / 1024 / 375px ไม่ล้น

### B · การ์ด CLO: ย่อรายละเอียดรอง — contract: `S.tab` (คีย์ใหม่) ไม่แตะข้อมูล
หัวการ์ดปัจจุบันวางข้อเท็จจริง 7 ชิ้น (เลข CLO · Bloom · SOLO · เกณฑ์ผ่าน · เป้าหมายชั้นเรียน + ที่มา · น้ำหนัก · มิเตอร์บรรลุ) **ก่อน** ตัวข้อความ CLO ซึ่งเป็นสิ่งสำคัญที่สุด — ขนาดไม่ได้นำลำดับ

- แถวแรกเหลือ: `CLO n` · ข้อความ CLO (15px) · ค่าบรรลุ + ชิปผลตัดสิน · ปุ่มแก้ไข/ลบ
- ข้อมูลรอง (Bloom · SOLO · น้ำหนัก · เกณฑ์ผ่าน · เป้าหมาย) ยุบเป็น **บรรทัดเดียวสีจาง** ใต้ข้อความ
- แถบ “วัดด้วยกิจกรรม” **พับเมื่อปกติ** และ **กางเองเมื่อมีปัญหา** (ไม่มีกิจกรรมวัด = ต้องเห็น)
- จุดประสงค์เชิงพฤติกรรม: พับเป็นค่าตั้งต้น แต่กางเองถ้ามีข้อใดยังไม่มีวิธีประเมิน · ปุ่มพับ/กางทั้งหมดที่หัวหน้า

**กติกาที่ใช้ทั้งการ์ด:** *พับเมื่อทุกอย่างปกติ · กางเองเมื่อมีสิ่งที่ต้องแก้* — ผู้ใช้ไม่ต้องคลิกหาปัญหา

**พิสูจน์:** ความสูงการ์ด CLO 1 ลดลงจากเดิม (วัดเป็น px) · CLO ที่ไม่มีกิจกรรมวัดยังเห็นคำเตือนโดยไม่ต้องคลิก · พับ/กางแล้วสถานะอยู่รอดการ re-render · ไม่มีข้อมูลใดหายไปจากหน้า (ย้ายที่เท่านั้น)

### C · ความสม่ำเสมอข้าม 9 view — contract: ชั้น utility ที่ทุก view ใช้ร่วม
ไม่ใช่การ “ตกแต่งเพิ่ม” แต่เก็บความไม่ตรงกันที่วัดได้:

- สถานะว่าง 6 แบบต่างกัน (`py-8` / `py-10` / `py-12` × `13px` / `13.5px` × สี) → helper `hollow(text, tone)` ตัวเดียว
- ระยะห่างการ์ดในหน้าเดียวกันสลับ `mb-4` / `mb-5` → ใช้ `mb-4` ตามฐาน 8px
- ความกว้างเนื้อหาต่างกันต่อ view (`1180px` / `1120px` / ไม่กำหนด) ทำให้กรอบกระตุกตอนสลับหน้า → ค่าเดียว

**พิสูจน์:** `grep` สถานะว่างแบบเก่า = 0 · สลับ 9 view ต่อเนื่องแล้วความกว้างเนื้อหาไม่ขยับ · ไม่มี console error

## 4 · ผลที่วัดแล้ว (2569-09-16) — รันจริงใน browser ทุกข้อ

เสิร์ฟด้วย `docs-pages` (`:10011`) · เข้าสู่ระบบเป็น somchai@fac.ac.th · ไม่มี console error ตลอดการตรวจ

### A · เรดาร์ในหน้าภาพรวม
- 1440px: การ์ด “ผลการบรรลุ CLO” แบ่ง `390px + 634.8px` เรดาร์ซ้าย ตารางขวา · ลำดับในหน้าเป็น
  statbar → **ผลการบรรลุ CLO** → นักศึกษาที่ต้องติดตาม → การ์ดเล็กสามใบ
- ป้ายทั้ง 6 ชิ้นใน SVG อยู่ใน `viewBox 0 0 460 340` ครบ (ตรวจด้วย `getBBox()` ไม่ใช่สายตา)
- c1 (4 CLO) = เรดาร์ · c2 (2 CLO) = กราฟแท่ง · c3 และ c4 (ถูกล็อก) = ไม่มีกราฟ ใช้ข้อความล็อกเดิม
- ตารางในโหมดคู่ทิ้งคอลัมน์มิเตอร์ และย้าย `9/12 คน · เป้า 70%` ไปเป็นบรรทัดรองใต้ค่า `ผ่าน` — ไม่มีข้อมูลหาย
- 1279px คือจุดสลับ ต่ำกว่านั้นเรดาร์ไปอยู่บนตาราง เส้นคั่นย้ายจากข้างเป็นบน-ล่างตามจริง

### B · การ์ด CLO
- **หน้า CLO สูง 1,752 → 1,006px ที่ 1440px** (−43%) · การ์ดละ 214px เท่ากันทุกใบ
- c3 CLO 4 (ไม่มีกิจกรรมวัด ไม่มีจุดประสงค์) กางทั้งสองแถบเองโดยไม่ต้องคลิก และสูง 309px ขณะที่ใบปกติ 214px
  — กติกา “พับเมื่อปกติ กางเองเมื่อมีสิ่งที่ต้องแก้” ทำงานจากข้อมูลจริง
- กดกางจุดประสงค์ → เห็นข้อ 1.1 · เรียก `render()` ใหม่ → ยังกางอยู่ (สถานะของผู้ใช้ชนะค่าตั้งต้น)
- ปุ่มหัวหน้า: `ย่อทุกข้อ` → 1,006px · `ขยายทุกข้อ` → 1,888px พร้อมจุดประสงค์ 9 แถว · ป้ายปุ่มสลับตามสถานะจริง
- ข้อมูลที่ย้ายที่ ไม่มีข้อไหนหาย: Bloom · SOLO · น้ำหนัก · เกณฑ์ผ่าน · เป้าหมายชั้นเรียน อยู่ครบในบรรทัดจาง
  และที่มาของเป้าหมาย (สืบทอด/เฉพาะข้อนี้) ย้ายไปอยู่ใน `title`

### C · ความสม่ำเสมอ
- `hollow()` ใช้ 12 จุด · สถานะว่างแบบเก่า `grep` = **0**
- ความกว้างเนื้อหาเหลือค่าเดียว `max-w-[1180px]` (เดิม 1180/1120) · `mb-5` ในการจัดวางการ์ดหมดแล้ว
  (เหลือ 1 จุดในข้อความของโมดัลนำเข้าไฟล์ ซึ่งไม่ใช่ระยะห่างการ์ด)

### D · สิ่งที่พบระหว่างทางและแก้เพิ่ม (ไม่ได้อยู่ในแผนตอนเขียน)
1. **ป้ายในกราฟเล็กจนอ่านไม่ออกบนมือถือ** — SVG ย่อตามความกว้างพร้อมตัวหนังสือ: ที่ 375px
   กราฟแท่ง 11.5px เหลือ **5.7px** และ histogram เหลือ **6.6px** (ของเดิมในหน้าผลการประเมิน ไม่ใช่ของใหม่)
   แก้ด้วยความกว้างขั้นต่ำ + `.scroll-x` แบบเดียวกับตารางคะแนน → ตอนนี้ 10.1 / 11.0 / 9.0px และหน้าไม่ล้น
2. **หัวการ์ด CLO พังที่ 362px** — บล็อกสัดส่วนผู้ผ่าน `shrink-0` บีบคอลัมน์ข้อความจนตัว CLO
   แตกเป็นคำละบรรทัดและทับเลข CLO · แก้ด้วย `flex-wrap` + `min-w` และมัดปุ่มเลื่อนลำดับไว้กับคอลัมน์ข้อความ
   (ไม่งั้นมันกินบรรทัดเต็มบรรทัดโดยกว้าง 26px) → การ์ดมือถือ 454 → **389px** ไม่มีกล่องไหนทับกัน

### E · ไม่ถดถอย
- 4 รายวิชา × 8 route = **32 หน้า เรนเดอร์ครบ 0 error 0 ล้นแนวนอน** ทั้งที่ 1440px และ 375px
- `check-design-tokens` · `check-action-caps` (24×2) · `check-perm-matrix` (55 ช่อง) · `check-auth-events` ผ่านทั้งหมด
- ไม่แตะการคำนวณ CR-01…CR-11 ไม่แตะ schema ไม่แตะข้อมูลตัวอย่าง

### F · ที่ยังไม่ได้ทำ
- สถานะว่างในแถบรายการซ้าย (`:5113`, `:5144`) ยังเป็น 12.5px ของตัวเอง — คนละบริบทกับการ์ด จงใจไม่รวม
- อีก 4 ไฟล์ใน `docs/pages/` ไม่ได้แตะ ตามขอบเขต

## 5.2 · ราคาที่ต้องรู้ก่อน — G1 เปลี่ยนคำตัดสิน ไม่ใช่แค่ป้าย

`met` ตาม CR-04 คือ `share >= target` เมื่อ `target` กลายเป็น 100 ทุก CLO ที่ยังมีคนสอบตกแม้คนเดียว
จะขึ้นว่า **ไม่บรรลุ** ทันที — c1 จะเปลี่ยนจาก “CLO ที่บรรลุ 2/4” เป็น **0/4** ทั้งที่ตัวเลขสัดส่วนผู้ผ่านไม่ได้เปลี่ยนเลย
นี่คือความเสี่ยงที่ D2 ใน [[mockup-feedback-plan]] เคยเขียนไว้ และเจ้าของงานเลือกทางนี้แล้ว จึงทำตามและบันทึกผลจริงไว้
