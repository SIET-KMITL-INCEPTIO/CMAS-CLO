## 1. "เสร็จ" แปลว่าอะไร — มาตรฐานที่ต้องผ่าน

ใช้ ST-UI-1…8 ของ [[system-test-plan]] §5.8 เป็นแกน และทำให้แต่ละข้อมีตัวเลขหรือ test ที่ตรวจได้

| ข้อ | เกณฑ์ที่วัดได้ | ตรวจด้วย |
|---|---|---|
| **U-1** contrast | ข้อความทุกชิ้น ≥ 4.5:1 · ข้อความใหญ่และขอบของปุ่ม/ช่องกรอก ≥ 3:1 · **ทั้งธีมสว่างและมืด** (WCAG 2.2 AA) | unit test คู่สีใน `tokens.css` + axe `color-contrast` ใน Playwright |
| **U-2** สีจาก token เท่านั้น | ไม่มี hex ใหม่ในกฎของ component · ทุก token ที่เป็นพื้นผิวหรือข้อความมีค่าทั้งสองธีม | `styles/theme.test.ts` (ขยาย) |
| **U-3** 4 สถานะ | ทุกหน้ามี กำลังโหลด · ว่าง · ผิดพลาด (ภาษาไทย + วิธีแก้) · สำเร็จ | component test ต่อหน้า |
| **U-4** คีย์บอร์ด | ทุกปุ่ม/ลิงก์/ช่องเข้าถึงด้วย Tab · มีกรอบ `:focus-visible` · dialog กัก focus และปิดด้วย Esc | Playwright + axe |
| **U-5** โครงสร้างเข้าถึงได้ | axe ไม่พบ violation ระดับ serious/critical ในทุกหน้า | `@axe-core/playwright` |
| **U-6** ขนาดจอ | ใช้ได้ที่ 375 · 768 · 1280 · 1440 px ไม่มีแถบเลื่อนแนวนอนของทั้งหน้า | Playwright viewport |
| **U-7** การเคลื่อนไหว | เคารพ `prefers-reduced-motion` | ตรวจ CSS + Playwright `reducedMotion` |
| **U-8** ตรงกับต้นแบบ | ST-UI-1 และ ST-UI-8 (ข้อความ · ลำดับส่วน · ตัวเลขตรงกับ `index-q.html` บนข้อมูลชุดเดียวกัน) | เทียบด้วยตาบน seed (ตรวจมือ มีเช็กลิสต์) |

ข้อ U-1 ขัดกับ ST-UI-2 "สีตามต้นแบบ" ในจุดเดียว: สี `dim` ของต้นแบบเองไม่ผ่าน AA — ดูการตัดสิน D-UI-2 ใน §5

## 2. สภาพปัจจุบัน — วัดแล้ว

### 2.1 contrast (คำนวณตามสูตร WCAG จากค่าใน `tokens.css`)

### 2.2 สีตายตัวและธีมมืด

- `atelier.css` มี hex **66 ค่า** นอก `tokens.css` · ในจำนวนนี้ ~40 ค่าเป็นสีของปุ่ม `kbd` `meter` tooltip toast และช่องกรอกตอน focus ที่ไม่มีค่าธีมมืด
- บางส่วนตั้งใจให้เหมือนกันทั้งสองธีม (แถบบน rail แถบค้นหา) — ต้องแยกให้ชัดว่าข้อไหนตั้งใจ
- ใน `.tsx` มี hex 14 ค่า (11 อยู่ใน `LevelChips.tsx`)
- รอบก่อนแก้ไปแล้ว 5 พื้นผิว (PR #85) และมี test กันถอยหลัง

### 2.5 เครื่องมือทดสอบ UI

- client มี test 12 ไฟล์ — เป็น test ของฟังก์ชันคำนวณ **ไม่มี test ของ component เลย** (ไม่มี `@testing-library/react`)
- Playwright มี 2 กรณีในเบราว์เซอร์ (`e2e/tests/browser.spec.ts`) · **ไม่มี axe** · ไม่มี `eslint-plugin-jsx-a11y`
- ขนาดตัวอักษรเป็น `text-[Npx]` 214 จุด — การตั้งค่าขนาดตัวอักษรของแอป (`data-scale`) ต้องตรวจว่ายังขยายตามได้

## 3. ลำดับงาน — หนึ่งช่วง = หนึ่ง branch จาก `develop`

แบ่งตาม "อะไรต้องใช้ผลของอะไร": P0 สร้างเครื่องวัดที่ทุกช่วงต่อจากนี้ใช้ตรวจ · P3a สร้าง endpoint ที่ P3b เรียก

| ช่วง | branch | งาน | ผ่านเมื่อ (gate) |
|---|---|---|---|
| **P0 เครื่องวัด** | `test/ui-a11y-harness` | ติดตั้ง `@axe-core/playwright` · `@testing-library/react` · `eslint-plugin-jsx-a11y` · seed สำหรับ E2E (1 วิชา ครบทุกขั้น) · spec ที่เปิดทุกหน้า × 2 ธีม × 4 ขนาดจอ แล้วรัน axe · unit test คู่สีจาก `tokens.css` | test รันใน CI · **พิสูจน์ว่าเครื่องวัดล้มได้**: ใส่สีผิดหนึ่งค่าแล้ว test แดง · บันทึกจำนวน violation ตั้งต้นต่อหน้า |
| **P1 สีและ focus** | `fix/ui-contrast-tokens` | `dim` สำหรับข้อความ → `#646a8c` (5.27:1 บนขาว · 4.84:1 บน `wash`) · `faint`/`fgray` ใช้เฉพาะเส้นและของตกแต่ง · ย้าย hex ใน `atelier.css` ไปเป็น token ที่มีค่าทั้งสองธีม · `ok/okBg` ≥ 4.5 · `:focus-visible` ทุกองค์ประกอบที่กดได้ · `prefers-reduced-motion` ครอบทุก transition | unit test คู่สี 0 ข้อยกเว้น · axe `color-contrast` = 0 ทุกหน้าทั้งสองธีม · ภาพก่อน/หลังของ 13 หน้า |
| **P2 สถานะและ error** | `fix/ui-page-states` | ใส่สถานะที่ขาดใน §2.3 · component กลาง `PageState` (โหลด/ว่าง/ผิดพลาด) · ข้อความ error ภาษาไทยบอกวิธีแก้ (งาน E ของ [[finish-plan-2026-11]]) | component test ทุกหน้า 4 สถานะ · ไม่มีข้อความภาษาอังกฤษจาก server หลุดถึงผู้ใช้ |
| **P3a endpoint ที่เหลือ** | `feature/api-remaining-4` | `POST /users` · `GET …/students/export` · `POST /courses/copy-level/preview` · `/commit` ตามแผ่น Design ของ Excel | `api-contract.test.ts` เปลี่ยน 4 แถวเป็น "ทำแล้ว" · ST-AUTH-10 · ST-COURSE-07/08 · ST-IMP-07 ผ่าน · test ข้ามรายวิชา (S-8) ครอบ 4 ตัวใหม่ |
| **P3b หน้าจอที่ขาด** | `feature/ui-missing-screens` | ตาราง §2.4 ทั้งหมด | ทุก use case ในแผ่น UseCases ของ Excel เป็น "ทำแล้ว" · ผ่าน U-1…U-7 จากเครื่องวัด P0 |
| **P4 ปิดงาน** | `test/ui-acceptance` | เดินเช็กลิสต์ ST-UI-1…8 ทีละหน้าบน seed เดียวกับต้นแบบ · ทดสอบ flow ของ use case หลักใน Playwright (ล็อกอินด้วยลิงก์อีเมล → สร้างวิชา → CLO → กิจกรรม → นำเข้าคะแนน → ดูผล → ตัดเกรด) | เช็กลิสต์ครบ 13 หน้า · E2E flow เขียว · บันทึกผลใน [[system-test-plan]] |

P1 กับ P2 ไม่ใช้ผลของกันและกัน ทำขนานได้ · P3a ต้องเสร็จก่อนส่วนของ P3b ที่เรียก endpoint ใหม่ (`modalProfile` · histogram ไม่ต้องรอ)

## 4. ถ้าช้า — ตัดตามลำดับ
