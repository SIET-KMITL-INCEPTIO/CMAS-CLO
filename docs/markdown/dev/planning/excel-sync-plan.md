# แผนซิงก์คะแนนกับ Excel: การใช้งาน ข้อจำกัด และความปลอดภัย

สถานะ: **ต้นแบบใช้งานได้ (Excel → เว็บ) · ระยะ 1 เสร็จ · แอปจริงยังไม่มี** · อ้างอิงโค้ด ณ 2026-11-12 บนสาขา `feat/excel-precheck-trial`

เป้าหมาย: อาจารย์กรอกคะแนนใน Excel ตามที่คุ้นเคย แล้วหน้าเว็บอัปเดตเองโดยไม่ต้องอัปโหลดซ้ำ
ไม่ใช้ Macro ไม่ใช้ Office Add-in และไม่ต้องติดตั้งอะไรใน Excel

เอกสารที่เกี่ยวข้อง: [office-addin-plan.md](office-addin-plan.md) (ทางเลือก Add-in ที่ไม่ได้เลือก เพราะติดตั้งและแจกจ่ายยาก)

## 1. สิ่งที่ทำแล้ว (ต้นแบบ `docs/index-q/index-q.html`)

| ส่วน | ทำงานอย่างไร |
| --- | --- |
| ไฟล์ส่งออก | `.xlsx` ธรรมดา ไม่มี Macro · แผ่นงานป้องกันไว้ (ไม่มีรหัสผ่าน) ให้พิมพ์ได้เฉพาะช่องคะแนน · ตรวจค่าในช่อง (0 ถึงคะแนนเต็ม, `ยกเว้น`) · หัวคอลัมน์มี `[รหัสกิจกรรม]` |
| เชื่อมไฟล์ | ลากไฟล์มาวาง หรือ "เลือกไฟล์" ใน Chrome/Edge → ขั้นยืนยันมีช่อง "อัปเดตอัตโนมัติ" → นำเข้าแล้วเชื่อมต่อในคราวเดียว |
| ตรวจการเปลี่ยน | ทุก 3 วินาทีดูเฉพาะเวลาแก้ไขของไฟล์ · อ่านทั้งไฟล์เมื่อเวลาเปลี่ยนเท่านั้น · ตรวจทันทีเมื่อหน้าต่างได้โฟกัสคืน |
| เขียนคะแนน | ผ่านตัวตรวจเดียวกับการนำเข้า (`validateWorkbook`) และตัวเขียนเดียว (`writeScore`) · มีประวัติ ประวัติการนำเข้า และเลิกทำได้ |
| ใช้เฉพาะช่องที่แก้ใน Excel | แต่ละช่องจำ "ค่าที่ตรงกันล่าสุด" (base) · ไฟล์เปลี่ยนแต่เว็บไม่เปลี่ยน → ใช้ค่า Excel · ไฟล์ไม่เปลี่ยน → ไม่ทับสิ่งที่แก้ในเว็บ · เปลี่ยนทั้งสองที่ → ไม่เขียน ให้เลือกที่การ์ด (ใช้ค่า Excel / เก็บค่าในเว็บ) |
| สถานะ | การ์ดมุมขวาล่าง: สด · กำลังอัปเดต · พัก (บอกเหตุผล) · อ่านไม่ได้ · แก้ทั้งสองที่ · เชื่อมต่ออีกครั้ง |
| ไฟล์ล้าสมัย | การ์ดเตือนทันทีเมื่อรายวิชามีกิจกรรมที่ไม่อยู่ในไฟล์ พร้อมปุ่มส่งออกใหม่ · เตือนคอลัมน์ในไฟล์ที่ไม่ตรงกิจกรรม |
| จำไฟล์หลังรีเฟรช | เก็บตัวจับไฟล์ใน IndexedDB ต่อ ผู้ใช้ × รายวิชา · ยังมีสิทธิ์ = เชื่อมเองและใช้ค่าในไฟล์ที่ต่างจากเว็บ · ไม่มีสิทธิ์ = การ์ดให้กด "เชื่อมต่อ" ครั้งเดียว |
| ช่องไม่ผ่านซ้ำ | บันทึกประวัติและแจ้งเฉพาะเมื่อชุดช่องที่ไม่ผ่านเปลี่ยน ไม่แจ้งซ้ำทุกครั้งที่บันทึก |
| กันฉีดสูตร | ทุกไฟล์ส่งออก: ข้อความที่ขึ้นต้นด้วย `= + - @` ถูกนำหน้าด้วย `'` (เหมือน `safeText` ของเซิร์ฟเวอร์) |
| ความปลอดภัยของเซสชัน | ออกจากระบบหรือสลับบัญชี = เลิกเชื่อมและลบไฟล์ที่จำไว้ทันที |

เทคโนโลยี: File System Access API (`showOpenFilePicker`, `DataTransferItem.getAsFileSystemHandle`) + SheetJS

## 2. แผนการใช้งาน (สำหรับอาจารย์)

### 2.1 ขั้นตอนปกติ

1. ตั้งค่ารายวิชาในเว็บให้ครบก่อน: CLO · วัตถุประสงค์ · **กิจกรรม** (คะแนนเต็ม น้ำหนัก การผูก) · รายชื่อ
2. กด **ส่งออกคะแนน** → เปิดไฟล์ใน Excel
3. ในเว็บ: **นำเข้าคะแนน** → ลากไฟล์เดียวกันมาวาง → ถัดไป → ติ๊ก "อัปเดตอัตโนมัติ" → ยืนยันบันทึก
4. กรอกคะแนนใน Excel แล้วบันทึก (Ctrl+S หรือ AutoSave) → หน้าเว็บเปลี่ยนเองภายในไม่กี่วินาที
5. เสร็จแล้วกด **×** ที่การ์ดสถานะ หรือปิดหน้า

ถ้าต้องการไม่ต้องกด Ctrl+S เลย: เก็บไฟล์ในโฟลเดอร์ OneDrive ของสถาบันบนเครื่อง แล้วเปิด **AutoSave** ใน Excel

### 2.2 กติกาที่ต้องตกลงกับผู้ใช้

| เรื่อง | กติกา |
| --- | --- |
| ทิศทาง | **Excel → เว็บ ทางเดียว** การแก้ในเว็บไม่กลับไปที่ไฟล์ |
| แก้ทั้งสองฝั่ง | Excel ทับเฉพาะช่องที่แก้ใน Excel · ช่องที่แก้ทั้งในเว็บและใน Excel ระบบไม่ทับเอง ให้เลือกที่การ์ด · เลือก "เก็บค่าในเว็บ" แล้ว ไฟล์ยังเป็นค่าเดิม ส่งออกใหม่ถ้าต้องการให้ตรงกัน |
| โครงสร้างรายวิชา | เพิ่ม/ลบ/แก้กิจกรรมในเว็บเท่านั้น · แล้ว **ส่งออกใหม่และเชื่อมไฟล์ใหม่** |
| ช่องว่าง | ล้างช่องใน Excel **ไม่ลบ** คะแนนในเว็บ (ตามกติกานำเข้า FR-62) · จะลบให้ลบในเว็บ |
| หลายคน | หนึ่งไฟล์ ต่อหนึ่งผู้สอน ต่อหนึ่ง Sec · ไม่แชร์ไฟล์ที่เชื่อมอยู่ให้หลายคนแก้พร้อมกัน |

## 3. ข้อจำกัด

### 3.1 ข้อจำกัดของวิธีนี้

| ข้อจำกัด | สาเหตุ | ทางรับมือ |
| --- | --- | --- |
| ไม่สดทุกตัวอักษร | Excel เขียนไฟล์เมื่อบันทึกเท่านั้น | AutoSave หรือ Ctrl+S |
| เว็บ → Excel ไม่ได้ | Excel ล็อกไฟล์ที่เปิดอยู่ และไม่โหลดค่าจากภายนอก | ส่งออกใหม่ · หรือระยะ 3 (Power Query) |
| เฉพาะ Chrome / Edge | File System Access API | เบราว์เซอร์อื่นนำเข้าได้ครั้งเดียว |
| รีเฟรชหน้าแล้วอาจต้องกด "เชื่อมต่อ" | เบราว์เซอร์อาจถอนสิทธิ์อ่านไฟล์เมื่อปิดแท็บ | การ์ดถามให้กดครั้งเดียว · ถ้าไฟล์ถูกย้ายหรือลบ ต้องนำเข้าใหม่ |
| เชื่อมต่ออีกครั้งหลังรีเฟรชใช้ค่าในไฟล์ทั้งหมด | หลังรีเฟรชไม่มี base เดิม (ต้นแบบล้างข้อมูลทุกครั้งที่รีเฟรชอยู่แล้ว) | แอปจริงต้องเก็บ base ไว้ด้วย ไม่อย่างนั้นค่าที่แก้ในเว็บระหว่างปิดหน้าจะถูกทับ |
| ต้องเปิดหน้าเว็บค้างไว้ | ตัวตรวจอยู่ในหน้าเว็บ · แท็บที่ถูกซ่อนจะไม่อ่าน | วางเว็บกับ Excel ข้างกัน |
| ต้นแบบไม่เก็บข้อมูลถาวร | ต้นแบบไม่มีเซิร์ฟเวอร์ | ระยะ 2: ย้ายไปแอปจริง |

### 3.2 ข้อจำกัดเมื่อย้ายไปแอปจริง (ตรวจจากโค้ดแล้ว)

- `PUT /courses/:courseId/scores` รับ `source` ได้แค่ `MANUAL · PASTE · FILL · FILL_UNDO · UNDO` ([`scores.validator.ts`](../../../../app/server/src/modules/scores/scores.validator.ts)) ไม่มี `IMPORT`
  ทางที่ใช้โค้ดเดิมมากที่สุดคือให้ไคลเอนต์ส่งไฟล์ไป `POST …/scores/import/preview` แล้ว `…/import/commit` เอง ซึ่งได้ตัวตรวจ ประวัติ (`ScoreChange.source = IMPORT`) และ `ScoreUploadLog` ครบ
- `preview` จำกัด **10 ครั้งต่อนาทีต่อผู้ใช้** (`IMPORT_LIMIT` ใน [`students.route.ts`](../../../../app/server/src/modules/students/students.route.ts)) · AutoSave บันทึกถี่ จึงต้องหน่วงฝั่งไคลเอนต์ไม่ให้ส่งเกินหนึ่งครั้งทุก ~10 วินาที
- ผลตรวจไฟล์เก็บในหน่วยความจำของเซิร์ฟเวอร์ 15 นาที ([`preview-store.ts`](../../../../app/server/src/lib/preview-store.ts)) · ใช้ได้กับเซิร์ฟเวอร์ตัวเดียว
- ไฟล์จำกัด 10 MB, 5 แผ่นงาน, 2,000 แถว และไฟล์ที่มีสูตรถูกปฏิเสธ ([`excel.ts`](../../../../app/server/src/lib/excel.ts)) · ไฟล์ส่งออกของต้นแบบมีสูตร `SUM` ในคอลัมน์คะแนนรวม **ต้องเอาออก** ก่อนใช้กับแอปจริง หรือให้เซิร์ฟเวอร์ยอมสูตรในคอลัมน์ที่ไม่ได้นำเข้า
- access token หมดอายุ 15 นาที — ตัวตรวจต้องหยุดหรือขอโทเคนใหม่เมื่อได้ 401

## 4. ความปลอดภัย

### 4.1 ภัยและมาตรการ

| ภัย | มาตรการ (ต้นแบบ / แอปจริง) |
| --- | --- |
| เว็บอ่านไฟล์อื่นในเครื่อง | เบราว์เซอร์ให้สิทธิ์เฉพาะไฟล์ที่ผู้ใช้เลือกหรือลากเอง · ขอสิทธิ์**อ่านอย่างเดียว** · ไม่ขอสิทธิ์เขียน |
| ไฟล์มีเนื้อหาอันตราย (สูตร ค่าแปลก ไฟล์ใหญ่) | อ่านเฉพาะค่า ไม่รันสูตรหรือ Macro · ไฟล์เสียหรือไม่ใช่ `.xlsx` ถูกปฏิเสธ · แอปจริง: ตรวจซ้ำทุกแถวที่เซิร์ฟเวอร์ (Zod + กติกาเดิม) ไม่เชื่อผลตรวจจากไคลเอนต์ |
| ฉีดสูตรผ่านไฟล์ส่งออก (CSV/formula injection) | ข้อความที่ขึ้นต้นด้วย `= + - @` ถูกนำหน้าด้วย `'` ทั้งเซิร์ฟเวอร์ (`safeText`) และต้นแบบ (`neutraliseText`) |
| เขียนคะแนนข้ามรายวิชา | ไฟล์ต้องตรงกับ Sec ที่เปิดอยู่ (`[รหัสกิจกรรม]`) · การ์ด "พัก" เมื่ออยู่วิชาอื่น · แอปจริง: ทุกคำขอผ่าน `config: { access: { cap } }` และขอบเขตรายวิชาได้ **404** ไม่ใช่ 403 |
| คนอื่นใช้เครื่องต่อแล้วไฟล์ยังเชื่อมอยู่ | เลิกเชื่อมและลบไฟล์ที่จำไว้เมื่อออกจากระบบหรือสลับบัญชี · ไฟล์ที่จำไว้แยกตามผู้ใช้ · แอปจริง: เลิกเชื่อมเมื่อได้ 401 หรือโทเคนหมดอายุ |
| ทับคะแนนที่แก้ในเว็บโดยไม่ตั้งใจ | ใช้เฉพาะช่องที่แก้ใน Excel · ช่องที่แก้ทั้งสองที่ต้องให้ผู้ใช้เลือก |
| บัญชีถูกระงับระหว่างเชื่อม | แอปจริง: `authMiddleware` อ่าน User จากฐานข้อมูลสดทุกคำขอ จึงถูกปฏิเสธทันที |
| แก้คะแนนโดยไม่มีร่องรอย | ทุกช่องผ่าน `writeScore` (ต้นแบบ) หรือ `ScoreChange` (แอปจริง) · มีประวัติการนำเข้าและเลิกทำได้ |
| ทับคะแนนที่ไม่ควรแก้ | เกรดถูกตรึง · กิจกรรมปิดรับ · นักศึกษาถอนรายวิชา ถูกปฏิเสธตามกติกานำเข้า · ช่องว่างไม่ลบคะแนน |
| ส่งคำขอถี่เกิน (AutoSave) | อ่านไฟล์เมื่อเวลาแก้ไขเปลี่ยนเท่านั้น · ส่งเฉพาะช่องที่เปลี่ยน · แอปจริง: หน่วงฝั่งไคลเอนต์ + rate limit ของเซิร์ฟเวอร์ |

### 4.2 ข้อมูลส่วนบุคคลในไฟล์ Excel

ไฟล์มี **รหัสและชื่อนักศึกษาพร้อมคะแนน** เมื่อส่งออกแล้ว ไฟล์อยู่นอกการควบคุมของระบบ จึงต้องแนะนำผู้ใช้:

- เก็บในเครื่องของสถาบัน หรือ OneDrive ของสถาบัน (ไม่ใช่บัญชีส่วนตัว)
- ไม่ส่งไฟล์ทางอีเมลหรือแชท · ลบเมื่อจบภาคการศึกษา
- **การป้องกันแผ่นงานไม่ใช่ความปลอดภัย** (ไม่มีรหัสผ่าน มีไว้กันพิมพ์ผิดช่อง) · ใครที่มีไฟล์ก็อ่านได้ทั้งหมด

### 4.3 Macro และ Power Query

- **ไม่ใช้ Macro** ในแผนนี้ · ถ้ามีผู้ใช้เพิ่ม Macro เอง ระบบอ่านเฉพาะค่าในชีตแรก ไม่รัน Macro และไฟล์ที่มีสูตรยังถูกปฏิเสธ
- ถ้าทำระยะ 3 (เว็บ → Excel ด้วย Power Query):
  - endpoint **อ่านอย่างเดียว** ต่อหนึ่งรายวิชา
  - ใช้โทเคนแยกสำหรับ Excel: จำกัดขอบเขตรายวิชา หมดอายุ เพิกถอนได้ และส่งใน header ไม่ใส่ใน URL
  - **ห้ามฝังโทเคนหรือรหัสผ่านในไฟล์** · ให้ Excel เก็บเองในที่เก็บรหัสของ Excel

## 5. ลำดับงาน

| ระยะ | งาน | ขอบเขต |
| --- | --- | --- |
| 0 | Excel → เว็บ ในต้นแบบ | **เสร็จแล้ว** |
| 1 | ปรับต้นแบบ: เตือนไฟล์ล้าสมัย · เตือนคอลัมน์ที่ถูกข้าม · ใช้เฉพาะช่องที่แก้ใน Excel และให้เลือกเมื่อแก้ทั้งสองที่ · จำไฟล์ไว้หลังรีเฟรช · กันฉีดสูตรในไฟล์ส่งออก | **เสร็จแล้ว** |
| 2 | ย้ายไปแอปจริง: hook `useExcelLink` ใน `features/scores` ส่งไฟล์ผ่าน `import/preview` + `import/commit` · ตรวจ "แก้ทั้งสองที่" ต้องใช้ base ที่เก็บถาวร (เซิร์ฟเวอร์ หรือ IndexedDB) และเซิร์ฟเวอร์ต้องรับเงื่อนไข "เขียนเมื่อค่ายังเป็น X" · หน่วงตาม rate limit · หยุดเมื่อ 401 · เอาสูตรออกจากไฟล์ส่งออก · ทดสอบ (unit + Playwright) · แก้ SRS/DFD | client + server |
| 3 | เว็บ → Excel ด้วย Power Query (ถ้าต้องการ): endpoint อ่านอย่างเดียว + โทเคนสำหรับ Excel | server + เอกสาร |

ทุกระยะต้องอัปเดต SRS (FR ใหม่สำหรับการเชื่อมไฟล์) และแผนภาพ DFD ระดับ 2 กระบวนการ 4.0 ตามกฎของโปรเจกต์
