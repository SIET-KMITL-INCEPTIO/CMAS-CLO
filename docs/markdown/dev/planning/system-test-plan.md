## 2. Gray box ในโปรเจกต์นี้หมายถึงอะไร

ผู้ทดสอบ**ป้อนข้อมูลจากภายนอกเท่านั้น**: ยิง HTTP เข้า `/api/v1/*` หรือคลิกในเบราว์เซอร์ ไม่เรียกฟังก์ชันภายในโดยตรง
แต่**ใช้ความรู้ภายในสองทาง**: ใช้ออกแบบกรณีทดสอบ และใช้ตรวจผล

| ความรู้ภายในที่ใช้ | ใช้ออกแบบกรณีอะไร | ใช้ตรวจผลอย่างไร |
|---|---|---|
| ตาราง capability (`capabilities.ts` = `PERM` ของต้นแบบ) | ตารางสิทธิ์ บทบาท × capability × สังกัดรายวิชา (§5.2) | รหัสสถานะ 401 / 403 / 404 ตรงตาราง |
| `schema.prisma` · unique key · CHECK และ trigger ใน migration `0002` และ `0004` | ค่าขอบ ค่าซ้ำ ค่าข้ามรายวิชา | ไม่มีแถวผิดเข้าฐานข้อมูล · API ตอบ 409/422 ก่อน DB ปฏิเสธ (NFR-12) |
| `ScoreChange` · `ScoreUploadLog` | ทุกทางที่เขียนคะแนน | query ฐานข้อมูลหลังทดสอบ: ทุกการเขียนมีแถวประวัติ (A-12, FR-71) |
| ลำดับ preHandler (A-7) และ error handler | ส่ง id รูปผิด หรือ body เกินฟิลด์ | ไม่มีการอ่าน DB ด้วย id ที่ยังไม่ผ่าน Zod · ไม่มี stack trace ในคำตอบ |
| สูตร CR-01…CR-11 และ `derive()` ในต้นแบบ | ชุดข้อมูลที่ครอบคลุมกรณีขอบของสูตร | ตัวเลขจาก API = ตัวเลขที่ต้นแบบคำนวณจาก seed เดียวกัน |
| การตั้งค่า log (pino `redact`) | ส่งข้อมูลนักศึกษาให้เกิด error | ค้น log ทั้งไฟล์ ต้องไม่พบรหัสนักศึกษา ชื่อ หรือคะแนน (NFR-08) |

การตรวจฐานข้อมูลทำด้วยบัญชี**อ่านอย่างเดียว**เท่านั้น ผู้ทดสอบไม่แก้ข้อมูลตรงในฐานข้อมูลระหว่างรันกรณีทดสอบ

## 5. ชุดทดสอบ

รหัสกรณีทดสอบ: `ST-<ชุด>-<เลข>` · คอลัมน์ "ตรวจภายใน" คือส่วน gray box ที่มองไม่เห็นจากคำตอบ HTTP อย่างเดียว

### 5.1 เทคนิคที่ใช้

| เทคนิค | ใช้กับ |
|---|---|
| ตารางตัดสินใจ (decision table) | สิทธิ์ (§5.2) · สถานะนักศึกษาและกิจกรรม |
| แบ่งกลุ่มสมมูลและค่าขอบ | คะแนน `0 ≤ score ≤ maxScore` · หน่วยกิต 0 · น้ำหนักรวม 99 / 100 / 101 · `n < 2` ของการตัดเกรดอิงกลุ่ม |
| เปลี่ยนสถานะ (state transition) | นักศึกษา ปกติ → ถอน → คืนสถานะ · กิจกรรม เปิด → ปิด → เปิดใหม่ · เกรด ยังไม่ตรึง → ตรึง → ยกเลิก |
| สร้างกรณีจากรายการ route | ทุก route ใน Excel ได้กรณีบวก 1 และกรณีลบอย่างน้อย 1 อัตโนมัติ |
| เทียบผลกับต้นแบบ | ทุกตัวเลขบนแดชบอร์ดและผลตัดเกรด |

### 5.2 ST-ACL สิทธิ์และขอบเขตรายวิชา (NFR-06, NFR-07, NFR-19, D-1)

ตารางนี้ใช้กับ **ทุก** endpoint ที่มี `:courseId` หรือ leaf id ตามคอลัมน์ "Capability" ใน Excel

| ผู้เรียก | รายวิชาของตน | รายวิชาที่ไม่ได้สอน | id ที่ไม่มีอยู่ |
|---|---|---|---|
| ไม่มี token / token หมดอายุ / refresh token | 401 | 401 | 401 |
| ผู้สอน (`u1` กับ `c1`) · capability งานสอน | 2xx | **404** | 404 |
| ADMIN (`u3`) · อ่าน (`course.view`) | 2xx | 2xx | 404 |
| ADMIN · งานสอน (`score.edit`, `clo.write` ฯลฯ) | **403** | **403** | 404 |
| ADMIN · `staff.write`, `course.delete` | 2xx | 2xx | 404 |
| ผู้สอนที่ถูกปิดบัญชีหลังได้ token | 401 ทันที ไม่รอ token หมดอายุ | 401 | 401 |

| รหัส | กรณี | ตรวจภายใน |
|---|---|---|
| ST-ACL-01 | `u6` ยิงทุก route ของ `c1` (ที่ตนไม่ได้สอน) ต้องได้ 404 | body และ header ของ 404 ต้องเหมือน "id ไม่มีอยู่จริง" ทุกไบต์ (A-13) |
| ST-ACL-02 | `u6` ยิง leaf id (`/clos/:cloId`, `/students/:studentId`) ของ `c1` | ได้ 404 ไม่ใช่ 403 แม้ id มีอยู่จริง |
| ST-ACL-03 | ปิดบัญชี `u1` ขณะ token ยังไม่หมดอายุ แล้วยิงต่อ | ได้ 401 ใน request ถัดไป (อ่านแถว `User` สด · NFR-19) |
| ST-ACL-04 | ส่ง `courseId`, `role`, `uploadedBy` มาใน body | ค่าใน body ถูกปฏิเสธ (`.strict()`) และไม่ถูกเขียน (A-8) |
| ST-ACL-05 | refresh token ใช้แทน access token | 401 (S-1) |
