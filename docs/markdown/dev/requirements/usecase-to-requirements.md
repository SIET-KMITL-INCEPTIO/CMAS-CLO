# Use case → ข้อกำหนด: function นี้ทำเพื่ออะไร และเพราะอะไร

เอกสารนี้อธิบายทีละ function ใน `docs/diagrams/usecase/usecase-diagram.drawio` ว่า
**ใครทำได้ · ตรงกับข้อกำหนดข้อไหนใน [srs.md](srs.md) · ทำไมระบบต้องเป็นแบบนี้**

อ่านสิทธิ์จาก `app/server/src/modules/authorization/capabilities.ts` (สำเนาของ `PERM` ในต้นแบบ)

- **สถานะ** ✅ = ใช้ได้จริงในแอปตอนนี้ · ⏳ = อยู่ในต้นแบบ `index-q.html` ยังไม่ได้ทำในแอป
- **ADMIN** = ผู้ดูแลระบบ · **ผู้สอน** = INSTRUCTOR ของวิชานั้น (ผู้สอนทำได้เฉพาะวิชาที่ตนสอน — FR-25, NFR-07)
- **ADMIN ดูข้อมูลทุกวิชาได้ แต่ไม่ทำงานสอน** (คะแนน นักศึกษา CLO กิจกรรม เกรด) — มติ D-1

| 1.2 | แก้ไขบัญชีผู้ใช้ | FR-05 | แก้ชื่อ อีเมล บทบาท โดยไม่ต้องสร้างบัญชีใหม่ | ⏳ |

| 1.6 | อนุมัติบัญชีที่รออนุมัติ | FR-08b | Google หรือลิงก์อีเมลนอกโดเมนคณะสมัครได้ แต่ต้องให้ ADMIN ตรวจก่อนจึงใช้งานได้ | ✅ |
