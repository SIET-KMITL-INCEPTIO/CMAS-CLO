## 1. ข้อความสำหรับหัวข้อ 2.5.1 (แทนของเดิม)

> ของเดิมเขียนว่าวิธีนี้ "เหมาะสมสำหรับการให้ผู้ทรงคุณวุฒิประเมินระบบ" ซึ่งปนการทดสอบเข้ากับการประเมินคุณภาพ
> การทดลองใช้ของผู้ทรงคุณวุฒิย้ายไปอยู่ที่หัวข้อ 3.6.2 (แบบประเมิน Likert) ส่วนนี้เหลือแต่การทดสอบ

**2.5.1 การทดสอบแบบกล่องดำ (Black Box Testing)**

การทดสอบแบบกล่องดำ คือกระบวนการทดสอบซอฟต์แวร์ที่ออกแบบกรณีทดสอบจากข้อกำหนดความต้องการของระบบ
โดยพิจารณาเฉพาะข้อมูลนำเข้าและผลลัพธ์ที่สังเกตได้จากภายนอก ไม่คำนึงถึงโครงสร้างหรือกลไกการทำงานภายในของโปรแกรม
แต่ละกรณีทดสอบประกอบด้วยข้อมูลนำเข้าและผลที่คาดหวังซึ่งกำหนดไว้ล่วงหน้า เมื่อทดสอบแล้วจึงนำผลที่ได้มาเทียบกับ
ผลที่คาดหวังเพื่อตัดสินว่าผ่านหรือไม่ผ่าน เทคนิคที่ใช้ออกแบบกรณีทดสอบ ได้แก่ การแบ่งกลุ่มสมมูล (Equivalence
Partitioning) ซึ่งแบ่งข้อมูลนำเข้าเป็นกลุ่มที่ระบบต้องตอบสนองเหมือนกันแล้วเลือกตัวแทนกลุ่มละหนึ่งค่า การวิเคราะห์
ค่าขอบเขต (Boundary Value Analysis) ซึ่งเลือกค่าที่ขอบของแต่ละกลุ่มเนื่องจากข้อผิดพลาดมักเกิดที่ขอบของเงื่อนไข
และตารางการตัดสินใจ (Decision Table) ซึ่งใช้กับข้อกำหนดที่ผลลัพธ์ขึ้นกับหลายเงื่อนไขพร้อมกัน

ในโครงงานนี้ ได้นำการทดสอบแบบกล่องดำมาใช้ตรวจสอบว่าระบบทำงานตรงตามข้อกำหนดความต้องการเชิงหน้าที่ โดยคณะ
ผู้จัดทำออกแบบกรณีทดสอบ 50 กรณี ครอบคลุมการควบคุมสิทธิ์การเข้าถึงรายวิชา การจัดการรายวิชาและกิจกรรมประเมิน
การกรอกและนำเข้าคะแนนจากไฟล์ Excel การคำนวณระดับการบรรลุผลลัพธ์การเรียนรู้ และการตัดเกรด ผลที่คาดหวังของ
กรณีด้านการคำนวณได้จากการคำนวณด้วยมือตามสูตรในข้อกำหนดความต้องการของระบบ ผู้ทดสอบใช้งานผ่านหน้าจอของระบบ
โดยไม่เห็นซอร์สโค้ด และบันทึกผลที่ได้เทียบกับผลที่คาดหวังเป็นรายกรณี ดังรายละเอียดในหัวข้อ 3.6.1 ส่วนการทดลองใช้งาน
โดยผู้ทรงคุณวุฒิเป็นการประเมินคุณภาพของระบบ ไม่ใช่การทดสอบแบบกล่องดำ ซึ่งอธิบายไว้ในหัวข้อ 2.6 และ 3.6.2

## 2. ข้อความสำหรับหัวข้อ 3.6.1 ข้อ 2 (แทนของเดิม)

2. **การทดสอบแบบกล่องดำ (Black Box Testing)** คณะผู้จัดทำออกแบบกรณีทดสอบจากข้อกำหนดความต้องการเชิงหน้าที่
   ด้วยเทคนิคการแบ่งกลุ่มสมมูล การวิเคราะห์ค่าขอบเขต และตารางการตัดสินใจ รวม 50 กรณี แบ่งเป็น 7 กลุ่ม
   ตามตารางที่ 3.x ผลที่คาดหวังของกรณีด้านการคำนวณได้จากการคำนวณด้วยมือตามสูตรในหัวข้อ 3.3
   ส่วนกรณีด้านการนำเข้าไฟล์ใช้ไฟล์ทดสอบที่ระบุข้อผิดพลาดของแต่ละแถวไว้ล่วงหน้า
   ผู้ทดสอบใช้งานผ่านหน้าจอของระบบเท่านั้น และบันทึกผลที่ได้เทียบกับผลที่คาดหวังเป็นรายกรณี
   เกณฑ์ผ่านคือกรณีทดสอบทุกกรณีให้ผลตรงกับผลที่คาดหวัง

