## 1. ภาพรวมไทม์ไลน์

### 1.1 หมุดหมายจากกำหนดส่งรายงานความก้าวหน้า (ตัวตั้งของแผนนี้)

รายวิชากำหนดส่งรายงานความก้าวหน้า **4 ครั้ง** และแต่ละครั้งผูกกับ CLO หนึ่งข้อแบบหนึ่งต่อหนึ่ง
วันที่เหล่านี้เป็น **ข้อมูลจากภายนอก เลื่อนไม่ได้** — ทุกงานในแผนถูกจัดให้ชนวันเหล่านี้พอดี

| ครั้งที่ | วันส่ง | CLO ที่ถูกประเมิน | สิ่งที่ต้องมีให้ดูวันนั้น |
|---|---|---|---|
| 1 | ก.ค. 2026 ✅ | CLO 1 — ระบุปัญหา | Root Cause Analysis + Literature Review |
| 2 | **เสาร์ 15 ส.ค. 2026** | CLO 2 — ตั้งสมมติฐาน | H1–H7 ที่ sign-off แล้ว, เกณฑ์ประเมิน §3.1–3.3, แบบประเมิน, **baseline Excel** |
| 3 | **เสาร์ 26 ก.ย. 2026** | CLO 3 — ออกแบบสถาปัตยกรรม | ER-Diagram, DFD L0–L2, API contract, Design System + UI ครบ 13 หน้า, Route map |
| 4 | **เสาร์ 24 ต.ค. 2026** | CLO 4 — พัฒนาได้ **ตามแผน** | ระบบที่รันได้จริงจบ Sprint 1–3 (Auth/RBAC · Course · CLO & Objectives) + หลักฐานว่าเดินตาม Gantt |

> **ครั้งที่ 4 ไม่ใช่วันจบ CLO 4** — ถ้อยคำของ CLO 4 คือ "พัฒนาโครงงานตามสถาปัตยกรรมที่ออกแบบ
> **ได้ตามแผน**" สิ่งที่ถูกประเมินจึงเป็น *ความสอดคล้องกับแผน* ไม่ใช่ความครบของฟีเจอร์
> การพัฒนาเดินต่อถึง 24 ม.ค. 2027 ตามเดิม และ **ไม่มีรายงานความก้าวหน้าหลังครั้งที่ 4**
> CLO 5 จึงกำหนดวันเอง โดยจบที่วันสอบป้องกัน

### 5.2 ค่าที่คำนวณอัตโนมัติ (ไม่ต้องกรอกมือ)

- **แถว CLO 1–5** — ช่วงเวลา ระยะเวลา ผู้รับผิดชอบ และร้อยละ คำนวณจากงานลูกทั้งหมด
  ร้อยละ = ค่าเฉลี่ย**ถ่วงน้ำหนักด้วยจำนวนวัน**ของ *งานหลัก (เลข 2 ระดับ)* เท่านั้น
  ไม่นับงานย่อยซ้ำ มิฉะนั้นงานที่ซอยละเอียดจะมีน้ำหนักเกินจริง
- **ระยะเวลา** = วันที่ต้องเสร็จ − วันที่เริ่ม (วันตามปฏิทิน) งานหมุดหมายวันเดียวจึงเป็น `0`
- **แถบ `█`** — เติมในสัปดาห์ที่ช่วงวันของงานคาบเกี่ยว (สัปดาห์ 1 = วันที่ 1–7 · สัปดาห์ 4 = วันที่ 22–สิ้นเดือน)

### 5.3 การตรวจความถูกต้อง

สคริปต์จะ **ไม่เขียนไฟล์** ถ้าตรวจพบข้อใดข้อหนึ่งต่อไปนี้ และจะพิมพ์เลขงานที่ผิดออกมา:

| ตรวจ | เงื่อนไขที่ต้องผ่าน |
|---|---|
| รูปแบบวันที่ | `ด/ว/ป` ค.ศ. สองหลัก และวันเสร็จต้องไม่มาก่อนวันเริ่ม |
| ระยะเวลา | ต้องเท่ากับผลต่างของวันที่จริง |
| ผู้รับผิดชอบ | ต้องเป็น ธ / น / นู เท่านั้น |
| ลำดับชั้น | งานย่อยต้องอยู่ในกรอบเวลาของงานหลัก **และ** งานหลักต้องกว้างเท่ากรอบของงานย่อยพอดี |

ข้อสุดท้ายคือข้อที่จับ error ได้จริงบ่อยที่สุด — ถ้าเพิ่มงานย่อยแล้วลืมขยายงานหลัก จะไม่ผ่าน

เปิดด้วย Excel → **Data → From Text/CSV → File Origin: UTF-8** เพื่อไม่ให้ภาษาไทยเพี้ยน

สร้างไฟล์ใหม่ทุกครั้งที่แก้แผนในเอกสารนี้ (ห้ามแก้ CSV ตรง ๆ — จะถูกเขียนทับ):

```bash
npm run plan:csv
```
