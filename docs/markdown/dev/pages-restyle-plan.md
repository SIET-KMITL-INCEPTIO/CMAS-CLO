### 0.1 ข้อขัดแย้งในแผนเดิม — เฟส 1 กับข้อจำกัด "ไฟล์เดียว"

แผนเดิมสั่งว่า *"ให้ `index-q.html` เลิกถือโทเคนของตัวเองแล้วมาอ้างไฟล์ร่วมแทน"*
แต่ `index-q.html` เป็น**ต้นแบบไฟล์เดียวที่ต้องส่งต่อทางอีเมลและเปิดจาก `file://` ได้** ซึ่งเป็นข้อจำกัดที่ยืนมาตลอดทุกรอบ
การผูกกับ CSS ภายนอกทำลายข้อนั้นเพื่อความสวยงามของโครงสร้างอย่างเดียว

**ตัดสิน:** ชั้น CSS ร่วมมีไว้สำหรับ **4 หน้าเอกสาร** · `index-q.html` ถือสำเนาของตัวเองต่อไป
ปัญหาที่แท้จริงของการคัดลอกคือ **การเลื่อนไถลโดยไม่มีใครรู้** จึงแก้ด้วย
`scripts/check-design-tokens.py` ที่ล้มเมื่อค่าโทเคนในสองที่ไม่ตรงกัน — ได้ประโยชน์ของแหล่งความจริงเดียวโดยไม่เสียข้อจำกัด

### 0.2 ตัดสิน §6 แล้ว — `design-system-preview.html`

เลือก **ทางเลือก ข.** ตามที่แผนเสนอ: ติดแถบ "เอกสารนี้บันทึกระบบ Verdure ซึ่งเลิกใช้แล้ว"
เหตุผลที่ตัดสินเองได้โดยไม่ต้องรอ: **ย้อนกลับได้ทันที ไม่ทำลายอะไร และหยุดความเข้าใจผิดได้เดี๋ยวนี้**
ทางเลือก ก. (เขียนใหม่เป็น Nocturnal Atelier) ยังเปิดอยู่เสมอเมื่อ UI นิ่ง

### 0.3 ป้องกันการเลื่อนไถลของเนื้อหา ไม่ใช่แค่แก้ครั้งเดียว

`database-preview.html` ผิดเพราะ schema เปลี่ยนแล้วไม่มีใครรู้ว่าหน้านี้ต้องตามด้วย

`database/schema.prisma` แล้วล้มถ้าไม่ตรง — ครั้งหน้าที่ schema ขยับ จะมีคนรู้

**อาการที่เห็นตรงกันทั้ง 4 หน้าเก่า**

2. **ไม่มีคำตอบอยู่บนสุด** — ทุกหน้าเปิดด้วยหัวเรื่องแล้วเข้าเนื้อหายาวทันที ผู้อ่านต้องเลื่อนหาเองว่าตัวเลขสำคัญคืออะไร
3. **คำตัดสินอยู่ในประโยค ไม่ใช่ป้าย** — เช่น "เหมาะสม" / "มีความเสี่ยง" ฝังอยู่ในย่อหน้า กวาดสายตาหาไม่เจอ

## 2. สิ่งที่พบและต้องแก้ก่อนจัดสไตล์

### 2.1 `database-preview.html` เนื้อหาไม่ตรง schema (สำคัญที่สุด)

ตรวจกับ `database/schema.prisma` (v4, 13 models) พบว่า

| รายการ | ในหน้า | ใน schema จริง |
|---|---:|---|
| `Curriculum` | กล่าวถึง **11 ครั้ง ใน 7 บรรทัด** ในฐานะตารางที่ใช้งานจริง | **ถูกตัดออก** ตามมติ 2.7 (2026-08-04) |
| `GradeBand` | **0** | มีอยู่ — ขั้นบันไดเกรดของรายวิชา |
| `StudentGrade` | **0** | มีอยู่ — เกรดที่ตรึงไว้ + เหตุผลการปรับ |

หน้านี้ถูกแก้ครั้งสุดท้าย **16 ก.ค.** ซึ่งเก่ากว่ามติ 2.7 (4 ส.ค.) และเก่ากว่าการเพิ่มระบบตัดเกรด (23 ส.ค.) กับการยุบ `GradeScheme`/`GradeRun` (6 ก.ย.)

**13 model ที่ต้องมีครบ** (จาก `schema.prisma`)

```
User · Course · CourseInstructor · CLO · BehavioralObjective · Activity
AssessmentCriteria · ObjectiveAssessment · Student · Score · ScoreUploadLog
GradeBand · StudentGrade
```

> **ข้อสรุป:** ห้ามจัดสไตล์หน้านี้ก่อนแก้เนื้อหา — การทำให้ข้อมูลที่ผิดดูน่าเชื่อถือขึ้น แย่กว่าปล่อยให้มันดูเก่า

### 2.2 อีกสองหน้าเนื้อหายังใช้ได้

`evaluation-criteria.html` และ `tech-stack-review.html` ไม่มีการอ้างถึง `Curriculum` / `Institution` เลย และ tech-stack อ้าง PostgreSQL + Prisma ตรงกับ datasource จริง — **สองหน้านี้แก้แค่สไตล์กับการจัดลำดับข้อมูลพอ**

## 3. ภาษาออกแบบเป้าหมาย

ยึดตามที่ `index-q.html` ใช้อยู่จริงตอนนี้ ไม่ใช่ตามเอกสาร `design-system.md` ซึ่งยังเขียนถึง Verdure

> **เรื่อง "ญี่ปุ่น" — ตัดสินไปแล้ว ไม่ต้องถามซ้ำ**
> คำขอ "remove the Japanese language" (รอบก่อน) กับ "design feel engineering and japan" (รอบนี้) ไม่ขัดกัน:
> **เอา*ตัวอักษร*ญี่ปุ่นออก · เก็บ*สุนทรียะ*วิศวกรรมแบบญี่ปุ่นไว้**
> คือความยับยั้งชั่งใจ เส้นบาง ระยะที่แม่นยำ ตัวเลขเรียงหลัก และการใช้สีเท่าที่จำเป็น — ไม่ใช่คันจิ

### 3.1 สี — Nocturnal Atelier

```
หลัก (UI ข้อความ พื้นผิว)   #C8CDEB · #878CB4 · #465078 · #1E233C · #0A0F19
พื้นผิวสว่าง                 #FFFFFF card · #FAFAFC content · #F7F7FB list · #F4F5FA wash
เส้น                         #EDEEF6 hairline · #E4E5F0 edge
สถานะ (ลดความอิ่มตัวแล้ว)     ผ่าน #4F7C68 · เตือน #96793D · ไม่ผ่าน #A2504F
```

**สีใช้บอกคำตัดสินเท่านั้น** ห้ามใช้ตกแต่ง — กฎนี้คือสิ่งที่ทำให้หน้าจอดู "วิศวกรรม" มากกว่ารายละเอียดอื่นใด

## 4. หลักการ "ข้อมูลสำคัญขึ้นก่อน"

ใช้กับทุกหน้าเอกสาร รูปแบบเดียวกันหมด

### 4.1 แถบคำตอบ (answer bar) — บังคับทุกหน้า

วางใต้หัวเรื่องทันที **ก่อน**เนื้อหาใด ๆ บรรจุ **3–5 ตัวเลขหรือคำตัดสิน** ที่ตอบคำถามหลักของหน้านั้น

| หน้า | สิ่งที่ต้องอยู่ในแถบคำตอบ |
|---|---|
| `evaluation-criteria` | จำนวนผู้ประเมิน · จำนวนข้อประเมิน (ก./ข.) · เกณฑ์ผ่าน · สถิติที่ใช้ |
| `tech-stack-review` | จำนวนเทคโนโลยีที่ประเมิน · จำนวนที่ "เหมาะสม" · จำนวนที่ "มีความเสี่ยง" · ข้อสรุปหนึ่งบรรทัด |
| `database-preview` | จำนวน model (13) · จำนวนความสัมพันธ์ · จำนวน constraint/trigger · เวอร์ชัน schema |

### 4.2 กฎรายหัวข้อ

1. **หนึ่งหัวข้อ = หนึ่งคำถาม** และ**บรรทัดแรกต้องตอบคำถามนั้น** ไม่ใช่เกริ่นนำ
2. **คำตัดสินเป็นป้าย ไม่ใช่ประโยค** — `เหมาะสม` / `มีความเสี่ยง` / `ต้องตัดสินใจ` เป็น chip สีตามสถานะ
3. **อะไรที่เป็นการเปรียบเทียบ ต้องเป็นตาราง** ไม่ใช่ย่อหน้า
4. **มีบรรทัด "ทำอะไรต่อ"** ในหัวข้อที่ต้องมีการตัดสินใจ
5. **คำอธิบายยาวเก็บใน `<details>`** — เปิดดูได้ ไม่กินพื้นที่หน้าหลัก (แนวเดียวกับปุ่ม `?` ใน `index-q.html`)

### 4.3 สารบัญ

TOC ติดขอบซ้าย + **scroll-spy** บอกว่าอ่านถึงไหน (ปัจจุบัน `evaluation-criteria` กับ `tech-stack-review` มี TOC แต่ไม่มี scroll-spy · `database-preview` ไม่มี TOC เลย)

หนึ่งเฟส = หนึ่งสาขา (branch) จัดกลุ่มตาม**สิ่งที่เฟสถัดไปต้องใช้** ไม่ใช่ตามหัวข้อ

### เฟส 1 · ชั้นออกแบบร่วม — `docs/pages/cmas-pages.css`
**สาขา:** `feat/pages-shared-design-layer` · **ขนาด:** M

สร้างไฟล์ CSS เดียวที่ทั้ง 5 หน้าใช้ร่วมกัน จบปัญหาโทเคน 3 ชุดที่คัดลอกกันไว้ และดึงหน้าที่หลุดออกนอกระบบกลับเข้ามา

> **เฟสนี้ต้องมาก่อนทุกเฟส** เพราะทุกเฟสหลังบริโภคโทเคนจากที่นี่ — ถ้าทำทีหลังจะต้องรื้อสไตล์ที่เพิ่งเขียนไป

**ผ่านเมื่อ:** `index-q.html` หน้าตาเหมือนเดิมทุกประการหลังย้ายไปใช้ไฟล์ร่วม · เปิดจาก `file://` ได้โดยไม่ต้องมีเซิร์ฟเวอร์

### บั๊กที่การตรวจรับจับได้ และไม่มีทางเห็นถ้าไม่เปิดเบราว์เซอร์จริง

1. **สารบัญบนจอแคบเปิดไม่ออก** — `body[data-toc="open"] .toc` specificity สูงกว่าและ selector ก็ตรง
   (พิสูจน์ด้วยการยิงกฎ `outline` ทดสอบเข้าไปแล้วติด) แต่ declaration `transform` กลับไม่ชนะจริง
   · หยุดวินิจฉัยหลังพยายามสามครั้งตามกฎ แล้วแก้เชิงโครงสร้าง: ย้ายสถานะไปเป็นคลาสบนตัว `.toc` เอง
2. **`design-system-preview` ล้นแนวนอนทุกความกว้างต่ำกว่า 1080** — `.main{max-width:1080px}` ไม่มี `min-width:0`
   · เป็นบั๊กเดิม ไม่ใช่ผลจากแถบที่เพิ่ง เพิ่ม แต่แก้เพราะเป็นกฎเดียวและอยู่ในหน้าที่เพิ่งแตะ

### เครื่องมือวัดพลาดเอง 2 ครั้ง ก่อนที่โค้ดจะพลาด

- `s.click()` บนฉากหลังไม่ bubble แบบที่คาด ทำให้คิดว่าปิดสารบัญไม่ได้ — `dispatchEvent` พิสูจน์ว่าใช้ได้
- `window.scrollTo()` ถูกเพิกเฉยใน emulated viewport ทำให้คิดว่า scroll-spy ไม่ทำงาน — เลื่อนด้วย input จริงแล้วถูกต้อง

**บทเรียนเดิมที่ยังจริง:** ยืนยันกับข้อมูล อย่ายืนยันกับสถานะของเครื่องมือทดสอบ
