1. วัตถุประสงค์ของโครงงาน (Objectives)

รหัส วัตถุประสงค์ ที่มา
OBJ-1 เพื่อพัฒนาระบบสารสนเทศสำหรับบันทึกและติดตามผลลัพธ์การเรียนรู้ที่คาดหวังระดับรายวิชา (CLO) ตามหลักสูตร ค.อ.บ. สาขาวิชาเทคโนโลยีคอมพิวเตอร์ (ปรับปรุง พ.ศ. 2567) srs §1.2 · UC2, UC3
OBJ-2 เพื่อออกแบบกลไกเชื่อมโยงกิจกรรมการประเมิน (Activity) เข้ากับ CLO พร้อมน้ำหนักรายคู่ และคำนวณระดับการบรรลุ CLO โดยอัตโนมัติ srs §3 (CR-01…CR-05) · UC5, UC6
OBJ-3 เพื่อลดภาระงานและข้อผิดพลาดจากการรวบรวม/คำนวณคะแนนด้วยมือผ่าน Excel ของอาจารย์ผู้สอน srs §1.2 · UC7
OBJ-4 เพื่อพัฒนาเครื่องมือรายงานผลระดับรายวิชาและรายบุคคล ที่ระบุนักศึกษากลุ่มเสี่ยง (at-risk) ได้ภายในภาคการศึกษา ไม่ใช่หลังจบเทอม srs FR-83, FR-85 · UC9, UC10
OBJ-5 เพื่อประเมินประสิทธิภาพและความพึงพอใจของระบบจากผู้เชี่ยวชาญและผู้ใช้จริง มาตรฐานการประเมินโครงงาน

ขอบเขตที่ตัดออกแล้ว (ห้ามเขียนเป็นวัตถุประสงค์)

รายการ เหตุผล
PLO / มคอ.2 mapping ระดับหลักสูตร นอกขอบเขต v1 และ ER v3 ไม่มีตาราง Program ให้ PLO เกาะ
การจัดการหลักสูตร (Curriculum) ตัดออกจาก ER v3 — สูงสุดของลำดับชั้นคือ Course
รองรับหลายสถาบัน (multi-tenant) ตัดออกจาก ER v3 — ระบบเป็น single-tenant (คณะเดียว)
ระบบลงทะเบียนเรียน / ตัดเกรดทางการ / เชื่อม REG นอกขอบเขต srs §1.2

2. สมมติฐานของการจัดทำโครงงาน

สภาพปัญหา (root cause): ปัจจุบันไม่มีระบบติดตามและประเมินผลลัพธ์การเรียนรู้ เป็นรายบุคคล อาจารย์ผู้สอนรวบรวมคะแนนด้วย Excel แยกไฟล์ตามกิจกรรม จึงทราบว่านักศึกษาคนใดไม่บรรลุ CLO ข้อใด ก็ต่อเมื่อสิ้นภาคการศึกษาไปแล้ว ซึ่งสายเกินกว่าจะแทรกแซงช่วยเหลือนักศึกษาคนนั้นได้ทัน

ฉบับใช้ในเล่ม (รูปแบบย่อหน้า)

เมื่อพัฒนาระบบติดตามและประเมินผลลัพธ์การเรียนรู้ที่คาดหวังระดับรายวิชานี้แล้ว อาจารย์ผู้สอนสามารถบันทึกคะแนนรายกิจกรรม เชื่อมโยงกิจกรรมเข้ากับผลลัพธ์การเรียนรู้ ที่คาดหวัง (CLO) พร้อมน้ำหนัก และติดตามผลการบรรลุ CLO ของนักศึกษาได้ เป็นรายบุคคลตั้งแต่ระหว่างภาคการศึกษา ทราบได้ว่านักศึกษาคนใดยังไม่บรรลุ CLO ข้อใด จนสามารถนำผลไปใช้ปรับปรุงการจัดการเรียนการสอนและช่วยเหลือนักศึกษากลุ่มเสี่ยง ได้จริง โดยระบบนี้จะผ่านการประเมินจากผู้ทรงคุณวุฒิในระดับผลการประเมิน ดี ขึ้นไป

ตัวชี้วัดที่ใช้พิสูจน์สมมติฐานข้างต้น

ย่อหน้าข้างบนคือสิ่งที่เขียนลงเล่ม ส่วนตารางนี้คือสิ่งที่ต้องวัดจริงเพื่อยืนยันว่า ย่อหน้านั้นเป็นจริง — แต่ละข้อผูกกับเกณฑ์การประเมินใน §3

รหัส ตัวชี้วัด ผูกกับ วิธีพิสูจน์
H1 ระบบคำนวณระดับการบรรลุ CLO (CR-03, CR-04) และคะแนนรวมรายวิชา (CR-05) ได้ผลลัพธ์ตรงกับการคำนวณด้วยมือ 100% รวมกรณีขอบ (ไม่มีคะแนน · คะแนนบางส่วน · น้ำหนักไม่ครบ 100 · maxScore ต่างกัน · CLO ที่ไม่มีกิจกรรมวัด) OBJ-2 Unit test ตาม NFR-14 + เทียบใบคำนวณมือที่อาจารย์ตรวจรับ
H2 ระบบแสดงผลการบรรลุ CLO รายบุคคล ได้ตั้งแต่มีคะแนนกิจกรรมแรก โดยไม่ต้องรอให้กรอกคะแนนครบทุกกิจกรรม — คือหัวใจที่ตอบ root cause โดยตรง OBJ-4 ทดสอบด้วยชุดข้อมูลที่กรอกคะแนนเพียงบางกิจกรรม แล้วตรวจว่าระบบระบุ at-risk ได้ถูกต้อง
H3 กลไกตรวจสอบไฟล์นำเข้า (FR-67, FR-69) ตรวจจับข้อผิดพลาดที่พบบ่อยได้ ไม่น้อยกว่า 95% OBJ-3 ชุดทดสอบไฟล์ Excel ที่จงใจใส่ข้อผิดพลาด 6 ประเภทตาม FR-69
H4 ระบบมีประสิทธิภาพผ่านเกณฑ์ srs §6 ทุกข้อ ที่ขนาดข้อมูล 1 วิชา / 200 นักศึกษา / 20 กิจกรรม OBJ-1, OBJ-4 NFR-01, NFR-02, NFR-03
H5 ผู้ทรงคุณวุฒิประเมินคุณภาพระบบโดยรวมอยู่ในระดับ ดี ขึ้นไป (ค่าเฉลี่ย ≥ 3.51) — ข้อนี้คือประโยคสุดท้ายของสมมติฐานโดยตรง OBJ-5 แบบประเมินผู้ทรงคุณวุฒิ (Black Box)
H6 ผู้ใช้ (อาจารย์ผู้สอน) มีความพึงพอใจอยู่ในระดับ ดี ขึ้นไป (ค่าเฉลี่ย ≥ 3.51) OBJ-5 แบบสอบถามความพึงพอใจ
H7 อาจารย์ที่ไม่เคยใช้ระบบมาก่อน นำเข้าคะแนนจนสำเร็จได้ภายใน 10 นาที โดยไม่ต้องใช้คู่มือ OBJ-3, OBJ-5 ทดสอบ usability ตาม NFR-09

3. เกณฑ์การประเมิน (Evaluation Criteria)

การประเมินแบ่งเป็น 3 ด้าน ตามลักษณะของสิ่งที่วัด — ด้านที่ 1-2 วัดด้วยตัวเลข ที่ระบบให้ได้เอง ด้านที่ 3 วัดด้วยแบบสอบถาม

3.1 ด้านความถูกต้องเชิงฟังก์ชัน (Functional Correctness)

ประเมินโดย ผู้พัฒนา + ผู้เชี่ยวชาญ 3–5 คน ด้วยวิธี Black Box Testing

รายการประเมิน เกณฑ์ผ่าน อ้างอิง
ความถูกต้องของสูตรคำนวณ CLO (CR-02, CR-03) ตรงกับการคำนวณด้วยมือ 100% H1 · NFR-14
ความถูกต้องของ attainment ระดับวิชา (CR-04) ตรงกับการคำนวณด้วยมือ 100% H1
ความถูกต้องของคะแนนรวมและสถานะนักศึกษา (CR-05) ตรงกับการคำนวณด้วยมือ 100% H1
การจัดการกรณีขอบ: ไม่มีคะแนน → แสดง — ไม่ใช่ 0 ผ่านทุกกรณี FR-84 · OI-12
การติดตามรายบุคคลระหว่างเทอม — ระบุได้ว่านักศึกษาคนใดไม่บรรลุ CLO ข้อใด เมื่อกรอกคะแนนเพียงบางกิจกรรม ระบุ at-risk ได้ถูกต้อง 100% เทียบใบคำนวณมือ H2 · FR-83, FR-85
การตรวจสอบไฟล์นำเข้า (6 ประเภทข้อผิดพลาด) ตรวจจับได้ ≥ 95% H3 · FR-69
การบังคับสิทธิ์: INSTRUCTOR เข้าถึงเฉพาะวิชาที่ถูกมอบหมาย ยิง API ตรงด้วย id วิชาอื่น ต้องได้ 404 NFR-07
ความครบถ้วนของฟังก์ชันตาม FR ระดับ MUST ทำงานได้ครบ 100% srs §4

3.2 ด้านประสิทธิภาพ (Performance)

วัดที่ขนาดข้อมูล 1 รายวิชา / 200 นักศึกษา / 20 กิจกรรม

รายการประเมิน เกณฑ์ผ่าน อ้างอิง
เวลาแสดงผลหน้าที่มีตาราง < 2 วินาที NFR-01
เวลาคำนวณ attainment ของ 1 รายวิชา < 1 วินาที และไม่เกิด N+1 query NFR-02
เวลานำเข้าไฟล์ 500 แถว < 10 วินาที NFR-03
เวลาที่ผู้ใช้ใหม่นำเข้าคะแนนสำเร็จ (ไม่ใช้คู่มือ) ≤ 10 นาที NFR-09 · H7

3.3 ด้านประสิทธิภาพของระบบและความพึงพอใจของผู้ใช้ (System Efficiency & User Satisfaction)

ใช้เครื่องมือ แบบมาตราส่วนประมาณค่า 5 ระดับ (Rating Scale / Likert Scale) จำนวน 2 ฉบับ คือ (ก) แบบประเมินประสิทธิภาพของระบบสำหรับผู้เชี่ยวชาญ และ (ข) แบบสอบถามความพึงพอใจ สำหรับผู้ใช้จริง — ทั้งสองฉบับใช้มาตรวัดและเกณฑ์แปลผลชุดเดียวกัน (§3.3.4–3.3.5)

3.3.1 กลุ่มผู้ประเมินและวิธีเลือก

กลุ่ม จำนวน วิธีเลือก ประเมินอะไร เครื่องมือ
ผู้เชี่ยวชาญด้านระบบสารสนเทศ / อาจารย์ที่ปรึกษา 3–5 คน เลือกแบบเจาะจง (purposive) — มีประสบการณ์ด้านการพัฒนาระบบหรือการวัดผลการเรียนรู้ ≥ 3 ปี ประสิทธิภาพของระบบ 4 ด้าน ด้วยวิธี Black Box Testing แบบประเมิน ก.
อาจารย์ผู้สอน (ผู้ใช้จริง) 15–30 คน เลือกแบบเจาะจงจากอาจารย์ผู้สอนในหลักสูตร ที่ได้ทดลองใช้ระบบจริงอย่างน้อย 1 รายวิชา ความพึงพอใจในการใช้งานจริง 5 ด้าน แบบสอบถาม ข.

ถ้าผู้ใช้จริงไม่ถึง 15 คน ให้ทำตามข้อเสนอใน E-05 (§5) คือเสริมด้วยการสัมภาษณ์เชิงคุณภาพ และรายงานขนาดกลุ่มตัวอย่างจริงตามตรงในเล่ม

3.3.2 แบบประเมิน ก. — ประสิทธิภาพของระบบ (ผู้เชี่ยวชาญ, 20 ข้อ)

ด้าน ข้อ ข้อคำถาม อ้างอิง
1. ด้านตรงตามความต้องการของผู้ใช้ (Functional Requirement Test) — 5 ข้อ 1.1 ระบบจัดการข้อมูลรายวิชา · CLO · กิจกรรมการประเมิน ได้ครบตามที่ออกแบบ FR MUST · srs §4
1.2 ระบบเชื่อมโยงกิจกรรมการประเมินเข้ากับ CLO พร้อมกำหนดน้ำหนักรายคู่ได้ OBJ-2 · CR-01
1.3 ระบบนำเข้าคะแนนจากไฟล์ Excel และแจ้งข้อผิดพลาดของไฟล์ได้ FR-67, FR-69
1.4 ระบบรายงานผลการบรรลุ CLO ทั้งระดับรายวิชาและรายบุคคลได้ FR-83, FR-85
1.5 ระบบระบุนักศึกษากลุ่มเสี่ยง (at-risk) ได้ตั้งแต่ระหว่างภาคการศึกษา OBJ-4 · H2
2. ด้านการทำงานตามหน้าที่ของระบบ (Functional Test) — 5 ข้อ 2.1 ผลการคำนวณระดับการบรรลุ CLO ถูกต้องตรงตามสูตรที่กำหนด CR-02, CR-03 · H1
2.2 ผลการคำนวณคะแนนรวมและสถานะของนักศึกษาถูกต้อง CR-05 · H1
2.3 ระบบจัดการกรณีข้อมูลไม่ครบได้เหมาะสม (ไม่มีคะแนน → แสดง — ไม่ใช่ 0) FR-84 · OI-12
2.4 การเพิ่ม / แก้ไข / ลบข้อมูล ให้ผลลัพธ์ถูกต้องและข้อมูลคงความสอดคล้อง §3.1
2.5 ระบบทำงานได้ต่อเนื่องไม่หยุดชะงักหรือแสดงข้อผิดพลาดที่ไม่คาดคิด §3.1
3. ด้านการใช้งานของระบบ (Usability Test) — 5 ข้อ 3.1 การจัดวางเมนูและลำดับขั้นตอนการใช้งานเข้าใจง่าย NFR-09
3.2 รูปแบบตัวอักษร สี และขนาดที่ใช้ อ่านง่ายและเหมาะสม NFR-09
3.3 ข้อความแจ้งเตือน / ข้อผิดพลาดเป็นภาษาไทยที่เข้าใจได้และบอกวิธีแก้ไข NFR-09
3.4 รายงานและกราฟสรุปผลอ่านเข้าใจได้โดยไม่ต้องตีความเพิ่ม FR-83
3.5 ผู้ใช้ใหม่สามารถเรียนรู้การใช้งานได้เองโดยไม่ต้องใช้คู่มือ NFR-09 · H7
4. ด้านความปลอดภัยของระบบ (Security Test) — 5 ข้อ 4.1 ระบบตรวจสอบสิทธิ์การเข้าใช้งาน (authentication) ได้ถูกต้อง NFR-05
4.2 การกำหนดสิทธิ์ตามบทบาท (ADMIN / INSTRUCTOR) เหมาะสมกับหน้าที่ NFR-06
4.3 ผู้ใช้ไม่สามารถเข้าถึงข้อมูลรายวิชาที่ไม่ได้รับมอบหมายได้ NFR-07
4.4 ระบบป้องกันข้อมูลที่ไม่ถูกต้องจากฝั่งผู้ใช้ก่อนบันทึกลงฐานข้อมูล NFR-08 · Zod
4.5 ระบบบันทึกร่องรอยการแก้ไขข้อมูลสำคัญเพื่อการตรวจสอบย้อนหลัง srs §5

3.3.3 แบบสอบถาม ข. — ความพึงพอใจของผู้ใช้ (อาจารย์ผู้สอน, 20 ข้อ)

ด้าน ข้อ ข้อคำถาม
1. ด้านความสามารถทำงานตามความต้องการ — 4 ข้อ 1.1 ระบบช่วยให้บันทึกและจัดการคะแนนรายกิจกรรมได้สะดวก
1.2 ระบบช่วยให้เชื่อมโยงกิจกรรมกับ CLO ได้ตรงกับที่ออกแบบรายวิชาไว้
1.3 ระบบมีฟังก์ชันครบตามที่ต้องใช้ในการติดตามผลลัพธ์การเรียนรู้
1.4 ระบบตอบโจทย์การใช้งานได้ดีกว่าการทำด้วย Excel แบบเดิม
2. ด้านความถูกต้องของผลลัพธ์ — 4 ข้อ 2.1 ผลการคำนวณการบรรลุ CLO ตรงกับที่คาดหวัง
2.2 คะแนนรวมและสถานะของนักศึกษาถูกต้องน่าเชื่อถือ
2.3 รายงานผลรายบุคคลสะท้อนสถานะจริงของนักศึกษา
2.4 ข้อมูลที่บันทึกไว้ไม่สูญหายหรือคลาดเคลื่อน
3. ด้านความง่ายในการใช้งาน — 4 ข้อ 3.1 ขั้นตอนการใช้งานไม่ซับซ้อน เรียนรู้ได้เร็ว
3.2 หน้าจอและเมนูออกแบบเข้าใจง่าย หาสิ่งที่ต้องการเจอ
3.3 การนำเข้าคะแนนจากไฟล์ Excel ทำได้ง่าย
3.4 ข้อความแจ้งข้อผิดพลาดช่วยให้แก้ไขได้ด้วยตนเอง
4. ด้านประสิทธิภาพและความรวดเร็ว — 4 ข้อ 4.1 ระบบตอบสนองรวดเร็ว ไม่ต้องรอนาน
4.2 การแสดงรายงานและกราฟทำได้รวดเร็ว
4.3 ระบบช่วยลดเวลาในการรวบรวมและคำนวณคะแนนเมื่อเทียบกับวิธีเดิม
4.4 ระบบช่วยลดข้อผิดพลาดจากการคำนวณด้วยมือ
5. ด้านประโยชน์ที่ได้รับ — 4 ข้อ 5.1 ทราบได้เร็วขึ้นว่านักศึกษาคนใดยังไม่บรรลุ CLO ข้อใด
5.2 นำผลจากระบบไปใช้ช่วยเหลือนักศึกษากลุ่มเสี่ยงได้ทันภายในภาคการศึกษา
5.3 นำผลจากระบบไปใช้ปรับปรุงการจัดการเรียนการสอนได้
5.4 มีความพึงพอใจต่อระบบในภาพรวมและต้องการใช้งานต่อไป

ท้ายแบบสอบถามมีข้อเสนอแนะปลายเปิด 1 ข้อ (ไม่นำมาคิดค่าเฉลี่ย ใช้รายงานเชิงคุณภาพ)

3.3.4 เกณฑ์การให้คะแนน 5 ระดับ

ระดับคะแนน ความหมาย (แบบประเมินประสิทธิภาพ) ความหมาย (แบบสอบถามความพึงพอใจ)
5 ระบบมีประสิทธิภาพในระดับ ดีมาก พึงพอใจ มากที่สุด
4 ระบบมีประสิทธิภาพในระดับ ดี พึงพอใจ มาก
3 ระบบมีประสิทธิภาพในระดับ ปานกลาง พึงพอใจ ปานกลาง
2 ระบบมีประสิทธิภาพในระดับ น้อย (ควรปรับปรุง) พึงพอใจ น้อย
1 ระบบมีประสิทธิภาพในระดับ น้อยที่สุด (ต้องแก้ไข) พึงพอใจ น้อยที่สุด

3.3.6 สถิติที่ใช้

สถิติ ใช้กับ สูตร / หมายเหตุ
ค่าเฉลี่ย (x̄) คะแนนรายข้อ · รายด้าน · ภาพรวม x̄ = Σx / n
ส่วนเบี่ยงเบนมาตรฐาน (S.D.) คะแนนรายข้อ · รายด้าน · ภาพรวม รายงานคู่กับค่าเฉลี่ยทุกตาราง
ค่า IOC ตรวจความตรงเชิงเนื้อหาของข้อคำถาม IOC = ΣR / n โดยผู้เชี่ยวชาญให้คะแนน +1 / 0 / −1
ค่าสัมประสิทธิ์แอลฟาของครอนบาค (α) ความเชื่อมั่นของแบบสอบถาม ข. ทดลองใช้ (try-out) กับผู้ที่ไม่ใช่กลุ่มตัวอย่าง 10 คน

3.3.7 เกณฑ์การตัดสิน

เกณฑ์ ค่าที่ต้องได้ ผูกกับ
ค่าเฉลี่ยประสิทธิภาพของระบบโดยรวม (ผู้เชี่ยวชาญ) ≥ 3.51 (ระดับดีขึ้นไป) H5
ค่าเฉลี่ยความพึงพอใจโดยรวม (ผู้ใช้จริง) ≥ 3.51 (ระดับมากขึ้นไป) H6
ค่าเฉลี่ยรายด้าน — ทุกด้านของทั้งสองฉบับ ≥ 3.51 (ไม่มีด้านใดต่ำกว่า) H5, H6
ส่วนเบี่ยงเบนมาตรฐานรายด้าน < 1.00 (ความเห็นสอดคล้องกัน) —
ค่า IOC รายข้อ ≥ 0.50 จากผู้เชี่ยวชาญ 3 คน ข้อที่ต่ำกว่าต้องปรับหรือตัดทิ้ง คุณภาพเครื่องมือ
ค่าความเชื่อมั่น α ของแบบสอบถาม ข. ≥ 0.70 คุณภาพเครื่องมือ

สรุปเกณฑ์ผ่านของโครงงาน: ค่าเฉลี่ยรวมของทั้งผู้เชี่ยวชาญและผู้ใช้ ≥ 3.51 (ระดับดี) และไม่มีด้านใดด้านหนึ่งต่ำกว่า 3.51 — ตรงกับประโยคสุดท้ายของสมมติฐาน §2

4. ตารางสรุปความเชื่อมโยง วัตถุประสงค์ → สมมติฐาน → เกณฑ์

วัตถุประสงค์ สมมติฐาน เกณฑ์การประเมิน
OBJ-1 พัฒนาระบบติดตาม CLO H4 §3.1 (ความครบถ้วน FR MUST) · §3.2 (NFR-01)
OBJ-2 กลไกเชื่อม Activity ↔ CLO และคำนวณอัตโนมัติ H1 §3.1 (ความถูกต้องสูตร 100%) · §3.2 (NFR-02)
OBJ-3 ลดภาระและข้อผิดพลาดจากการทำมือ H3, H7 §3.1 (ตรวจจับ error ≥ 95%) · §3.2 (NFR-03, NFR-09)
OBJ-4 รายงานผลและระบุ at-risk รายบุคคลภายในเทอม H2, H4 §3.1 (แสดงผลรายบุคคลเมื่อคะแนนยังไม่ครบ · กรณีขอบ) · §3.2 (NFR-01)
OBJ-5 ประเมินประสิทธิภาพและความพึงพอใจ H5, H6 §3.3 (ค่าเฉลี่ย ≥ 3.51 ทั้งสองกลุ่ม)

5. ⚠ ประเด็นที่ต้องตัดสินใจก่อนเริ่มเก็บข้อมูล

ข้อเหล่านี้ไม่ใช่รายละเอียดปลีกย่อย — ถ้าไม่จัดการก่อน จะพิสูจน์สมมติฐานไม่ได้เลย และเป็นสิ่งที่กรรมการถามแน่นอน

# ประเด็น ผลถ้าไม่จัดการ ข้อเสนอ
E-01 H2 ไม่มี baseline — จะบอกว่า "เร็วกว่าเดิม" ต้องรู้ว่า "เดิม" ใช้เวลาเท่าไร แต่ยังไม่เคยจับเวลาวิธีทำมือด้วย Excel เลย พิสูจน์ H2 ไม่ได้ ต้องตัดสมมติฐานทิ้งกลางคัน หรือเขียนแบบไม่มีตัวเลขรองรับ เก็บ baseline ก่อนเริ่มพัฒนา — ให้อาจารย์ 3–5 ท่านทำงานเดิม (รวมคะแนน + คำนวณ CLO 1 วิชา) แล้วจับเวลาไว้ ทำครั้งเดียวใช้ได้ทั้งเล่ม
E-02 H1 ต้องมี "ใบคำนวณมือ" ที่เชื่อถือได้ ไว้เทียบ ถ้าคำนวณมือผิดเอง การเทียบไม่มีความหมาย H1 กลายเป็นการเทียบระบบกับตัวเอง ให้อาจารย์ที่ปรึกษาตรวจรับใบคำนวณมืออย่างน้อย 3 ชุด (กรณีปกติ / กรณีคะแนนไม่ครบ / กรณี PASS_FAIL) ก่อนใช้เป็นเกณฑ์
E-03 OI-10 ยังไม่ปิด — CR-03 กับ CR-02 ตีความน้ำหนักไม่ตรงกัน ทดสอบแล้วต่างกันถึง 20 จุด บนข้อมูลชุดเดียวกัน H1 พิสูจน์ไม่ได้ เพราะยังไม่รู้ว่า "คำตอบที่ถูก" คือสูตรไหน ต้อง sign-off srs OI-10 ก่อนเขียน unit test
E-04 OI-12 ยังไม่ปิด — ไม่ได้นิยามว่านักศึกษาที่ยังไม่มีคะแนนเลย นับเป็น at-risk หรือไม่ OBJ-4 วัดไม่ได้ เพราะ "at-risk" ยังไม่มีนิยามที่ชัด ต้อง sign-off srs OI-12 ก่อนทำ Dashboard
E-05 จำนวนผู้ใช้จริงอาจไม่ถึง 15 คน — srs §2.2 คาดว่ามีอาจารย์ 10–50 คน แต่ในทางปฏิบัติอาจหาผู้ทดลองใช้ได้น้อยกว่านั้น สถิติความพึงพอใจอ่อน กรรมการตั้งคำถามเรื่องขนาดกลุ่มตัวอย่าง ตกลงจำนวนขั้นต่ำกับอาจารย์ที่ปรึกษาไว้ล่วงหน้า และถ้าน้อยกว่า 15 ให้เสริมด้วยการสัมภาษณ์เชิงคุณภาพ
