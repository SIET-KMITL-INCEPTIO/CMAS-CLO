Section 1
Overview — 6 กลุ่มตาราง
ฐานข้อมูลแบ่งออกเป็น 6 กลุ่มตามหน้าที่ แต่ละกลุ่มมีสีที่ตรงกับ ER Diagram ด้านล่าง
Identity
User — ผู้ใช้ระบบ (อาจารย์ / ผู้ดูแล) เข้าสู่ระบบด้วย email + password มีบทบาท ADMIN หรือ INSTRUCTOR
Template
Curriculum → CurriculumCourse — หลักสูตรแม่แบบ เก็บแค่โครงสร้างหลักสูตรและรายวิชา (หน่วยกิต) — ส่วน CLO/วัตถุประสงค์/เกณฑ์ ปล่อยให้วิชาจริงกำหนดเองอย่างอิสระ
Live Course
Course → CLO → BehavioralObjective — วิชาจริงที่เปิดสอน ผลลัพธ์การเรียนรู้ และวัตถุประสงค์เชิงพฤติกรรมของแต่ละ CLO
Assessment
Activity → AssessmentCriteria — กิจกรรมประเมินผล (สอบ / โปรเจกต์ / ฯลฯ) และเกณฑ์ที่เชื่อม Activity กับ CLO
Scoring
Student → Score — นักศึกษาที่ลงทะเบียนในวิชา และคะแนนที่ได้รับจากแต่ละกิจกรรม
Audit
ScoreUploadLog — บันทึกการอัพโหลดไฟล์ Excel (ใคร เมื่อไร ไฟล์อะไร สำเร็จ/ล้มเหลวกี่แถว) ไม่มี FK — เป็น log เท่านั้น

Data Flow — ข้อมูลไหลอย่างไร
ลำดับการทำงานจริงของระบบ ตั้งแต่ Admin สร้างหลักสูตร จนถึงระบบคำนวณผลสัมฤทธิ์
1
Admin สร้างหลักสูตรแม่แบบ
กำหนดชื่อหลักสูตร สถาบัน ปีการศึกษา → เพิ่มรายวิชาในหลักสูตร (รหัสวิชา / ชื่อ / หน่วยกิต) — แม่แบบเก็บแค่โครงสร้าง ไม่ล็อก CLO

2
อาจารย์สร้างวิชาจริง
สร้าง Course (วิชา X / ภาคเรียน Y / ปี Z) → เพิ่ม CLO จริง (อาจคัดลอกจาก Template) → กำหนดวัตถุประสงค์เชิงพฤติกรรมสำหรับแต่ละ CLO

สร้าง Activity (เช่น Midterm 100 คะแนน น้ำหนัก 30%) → เชื่อม Activity กับ CLO ผ่าน AssessmentCriteria พร้อมกำหนดสัดส่วน

4
เพิ่มนักศึกษาลงวิชา
เพิ่ม Student เข้าในวิชา (1 row = นักศึกษา 1 คน ใน 1 วิชา) ใช้รหัสนักศึกษา + วิชาเป็น Unique Key

บันทึกคะแนน (Excel Upload)
อาจารย์อัพโหลดไฟล์ Excel → ระบบสร้าง Score (1 row = นักศึกษา 1 คน + Activity 1 อัน = คะแนนเท่าไร) → บันทึก log ว่าอัพไฟล์อะไร สำเร็จ/ล้มเหลวกี่แถว

Scenario — ตัวอย่างการใช้งานจริง
สมมติ อ.สมชาย สอนวิชา Computer Technology ภาคเรียน 1/2568
เรื่องราวของ อ.สมชาย กับ CMAS
1
เข้าสู่ระบบ → อ.สมชาย login ด้วย email → ระบบดึง User (role = INSTRUCTOR)
↓
2
สร้างวิชา → Course {code: "03376116", name: "Computer Technology", semester: 1, year: 2568}
↓
3
กำหนด CLO 3 ข้อ:
• CLO #1 — "ออกแบบฐานข้อมูลเชิงสัมพันธ์ได้" (เกณฑ์ผ่าน 60%)
• CLO #2 — "เขียน SQL Query ได้" (เกณฑ์ผ่าน 60%)
• CLO #3 — "วิเคราะห์ประสิทธิภาพ Query ได้" (เกณฑ์ผ่าน 60%)
↓
4
สร้าง 2 กิจกรรม:
• Activity "Midterm" — คะแนนเต็ม 100, น้ำหนัก 40%
• Activity "Project" — คะแนนเต็ม 100, น้ำหนัก 60%
↓
5
เชื่อมเกณฑ์:
• AssessmentCriteria → Midterm วัด CLO #1 (0.5) + CLO #2 (0.5)
• AssessmentCriteria → Project วัด CLO #2 (0.3) + CLO #3 (0.7)
↓
6
เพิ่มนักศึกษา 30 คน → Student {studentCode: "66065001"..., courseId: <วิชานี้>}
↓
7
อัพโหลดคะแนน Midterm.xlsx → สร้าง Score 30 rows + ScoreUploadLog {recordsOk: 28, recordsFail: 2}
↓
8
ระบบคำนวณ: นักศึกษา 66065007 ได้ CLO #1 = 48% (< 60%) → กลุ่มเสี่ยง → แจ้งเตือนอาจารย์
